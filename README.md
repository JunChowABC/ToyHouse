# 晚安，玩具屋 · 核心玩法原型

基于 GDD v1.4、核心玩法 MDD 和关卡设计对话制作的浏览器原型。当前第 1–20 关直接使用 `docs/design/核心玩法系统/晚安玩具屋_关卡配置_1-20_v1.3.json`：12×18 网格、每关 72 个玩具，保留原始坐标、占格、方向、皮肤、关卡编号与章节归属。

## 启动

在当前目录运行：

```powershell
npm start
```

然后打开 `http://127.0.0.1:4173`。

## 操作

- 点击兔子或鲸鱼：尝试沿其面对方向离场
- 小鸭不可点击移动；四方向相邻空格连通任意边缘时自动寻路离场，并逐轮触发后续小鸭
- 玩具前方有空位时：自动滑到第一个阻挡前并停下，不会回到原位
- `1` / `2` / `3`：打开消除 / 洗牌 / 翻转说明弹窗；点击“使用”或“购买”确认后执行，消除和翻转还需选择目标
- 右上角暂停键 / `P`：打开或关闭暂停弹窗
- `Esc`：取消当前道具选择；未选择道具时打开暂停，暂停中继续游戏
- `F`：切换全屏
- `Enter` / `Space`：开始或进入下一关

## 已实现

- 12×18 高密度竖向盘面，20 关均为 72 个玩具，直接开始完整布局，无教学提示或主题关编排
- 1–10 关仅 1×2 兔子；11–15 关兔子与 1×1 小鸭；16–20 关兔子、小鸭与 1×3 鲸鱼
- 方向和空间分布逐项取自 v1.3 JSON，取消旧中央分区生成、裁剪和镜像变体
- 小鸭在开局、手动离场、挪动、消除和洗牌改变占格后自动寻路；每轮先确定全部离场对象，再统一释放占格并扫描下一轮
- 小鸭每只独立计入 Combo；逻辑连锁同步完成，路径动画并行播放，翻转和洗牌不改变小鸭的无固定方向属性
- 占格与头部到边界的完整路径检测
- 盘内滑动、遇阻停止和永久位置变化；点击当帧主动玩具与被撞玩具立即同步播放撞击反馈
- 快速离场、条内显示连击数的 8 秒 Combo 进度条、连锁释放提示
- 消除两个、随机改向五个、指定翻转一个三种道具
- 底部提示、重开常驻按钮已移除；重开移入暂停弹窗
- 暂停弹窗包含音乐、音效、震动开关，以及重新开始、继续游戏、退出关卡
- 普通关结算可连续推进到第 20 关，全部完成后进入晚安演出
- `window.render_game_to_text()` 与 `window.advanceTime(ms)` 自动化测试接口

## V3 PSD 与指定原画实装（2026-09-16）

当前 UI 来自 `outputs/20260916_ui_proportions_v3/toyhouse-core-ui-layered-v3.psd`，背景、地毯、兔子、鲸鱼、鸭子来自 `原画资源/`。实际导出 29 个独立 UI 图层与 5 张原画，资源及来源哈希位于 `assets/toyhouse-ui-v3/manifest.json`，运行时不再加载旧版素材。

- 标题装饰、标题上方兔子、资源栏、Combo 和底部三道具按 V3 坐标装配；标题兔子、全部玩具、地毯和背景均等比缩放。标题按 PSD 双行布局显示实际关卡编号与名称。

- 12×18 棋盘采用 34 像素格子，点击坐标与绘制坐标统一；原有 20 关配置、占格、解法保持不变。同类玩具采用统一固定尺寸，连续两次在上一版基础上等比放大20%（固定比例1.44）；不随位置、朝向、邻居消除或关卡变化缩放。棋盘间距34px，本次按要求提供更大尺寸预览，密集处存在轮廓重叠，按实际透明轮廓检查遮挡，逻辑占格保持。普通飞出采用 0.9 秒缓起缓停动画，小鸭按每格 110 毫秒移动。
- 左上 V3 导航页签打开现有暂停菜单；继续、重开、退出及设置功能保留。金币、库存、关卡和 Combo 显示真实状态，不使用 PSD 的示例数字。
- 三种道具仍为初始库存 0、每关每种最多 3 次、购买 100 金币；取消目标保留库存，刷新/重开不返还。见 [道具库存与购买说明](art/tool-economy.md)。星星系统与资源加号获取入口仍未接入。

## GitHub Pages 发布

`docs/` 包含混淆版本，入口为 `docs/index.html`。仓库推送到 `main` 后，`.github/workflows/pages.yml` 仅提取入口、混淆程序、样式与运行图片到 `_site/` 并自动部署 Pages，设计资料与素材清单不发布到站点。访问地址：https://junchowabc.github.io/ToyHouse/。

说明：浏览器端代码必须交付给用户设备执行，因此不存在绝对意义上的客户端加密；本项目使用 Terser 进行压缩与变量混淆，源代码仍保留在仓库根目录供维护。

修改设计 JSON 后，执行 `npm install`（首次安装构建依赖）和 `npm run build`，重新生成 `src/level-config.js` 与混淆后的 `docs/game.js`。运行游戏本身不需要第三方依赖；构建结果随项目提交，推送后检查 Pages 工作流部署状态。
