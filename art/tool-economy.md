# 道具库存、说明弹窗与金币购买

## 当前规则

| 项目 | 实现 |
| --- | --- |
| 初始库存 | 消除、洗牌、翻转各 0 个 |
| 新玩家金币 | 暂设 0；用户尚未指定初始赠送或金币产出 |
| 购买价格 | 每个道具 100 金币 |
| 每关上限 | 三种道具各自最多成功使用 3 次；互不占用次数 |
| 顶部金币 | 实际本地余额 |
| 底部角标 | 实际背包数量，而非关内剩余次数 |
| 弹窗 | 标题、独立关闭按钮、大道具图标、两行用途、使用或购买按钮；不显示库存和每关次数 |
| 库存为 0 | 显示“购买”＋金币图标＋100；余额不足时禁用，弹窗内显示原因 |
| 库存 ≥1 | 显示“使用”，不消耗金币 |
| 达到 3 次 | 无论库存或余额多少均禁止再次使用/购买，弹窗显示本关已用尽 |
| 弹窗期间 | 盘面、移动和 Combo 计时冻结；点击不穿透到棋盘 |

弹窗按照最新参考图布局，复用 pause-dialog-v2 的兔子、缎带标题、蕾丝面板、星星、蝴蝶结及粉色按钮，搭配现有 toyhouse-ui-v3 道具和金币图标。三个标题为“消除”“反转”“洗牌”。无库存显示金币图标和“100 购买”，有库存显示“使用”；不可用时显示原因并弱化按钮。布局与点击热区均从 941×1672 原图坐标等比映射到游戏画布。

## 生效与取消

购买确认会扣除 100 金币、获得 1 个对应道具，并立即执行洗牌或进入消除/翻转选目标状态，不需要再打开一次弹窗。

消除选中两个有效玩具时才扣 1 个道具和 1 次机会；只剩一只时沿用原规则移除剩余玩具。翻转命中可翻转目标时才扣除；点击小鸭、空白或无效目标不扣。洗牌确认后立即扣除并执行，目标不足五只时按实际可用数量处理。

关闭说明弹窗不扣费。取消选目标不扣库存和次数；如果此前已购买，金币不退，购买的道具保留在背包。Esc 或打开暂停可取消；再次点击道具打开说明时也会取消尚未完成的选目标。

同一关的已用次数按关卡 ID 保存，重开、退出再进或刷新都不重置，防止同一关越过三次上限。新关从各 0/3 开始；库存和金币跨关保留。当前存档在浏览器 localStorage（`toyhouse-economy-v1`），不同来源的网站各自保存。

## 后续奖励接口

任务、成就、广告系统在确认奖励成功后，可调用：

```js
window.toyhouseRewards.grant({
  id: "daily-task-2026-09-07-01", // 同一笔奖励使用稳定且唯一的 ID
  source: "task",                // task / achievement / rewarded_ad
  coins: 100,
  tools: { remove: 1, shuffle: 0, flip: 0 }
});
```

返回 true 表示已发放，false 表示参数无效或重复领取。同一来源＋ID 的重复回调不会再次发奖；数量必须为非负安全整数。奖励可以增加背包，但不能增加已用尽的关内次数。

本轮只实现本地余额/库存与上述接入接口，没有任务页、成就判定、广告 SDK、充值或金币产出规则，也没有给实际用户注入测试奖励。

## 验证

2026-09-19 按最新参考图通过 ImageGen CLI/API 生成关闭按钮及灰色购买底图，位于 `assets/tool-dialog-v1/`。禁用状态使用专用底图；金币与星星运行时去色，价格和“购买”保持程序文字。独立资源、按钮增补 PSD、提示词与装配说明位于 `outputs/20260919_tool_button_assets/`。

`node tests/verify-tool-economy.mjs` 在源码与手机发布版验证：初始 0 库存，99/100 金币边界，购买后直接使用，有库存不扣金币，取消保留购买物，三种道具各用满 3 次后锁定，刷新/重开保存，新关独立次数，小鸭无效目标，奖励回调幂等。

测试通过隔离浏览器内的奖励接口设置数据，不改用户实际浏览器存档。截图与报告位于 `test-output/tool-economy/`。
