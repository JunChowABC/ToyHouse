# 《晚安，玩具屋》新增关卡机制设计 V1.0

## 1. 设计目标

新增机制不改变《晚安，玩具屋》的核心操作：

**观察盘面 → 找到突破口 → 点击玩具 → 改变占格 → 打开新的释放关系 → 连续清空盘面。**

新增机制主要解决三个问题：

1. 增加 Blocking / Release 依赖结构的变化；
2. 让“撞击、离场、占格变化”产生更多后续事件；
3. 提高后续大量关卡的组合空间，而不是单纯依靠增加玩具数量提高难度。

机制设计遵循以下原则：

- 单指点击仍然是主要操作；
- 不增加复杂拖拽、连线等第二套核心操作；
- 不增加步数失败、生命失败；
- 新机制优先改变盘面关系，而不是增加额外 UI；
- 单个机制原则上通过外观和状态即可识别；
- 新机制必须能够进入自动生成器与 Solver；
- 道具不是解关必需条件；
- 常规关卡仍保持高密度、四方向自然混排；
- 不设计“整关只展示某一个机制”的机制教学关；
- 新机制以较低密度混入正常完整关卡。

# 2. 机制分类

新增机制分为三个层级。

### 2.1 Toy Mechanic｜玩具机制

本身属于玩具对象，参与占格、阻挡、离场或连锁。

包括：

- 睡眠玩具
- 抱抱玩具
- 弹簧玩具

### 2.2 Obstacle Mechanic｜障碍机制

自身不是需要清空的玩具，但会改变路径和 Blocking 关系。

包括：

- 纸箱
- 冰块
- 锁盒

### 2.3 Board Mechanic｜盘面机制

直接改变空间、出口或移动关系。

包括：

- 传送门
- 单向出口
- 传送带
- 旋转区域

# 3. 新增机制详细设计

## 3.1 纸箱

### 机制定位

**可被逐步破坏的固定障碍。**

让原本单纯代表“无效操作”的撞击变成一种主动解题行为。

### 基础规则

- 默认占据 1×1 格；
- 自身不可点击；
- 视为实体阻挡物；
- 兔子或鲸鱼撞击纸箱时，正常停止在纸箱前；
- 每次有效撞击使纸箱耐久 -1；
- 耐久归 0 后纸箱立即破坏并释放占格；
- 纸箱破坏属于一次占格变化；
- 随后立即执行小鸭自动离场扫描；
- 纸箱不计入“剩余玩具数”；
- 纸箱破坏本身不增加 Combo。

### 推荐耐久

普通纸箱：

**2 次撞击。**

后续允许配置 1～3，但正式关卡原则上不建议超过 3。

### 视觉表达

完整纸箱
↓
出现裂纹
↓
纸箱散开 / 消失

玩家不需要查看文字即可判断状态。

### 解题价值

原规则：

> 撞击 = 当前路径无法离场。

加入纸箱后：

> 撞击 = 可能是在制造未来出口。

因此玩家开始思考：

**“这只兔子现在虽然走不了，但撞它是不是有价值？”**

### Cascade 示例

兔子撞纸箱
→ 纸箱破坏
→ 腾出 1 格
→ 小鸭获得出口
→ 小鸭离场
→ 打开新的直线路径
→ 鲸鱼离场。

### 推荐度

**S**

# 3.2 睡眠玩具

### 机制定位

**需要其他玩具先离场才能激活的延迟可操作单位。**

主要用于制造 Release Dependency。

### 基础规则

睡眠状态的兔子或鲸鱼：

- 正常占格；
- 正常阻挡其他玩具；
- 不可点击；
- 显示闭眼 / 睡眠状态；
- 与其绑定的“唤醒目标”离场后自动醒来；
- 唤醒后恢复为普通兔子/鲸鱼；
- 原有方向不发生变化。

### 依赖方式

每只睡眠玩具绑定 1 个 Wake Source。

例如：

```
Rabbit_18 → Sleeping_Rabbit_32
```

表示：

> Rabbit_18 离场后，Rabbit_32 苏醒。

不建议采用“周围任意玩具离场即苏醒”，因为这种关系在高密度盘面中不够容易预测。

### 视觉表达

睡眠：

- 闭眼；
- 小睡帽 / 月亮符号；
- 轻微呼吸动画。

唤醒：

- 睁眼；
- 小星星反馈；
- 恢复正常状态。

不需要弹出“已唤醒”文字。

### 解题价值

普通盘面主要思考：

> 谁挡住了谁？

加入睡眠后增加：

> 我要先释放谁，才能获得下一枚可操作棋子？

### Dependency 示例

A兔离场
→ B兔苏醒
→ B兔撞开纸箱
→ 小鸭离场
→ C鲸鱼路径打开。

### 推荐度

**S**

# 3.3 抱抱玩具

### 机制定位

**成对存在的前后依赖玩具。**

它比睡眠机制具有更强的视觉关系。

### 基础规则

两个玩具组成一组：

```
Pair A ↔ Pair B
```

其中：

- A 为自由玩具；
- B 为抱抱锁定状态；
- A 离场前，B 不可点击；
- A 离场后，B 自动解除锁定；
- B 随后按照自身原有方向正常参与玩法。

A 与 B 不要求空间相邻。

### 视觉表达

两只玩具使用相同：

- 蝴蝶结；
- 心形挂牌；
- 毛线颜色；

形成明显的 Pair Identification。

A 离场后：

B 身上的绑定标识消失。

### 与睡眠玩具的区别

睡眠玩具强调：

**状态变化。**

抱抱玩具强调：

**对象之间的明确依赖关系。**

### 设计限制

一组最多：

**2 个玩具。**

MVP 不设计：

A → B → C → D

这种长链。

避免玩家需要记忆过多对应关系。

### 推荐度

**S**

# 3.4 弹簧玩具

> 2026-09-30 用户修正：取消移动一格后缩回底座。弹簧不可点击移动，受到撞击后沿撞击方向持续滑行，遇到障碍停在其前一格；直到边缘都没有障碍时直接离场。停下后仍保持完整外观与阻挡，可再次受撞击。支持传送门，离场计入睡眠唤醒及 Combo。

### 机制定位

**受到撞击后会改变位置的动态障碍。**

这是整个新增机制中最适合强化 Cascade 的机制之一。

### 基础规则

- 占据 1×1 格；
- 不可直接点击；
- 会阻挡兔子和鲸鱼；
- 被兔子/鲸鱼撞击后，沿撞击方向持续滑行至首个障碍前；
- 紧邻障碍时保持原位；停止时仍阻挡，可再次被撞动；
- 经过传送门时按合法出口随机传出、同步转向并继续滑行；无合法出口则停在入口前；
- 移动后立即更新占格；
- 占格变化触发小鸭自动扫描。

### 边缘规则

前方直到边缘都没有障碍时，弹簧直接离场并释放占格；边缘朝外受撞也可立即离场。单向出口的方向限制仍适用。

### Combo

弹簧移动：

**仅位移不增加 Combo；实际离场增加 Combo，并计入睡眠玩具唤醒计数。**

但由其移动引发的小鸭离场正常增加 Combo。

### Cascade 示例

兔子 → 撞弹簧

弹簧向右滑行至障碍前，或直接离场

↓

原位置出现空格

↓

鸭 A 获得路径

↓

鸭 A 离场

↓

鸭 B 获得路径

↓

两只兔子的直线路径同时打开。

### 设计意义

现有玩法中：

**撞击主要意味着受阻。**

加入弹簧后：

**撞击本身成为解题手段。**

这会显著扩大玩家的操作判断空间。

### 推荐度

**S**

# 3.5 钥匙与锁盒

### 机制定位

**全局 Trigger → Unlock 机制。**

### 钥匙玩具

钥匙不是独立新玩具原型，而是附加在普通玩具上的状态。

例如：

> 一只兔子脖子上挂着金色钥匙。

该兔子：

- 行为与普通兔子完全一致；
- 成功离场后触发对应锁盒开启。

### 锁盒

- 默认占据 1×1 或 1×2；
- 不可移动；
- 阻挡所有玩具；
- 对应钥匙离场后立即消失；
- 消失后释放占格；
- 随即触发小鸭扫描。

### 支持关系

一个钥匙：

→ 1～3 个同色锁盒。

MVP 不建议：

多个钥匙共同开启一个锁。

### 视觉表达

金钥匙 → 金锁盒
银钥匙 → 银锁盒

通过颜色和造型直接建立关系。

### 解题价值

玩家会产生非常明确的目标：

> “我要先想办法把带钥匙的兔子送出去。”

它可以自然制造局部阶段目标，而无需额外任务 UI。

### 推荐度

**A+**

# 3.6 传送门

### 机制定位

**改变空间拓扑关系。**

属于中后期高价值机制。

### 基础规则

传送门必须成对出现：

```
Portal A ↔ Portal B
```

当兔子或鲸鱼沿自身方向移动并进入 Portal A：

→ 从 Portal B 出现
→ 保持原方向
→ 继续按照原直线路径规则运动。

### 出口判定

传送出口必须存在足够空间容纳完整玩具。

兔子需要：

2 格。

鲸鱼需要：

3 格。

若空间不足：

> 当前传送路径视为不可通过。

玩具停在入口前。

### 小鸭

第一版建议：

**小鸭不使用传送门。**

否则小鸭寻路图会从二维连通问题升级为带 Portal Edge 的图搜索，玩家理解成本和 Solver 复杂度都会明显提高。

### 解题价值

原玩法的空间关系：

> 左边的玩具主要影响左边。

传送门加入后：

> 左侧的一次操作可能改变右侧结构。

可以显著提升空间推理深度。

### 推荐度

**A**

# 3.7 冰块

### 机制定位

**玩具状态型障碍。**

### 基础规则

被冰冻的兔子/鲸鱼：

- 正常占格；
- 不可点击；
- 可以被其他玩具撞击；
- 每受到一次有效撞击，冰层 -1；
- 冰层归 0 后恢复正常操作。

### 推荐冰层

1～2 层。

### 问题

该机制与：

- 纸箱；
- 睡眠玩具；

在功能上存在一定重叠。

三者本质都是：

> “当前不可通过，需要满足条件解除。”

因此不建议早期同时正式上线。

### 推荐度

**B**

作为后续内容储备，不进入第一批机制。

# 3.8 单向出口

### 机制定位

改变边缘出口规则。

### 基础规则

部分边缘出口具有方向标识。

例如：

↑出口只允许朝上的兔子/鲸鱼离场。

其他方向的玩具即使抵达该出口，也无法离场。

### 问题

当前兔子/鲸鱼本身已经存在固定方向，因此单向出口容易与现有方向规则产生重复认知。

同时会增加边缘 UI 信息量。

### 推荐度

**B-**

暂不进入第一批正式机制。

# 3.9 传送带

### 机制定位

周期性改变玩具位置。

### 基础概念

特定地面区域带有方向。

触发后：

→ 上方玩具整体移动 1 格。

### 风险

需要处理：

- 多格兔子；
- 多格鲸鱼；
- 多玩具同时移动；
- 推挤；
- 边缘；
- 重叠；
- 连锁触发顺序。

会明显提高 Solver 和生成器复杂度。

### 推荐度

**C+**

建议后期再考虑。

# 3.10 旋转区域

### 机制定位

批量改变方向。

### 基础概念

触发后：

3×3 / 4×4 区域内的兔子、鲸鱼统一旋转 90°。

### 风险

高密度盘面下，多格玩具旋转极容易出现：

- 空间不足；
- 占格冲突；
- 旋转失败；
- 玩家难以预测最终状态。

同时会削弱当前“方向由玩具造型直接表达”的清晰性。

### 推荐度

**C**

暂时不建议正式制作。

# 4. 第一批正式机制建议

第一批建议只开发以下 **6 种**：

| 优先级 | 机制        | 核心价值               |
| ------ | ----------- | ---------------------- |
| P0     | 纸箱        | 把撞击转化为解题行为   |
| P0     | 睡眠玩具    | 建立释放前后依赖       |
| P0     | 弹簧玩具    | 制造动态占格与 Cascade |
| P1     | 抱抱玩具    | 建立明显的对象依赖     |
| P1     | 钥匙 / 锁盒 | 建立跨区域目标         |
| P2     | 传送门      | 改变空间拓扑           |

暂不制作：

- 冰块；
- 单向出口；
- 传送带；
- 旋转区域。

不是因为机制本身不可用，而是第一批继续增加它们的边际价值已经低于新增的认知与开发成本。

# 5. 机制组合关系

真正增加关卡数量的不是单个机制，而是**机制组合**。

## 5.1 一级组合

纸箱 + 小鸭

> 撞纸箱 → 纸箱消失 → 小鸭离场。

睡眠 + 小鸭

> 小鸭离场 → 睡眠玩具苏醒。

钥匙 + 锁盒

> 钥匙兔离场 → 锁盒消失。

## 5.2 二级组合

纸箱 + 小鸭 + 睡眠

> 撞箱 → 开缺口 → 鸭离场 → 唤醒兔。

弹簧 + 小鸭 + 鲸鱼

> 兔撞弹簧 → 弹簧位移 → 鸭连锁 → 鲸鱼出口打开。

抱抱 + 钥匙 + 锁盒

> A 离场 → B 解锁 → B 是钥匙兔 → B 离场 → 锁盒打开。

## 5.3 高价值 Cascade

后期目标结构：

**玩家操作**

↓

**第一次占格变化**

↓

**机制 A**

↓

**小鸭自动连锁**

↓

**机制 B**

↓

**第二次占格变化**

↓

**新的手动玩具获得出口**

↓

**大规模释放**

一个高质量后期关卡可以出现：

> 点击兔子
> → 撞击弹簧
> → 弹簧移动
> → 小鸭 ×2 离场
> → 钥匙兔路径打开
> → 钥匙兔离场
> → 2 个锁盒打开
> → 睡眠鲸鱼苏醒
> → 鲸鱼离场
> → 小鸭 ×5 连锁离场。

这类结构可以作为后续 **Cascade 强度** 的核心来源。

# 6. 关卡投放原则

## 6.1 不制作“机制教学关”

新增机制后仍然保持：

> 每一关都是正常、完整、高密度、可以直接玩的标准关卡。

不会出现：

> 第21关：纸箱教学
> 第31关：睡眠教学
> 第41关：弹簧教学

这种结构。

机制首次出现时只降低**机制数量和依赖深度**，而不是降低整个关卡质量。

# 7. 21～100 关机制密度建议

| 关卡段  | 主要机制池        | 单关机制数量建议 | Dependency Depth |
| ------- | ----------------- | ---------------- | ---------------- |
| 21～30  | 基础三玩具 + 纸箱 | 2～4             | 1～2             |
| 31～40  | + 睡眠            | 3～6             | 2～3             |
| 41～50  | + 弹簧            | 4～7             | 2～4             |
| 51～60  | + 抱抱            | 5～8             | 3～4             |
| 61～75  | + 钥匙/锁盒       | 6～10            | 3～5             |
| 76～100 | + 传送门          | 8～12            | 4～6             |

这里的“机制数量”不是玩具总数量。

常规盘面仍以大量普通兔子/小鸭/鲸鱼组成，新机制只占其中较小部分。

避免出现：

> 70 个对象里 40 个都是特殊机制。

那样会从“玩具挪车解谜”变成“规则识别游戏”。

# 9. Dependency Graph 升级

以后生成关卡不能只生成“谁挡住谁”。

Dependency Graph 建议升级为：

### Blocking Edge

```
A --blocks--> B
```

A 阻挡 B。

### Unlock Edge

```
A --unlock--> B
```

A 离场后 B 解锁。

### Break Edge

```
A --hit--> Box
```

A 可以破坏纸箱。

### Push Edge

```
A --push--> Spring
```

A 可以推动弹簧。

### Trigger Edge

```
KeyA --trigger--> Lock01
```

钥匙触发锁。

### Cascade Edge

```
A --release--> DuckGroup01
```

A 的状态变化会释放小鸭群。

因此一个正式关卡不再只是：

**Blocking Graph**

而是：

# Blocking + Trigger + Release Dependency Graph

这会成为后续自动生成关卡最核心的数据结构。

# 10. Solver 新增要求

生成器生成完关卡后必须验证：

### 10.1 基础可解

存在至少一条：

**不使用任何道具即可清空盘面**

的解法。

### 10.2 无永久死锁

不得出现：

A 等待 B
B 等待 C
C 等待 A

这种无法从外部解除的 Dependency Cycle。

### 10.3 机制可触发

所有关键机制必须至少存在一个合法 Trigger Source。

例如：

纸箱需要至少存在可以撞击它的玩具。

锁盒必须存在对应钥匙。

睡眠玩具必须存在合法唤醒源。

### 10.4 初始可行动量

即使后期机制很多，开局仍必须存在多个可判断选择。

避免：

> 开局只有唯一一只兔子可以点。

### 10.5 方向空间分布

上 / 下 / 左 / 右继续保持二维空间自然交错。

禁止：

左半边全部 ↑↓
右半边全部 ←→。

# 12. 难度模型升级

后续不建议再单纯用 ToyCount 判断难度。

建议：

**Difficulty = Blocking Complexity + Dependency Complexity + Choice Complexity + Mechanic Complexity**

其中：

### Blocking Complexity

普通阻挡结构复杂度。

### Dependency Complexity

机制之间依赖链深度。

### Choice Complexity

玩家同时存在多少个“看起来可以操作”的候选。

### Mechanic Complexity

当前盘面需要同时理解多少种特殊规则。

因此：

**70 个玩具 + 2 个纸箱**

完全可能比：

**65 个玩具 + 睡眠 + 弹簧 + 钥匙 + 传送门**

简单很多。

# 13. 最终机制体系

建议未来《晚安，玩具屋》的核心玩法逐步形成：

**基础层**

兔子 / 小鸭 / 鲸鱼

↓

**阻挡层**

普通阻挡 / 纸箱

↓

**状态层**

睡眠 / 抱抱

↓

**动态层**

弹簧

↓

**触发层**

钥匙 / 锁盒

↓

**空间层**

传送门

↓

**组合层**

Blocking + Trigger + Release + Cascade

最终核心体验从：

> **“找到哪只兔子能出去。”**

逐渐成长为：

> **“找到那个能让整个玩具堆开始松动的关键操作。”**

这应该作为新增机制最重要的设计方向。
