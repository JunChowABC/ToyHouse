# 六种关卡机制实现与验收 v1.4

依据：《新增关卡机制设计 V1.0》《关卡机制底层结构与生成器升级设计 V1.0》。本次按用户确认一次实现六种，不采用 21～200 关配方，不加入冰块、单向出口、传送带、旋转区域。

## 运行入口

运行 `npm start` 后：

- 游戏：`http://127.0.0.1:4173/`。前20关保留原始配置，第20关完成后进入第21关，最后一关改为100。
- 六机制预览：`http://127.0.0.1:4173/?previewLevel=76`。只在当前页面内使用进度和道具，不写入持久存档。
- 机制工作台：`http://127.0.0.1:4173/editor/`。
- 本地构建版：`/docs/`、`/docs/editor/`；`npm run build` 同步生成。

本次更新为本仓库 Web 版与本地 docs 构建。未发布 GitHub Pages，未同步独立 TapTap Maker 工程，不代表手机真机验收。

## 六种机制

|机制|操作与结算|状态与表现|
|---|---|---|
|纸箱|兔/鲸每次碰撞扣1耐久；相邻原地碰撞也有效；破坏后重新扫描小鸭|默认2耐久，1耐久显示裂纹；不增加Combo|
|睡眠|不可手动点击；绑定来源离场后唤醒，保持原方向|闭眼、Zz；双方同号挂牌标明绑定来源|
|弹簧|不可点击；受撞后沿撞击方向滑行至障碍前，无障碍则离场，更新占格后扫描小鸭|停下后保持完整外观及阻挡，可再次被撞动；支持传送门；实际离场计入唤醒计数及Combo|
|抱抱|自由成员先离场，锁定成员才可点击；不要求相邻|同组蝴蝶结；锁定成员解除后移除绑定标识|
|钥匙/锁盒|携带者离场后开启所有同ID锁盒，再扫描小鸭|钥匙和锁盒同色；锁盒支持1格/2格，不计入玩具数|
|传送门|兔/鲸头部进入入口，完整身体在配对出口按原方向放置，继续前进|完整身体放不下则停在入口前；循环传送作为无效动作；小鸭只按普通地面寻路，不传送|

2026-09-30 用户修正覆盖旧的“移动一格后缩回底座”补充。第41～100关已按持续滑行规则重新求解；第80、98关弹簧各平移一格，其他对象位置保留。

仅玩具实际离场增加Combo；纸箱、弹簧、锁盒均不计入剩余玩具数。道具直接消除玩具会正常触发其唤醒/抱抱/钥匙依赖，但被直接消除的玩具本身不增加Combo。睡眠/抱抱锁定的玩具不参与翻转、洗牌；洗牌占格检查包含实体障碍。消除的两只玩具先同时移除，再统一结算，避免选中的小鸭重复离场。

结算期间锁定下一次玩具操作；暂停冻结动画和计时。重开从关卡配置复位所有机关和依赖，同时保留已消耗库存及本关道具使用次数。普通继续游戏沿用已有的“关卡进度持久化、退出后重开当前关卡”策略，没有新增局中逐步存档。

## 文件和数据

- `src/mechanics.js`：共用占格、路径、事件队列、自动小鸭、校验、状态搜索、图关系及SHIFT分析。
- `src/mechanic-generator.js`：在现有高密度释放结构上插入显式机制节点，并以实际操作回放确认所有特殊机制可触发。
- `config/mechanic-levels-v1.4.json`：第21～100关、随机种子、来源结构、依赖边、解法和生成验证结果。
- `scripts/build-mechanic-levels.mjs`：重新生成80关。失败候选不会作为无解兜底输出。
- `scripts/build-level-config.mjs`：保留1～20原JSON，合并新增关卡。
- `editor/`：盘面/依赖图、对象属性、试玩、撤销、模拟触发链、逐步解法、后台Worker分析、候选生成与筛选、JSON导入导出。
- `assets/mechanics-v1/manifest.json`：机制图集来源路径、透明裁切范围、原图SHA-256。沿用项目已有原画；丝带取素材页第一枚蝴蝶结。

玩具仍使用 `ORDINARY/AUTO_EXIT/LARGE`；状态通过 `modifier`、`wake_source`、`hug_source`、`pair_id`、`key_id`附着。障碍放入独立 `board_entities`。样例以新增关卡JSON为准。

搜索状态含位置、方向、离场及计数状态、睡眠/抱抱状态、箱子耐久、障碍销毁/开启状态。每个搜索节点都是队列已清空的稳定盘面；同一个 `Mechanics.click()` 同时驱动游戏、Solver和工作台。超出搜索预算返回 `UNKNOWN`，不会把“未搜到”写成“死锁”。

## 投放

|关卡|机制池|
|---|---|
|21～30|纸箱|
|31～40|增加睡眠|
|41～50|增加弹簧|
|51～60|增加抱抱|
|61～75|增加钥匙/锁盒|
|76～100|增加传送门|

每关72只基础玩具，均包含兔/鸭/鲸；四方向混排。初始至少3只手动玩具可直接离场。特殊节点比例低于25%，没有独立机制教学小盘面。

- 同命令验证80关的无道具解法、完整机制覆盖、玩具数、方向、密度与完整配置非重复。
- `TEST_BUILT=1 node tests/verify-mechanics-browser.mjs`：源码/构建各100关；新增关卡每一步核对运行时与共用规则状态；过关奖励、零道具、重开及实际点击六机制。报告：`test-output/mechanics-v14/report.json`。

- `node tests/verify-mechanic-editor.mjs`：源码/构建工作台、图视图、Worker求解、SHIFT安全分析、逐步操作、撤销、导入导出、候选生成。
- 原1～20关精确配置与释放曲线回归，道具经济、弹窗/下一关/最后一关回归通过。旧测试已更新100关边界、分阶段加载等待和弹窗动画等待。

## 本版生成器的边界

80关使用已验证的基础布局作为释放结构，插入机制依赖后重新求解；不是从任意抽象图生成任意玩具数量的全新几何排布器。难度和Cascade在工作台中是候选评分目标，报告会显示实测与目标偏差，不能将“有解”当作“严格符合普通/高Cascade”。SHIFT安全率是可选的有限搜索分析，未知项不计作安全或陷阱；没有对全部80关承诺设计文档建议的安全率/依赖深度档位。

依赖图包含当前阻挡/触发边；完成分析后追加沿已找到解法观测到的释放边和依赖深度。它是可验证的操作路径分析，不宣称穷尽所有解法的全局最大Cascade。后续若要严格按难度档位批量生产关卡，应以工作台的目标偏差、SHIFT结果、分层释放曲线和人工试玩继续筛选，而不是直接把这些软目标标为PASS。
