# 关卡机制

| 机制                | 规则                                           | 带来的解题变化                 | 推荐  |
| ------------------- | ---------------------------------------------- | ------------------------------ | ----- |
| **纸箱**            | 固定占格，不可移动；周围指定数量玩具离场后消失 | 制造阶段性封路                 | ★★★★★ |
| **睡着的玩具**      | 初始不可点击；相邻玩具离场后被唤醒             | 形成“先解外围→激活内部”        | ★★★★★ |
| **抱抱玩具**        | 两只玩具绑定，其中一只离场后另一只才可移动     | 产生明确前后依赖               | ★★★★★ |
| **弹簧玩具**        | 被其他玩具撞击后，自动向自身朝向移动一次       | 把“撞击”从失败反馈变成操作手段 | ★★★★★ |
| **传送门**          | 玩具进入入口后从对应出口出现，继续按原方向运动 | 改变空间路径关系               | ★★★★  |
| **旋转木马**        | 周围发生指定事件后，区域内玩具整体旋转 90°     | 改变方向关系                   | ★★★★  |
| **钥匙 / 锁盒**     | 钥匙玩具离场后，对应锁盒解除占格               | 强依赖链                       | ★★★★  |
| **冰块**            | 玩具被冻住不可移动；被撞击 N 次后解冻          | 让撞击产生策略价值             | ★★★★  |
| **单向出口**        | 特定出口只允许指定类型/方向的玩具通过          | 改变出口价值                   | ★★★   |
| **移动地毯/传送带** | 占格变化后，将其上的玩具整体移动 1 格          | 动态改变盘面                   | ★★★   |

还有一点比较重要：你当前局内 UI 是高密度盘面，核心任务就是让玩家观察几十个玩具寻找突破口，UI 本身又刻意减少文字、箭头和额外提示。   UI-核心玩法系统界面交互说明.v1.0 所以新机制最好都满足一个原则：**看造型就能大致理解状态，不需要额外 UI 教玩家规则。** 例如纸箱就真的是纸箱，冰冻就直接套冰，睡眠就闭眼 + Zzz，绑定就用丝带连接。
