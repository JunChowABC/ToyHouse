# 《晚安，玩具屋》21～200关关卡配方规划 V0.2

## 1. 使用说明

- 本表覆盖第21～200关；第1～20关沿用现有基础关卡规划。
- 每20关引入1种新特殊机制。
- 每关特殊机制最多2种；兔子/小鸭/鲸鱼属于基础功能原型，不计入特殊机制数量。
- “钥匙/锁盒”作为一套机制计1种。
- Toy Count仅统计兔子、小鸭、鲸鱼；纸箱、弹簧、锁盒、传送门等 Board Entity 不计入 Toy Count。
- 睡眠、抱抱、冰冻、钥匙携带属于Toy Modifier，其实例已经包含在对应兔子/鲸鱼数量中，不额外增加Toy Count。
- Init=目标Initial Exit Count；RD=目标Release Depth；Dep=目标Dependency Depth。均为生成目标，实际关卡完成二维布局后必须由Solver重新计算。
- Cascade=自动生成目标档位。即使“低”档，也应保留至少一次明确的释放高潮。

## 4. 生产验收硬约束

1. 单关特殊机制种类不得超过2。
2. 前200关机制池锁定为：纸箱、睡眠、弹簧、抱抱、钥匙/锁盒、传送门、冰块；不使用单向出口与传送带。
3. 手动玩具上、下、左、右方向必须在二维空间中自然混排，不允许按区域聚类。
4. 开局自动结算后必须存在至少1个合法手动出口。
5. 不使用局内道具也必须存在完整通关路径。
6. 正式关不得通过合法操作进入永久死局；SHIFT Safety用于生产质检，不用于人为制造陷阱。
7. 每关必须存在明确的Cascade Moment，且尾盘应明显加速，不做长时间逐个清理。
8. 新机制首次10关主要控制机制数量与Dependency Depth，不降低整体Toy密度做小教学关。
9. 实际二维布局完成后，Toy Count、Initial Exit、Release Depth、Max Cascade、Auto Chain、Direction Distribution、Dependency Depth均以Solver实测结果回写。
