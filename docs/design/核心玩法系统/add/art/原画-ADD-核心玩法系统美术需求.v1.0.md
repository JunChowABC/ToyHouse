# 2. 需求概述

## 2.1 需求目标

建立核心玩法首发版的场景和玩具视觉资产要求，使原画、美术生成和后续动作/特效协作方能够直接拆单。画面必须在高密度布局下仍然一眼区分 1×2 兔子、1×1 小鸭和 1×3 大鲸鱼，同时让四周缺口、手动玩具头尾方向和小鸭“可向任意可达缺口离场”的语义清楚成立。

## 2.2 需求范围

- 一套核心玩法卧室场景整体概念；
- 场景远景、中景、盘面与前景的分层资源；
- 玩法盘面、围边和四方向缺口模块；
- 默认兔子 1×2、小鸭 1×1、大鲸鱼 1×3 三套玩具设计；
- 手动玩具四方向读形、小鸭四方向转身基础设计；
- 碰撞、提示等后续动作所需关键姿态设计参考；
- 不遮挡盘面的场景装饰对象。

## 2.3 不在本次范围

- 兔子替换为玩具熊等后续皮肤；本期只制作三套默认皮肤；
- 玩具移动、离场、转身、回弹、打哈欠的最终帧动画；
- 撞击粒子、寻路星轨、提示星光、完成星光与 Combo 特效；
- HUD、按钮、弹窗和完成文字包装；
- 夜晚终关完整睡前演出场景；
- 关卡具体布局、关卡缩略图、关卡选择预览图；
- 货币、奖励、道具和材料图标。

## 2.4 统一风格基准

1. 风格为柔和粉彩、扁平偏二维、精致娃屋和手绘玩具感；允许极轻轴测与体积暗示，但不得做成写实 3D 或塑料渲染。
2. 已锁定的《花花与幕间剧》式精致娃屋方向只用于气质、配色层级、扁平度和材质轻重参考，不复制其角色、家具、图标、Logo 或具体构图。
3. 主色使用奶油白、浅粉、薄荷绿、浅蓝、淡紫和少量暖金；低饱和背景承托较饱和的玩具主体。
4. 材质语义以软布、短绒、棉花填充、缝线和轻木质为主；高光柔软，阴影短而浅，不使用硬金属反光和强环境光遮蔽。
5. 外轮廓圆润、简洁、连贯。玩具内部细节只保留能强化身份和朝向的部分，避免在高密度缩小时糊成噪点。
6. 场景光线是温柔睡前氛围，整体偏暖，但盘面与玩具之间必须有明确明度和色相分离。

## 2.5 玩法可读性硬约束

1. 兔子与鲸鱼必须清楚显示头部朝向和尾部，不能依赖额外箭头才能读方向。
2. 小鸭不可被设计成只能朝嘴部方向移动；身体近圆形，朝向只服务运动表现，不成为玩法判定暗示。
3. 三类玩具的视觉长宽比例与占格一致：兔子 1×2、小鸭 1×1、鲸鱼 1×3。
4. 盘面不画可见格线；位置关系由玩具排列、柔和接触阴影和盘面留白表达。
5. 四周缺口必须比普通装饰更容易识别，且不能被床沿、书本、HUD 或前景装饰遮住。
6. 同关同一功能原型只使用一种皮肤；本 ADD 不要求在同一关混放兔子和同功能玩具熊。

# 4. 原画需求

## 4.1 关卡场景需求

### 4.1.1 场景整体说明

核心玩法发生在温柔夜晚的儿童卧室/玩具屋局部。镜头采用近俯视或轻轴测竖屏构图，玩法盘面占据视觉中心和大部分可用区域；床沿、星月窗帘、收纳架、书本等只在外围形成娃屋氛围。场景应像一张精致的可玩插画，但所有非玩法元素必须主动降对比、降细节，四周出口和三类玩具始终是第一阅读层。

## 4.2 玩具原画需求

### 4.2.1 玩具统一设计规则

- 三类玩具是布偶/软质玩具，不是活体动物；允许五官和小配饰，但优先保证轮廓。
- 统一使用轻描边、短绒或棉布材质、浅接缝和极弱高光；不使用塑料反光、硬金属件或复杂印花。
- 在 1080×1920 高密度盘面缩放后，眼睛、鼻口、头尾和颜色块仍能识别；小细节消失不影响功能判断。
- 静态原画不得烘焙撞击星星、提示光圈、固定路径箭头或 Combo 标记。
- 手动玩具的头部朝向必须由身体结构表达；小鸭不允许用身体箭头或单向底座表达朝向。

### 4.2.3 后续换皮约束

本期不制作玩具熊等替换皮肤，但后续皮肤必须复用 `ART-TOY-004` 占格模板：普通原型仍为 1×2、自动原型仍为 1×1、大型原型仍为 1×3；皮肤只能改变外观，不改变操作、方向和离场规则。同一关同一功能原型只能选一种皮肤。

# 5. 资源命名与交付规范

## 5.1 命名规则

- 全小写、下划线分隔、无中文、无空格、无特殊字符、数字不放开头。
- 场景背景：`bg_coreplay_层级`，如 `bg_coreplay_00_back.png`。
- 场景物件：`prop_模块_名称`，如 `prop_board_exit_up.png`。
- 玩具：`toy_角色_方向_状态`，如 `toy_rabbit_left_idle.png`。
- 阴影：`shadow_toy_尺寸`，如 `shadow_toy_1x3.png`。
- 设计参考稿：文件名末尾使用 `_guide`，不得混入运行时图集。

方向缩写统一：`up`、`down`、`left`、`right`；状态缩写统一：`idle`、`hit`、`hint`、`exit`。不使用方向数字码，避免跨团队误解。

## 5.2 输出要求

1. 整景概念和合成验证稿按 2160×3840 制作；运行时分层纹理根据 TA 方案切分，单张优先不超过设备纹理上限。
2. 玩具源文件使用统一方形画布与锚点体系：小鸭建议 1024×1024；兔子和鲸鱼建议 2048×2048 或更高源画布。实际主体保持 1×1、1×2、1×3 视觉比例。
3. 交付 PSB/PSD 分层源文件和 PNG-32 透明图；禁止 JPG。
4. 图层样式、智能对象和形状图层在运行时导出前栅格化；源文件保留可审阅分组。
5. 同一玩具四方向图使用相同画布尺寸、统一锚点和一致阴影基线；透明边无脏点。
6. 运行时玩具图不包含接地阴影、路径、粒子和 UI 光圈；阴影和特效独立。
7. 场景分层不能把玩具烘焙进背景；空盘状态必须能够由同一场景资源自然呈现。
8. Godot 导入参数由 TA 最终锁定；原画交付时附建议过滤、压缩、图集与锚点表，不直接套用 Unity Character Rig 规则。

## 5.3 玩具源文件分层建议

```text
toy_rabbit.psb
├── guide @_Hide
├── right
│   ├── face
│   ├── ears
│   ├── body
│   ├── feet_tail
│   └── accessory
├── left
├── up
├── down
└── pose_guide
```

小鸭和鲸鱼使用同一逻辑；如后续使用 2D 骨骼动画，再由动作需求确定头、躯干、耳、尾、鳍等部件的最终拆分，不在本 ADD 预设过度复杂骨骼。

# 6. 验收标准

## 6.1 场景原画验收

| 检查项 | 合格标准 | 严重程度 |
| --- | --- | --- |
| 风格统一 | 柔和粉彩、扁平二维娃屋感，无塑料 3D 和强镜面 | 致命 |
| 玩法层级 | 盘面和三类玩具为第一阅读层，背景主动降对比 | 致命 |
| 出口可见 | 四周缺口不被装饰、HUD 或前景遮挡 | 致命 |
| 无假格线 | 盘面和地面纹理不形成硬网格、假路径 | 主要 |
| 分层完整 | 远景、中景、盘面、围边、缺口、前景可独立控制 | 致命 |
| 空盘复用 | 清空后无需另换背景即可自然显示完成状态 | 主要 |
| 多分辨率 | 1080×1920 和异形屏裁切后无黑边、无关键元素缺失 | 主要 |

## 6.2 玩具原画验收

| 检查项 | 合格标准 | 严重程度 |
| --- | --- | --- |
| 占格比例 | 兔子1×2、小鸭1×1、鲸鱼1×3一眼可区分 | 致命 |
| 方向可读 | 兔子/鲸鱼头尾清楚，不依赖箭头 | 致命 |
| 小鸭语义 | 不暗示只能按面朝方向移动，四向占格一致 | 致命 |
| 高密度缩放 | 缩到实际盘面尺寸后身份、头尾、颜色仍清楚 | 致命 |
| 风格材质 | 三类统一为柔软布偶/玩具，描边与光影一致 | 主要 |
| 四方向画布 | 尺寸、锚点、阴影基线一致，无跳位 | 主要 |
| 透明边缘 | 无白边、黑边和半透明脏点 | 主要 |
| 特效分离 | 静态图不含撞击粒子、路径星轨和提示光圈 | 主要 |

## 6.3 通过标准

- 致命项必须为 0。
- 主要项不超过 3 项且必须有明确修复排期。
- 次要装饰优化可后续处理，但不得牺牲玩法占格、方向和出口可读性。

| 自检问题 | 结论 | 证据/处理 |
| --- | --- | --- |

| 是否覆盖全部玩法玩具 | 是 | 兔子、小鸭、鲸鱼均独立列项 |

| 是否把动作/特效混入静态原画 | 否 | 第 4.4 章登记依赖，运行时效果不烘焙 |
| 是否误展开夜晚终关场景 | 否 | 明确由章节系统负责 |
