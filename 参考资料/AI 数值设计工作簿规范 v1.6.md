# AI 数值设计工作簿规范 v1.6
## 0. 目的与适用范围

### 0.1 目的

指导 AI 在**不新增玩法逻辑**的前提下，依据 MDD（系统模块、配置表设计、数值与经济设计）产出一份**完整的（不需要用户补充数据）、可直接配置、可维护、可验算**的《数值设计工作簿》（Excel），并确保读者**一眼看懂**：

- 这个模块的数值**怎么设计**（基准、价值、概率、拐点、上限）
- 这个模块的数值**怎么配置**（表怎么填、字段口径、哪些是旋钮）

### 0.2 适用对象

- 数值策划 / 系统策划 / 主策
- 程序（需要对接配置）
- QA（需要验算、覆盖边界与周期）

### 0.3 适用范围

- 适用于活动、战斗、养成、经济、掉落/随机、排行榜、PVE/PVP等大多数系统的数值化。
- 不限制项目类型（MMO/卡牌/SLG/经营/二合等），但**必须以** **MDD** **已定义规则为边界**。

### 0.4 v1.3 变更摘要（增补）

- 新增：**公式最小交付**（强制验收门槛），避免仅输出静态数值。
- 新增：**场景模拟表（验算表）**（按触发器强制），用于一连串数值推演与体验验算。
- 新增：《总览》模块索引字段：**是否需要场景模拟表**、**模拟表位置**，便于快速定位验算入口。
- 新增：模块自检结论项：**公式联动**、**场景模拟表**（通过/不通过/不适用）。
- 更新：AI生成指令模板与验收标准，强制覆盖“可调参 + 可复算 + 可推演”。




### 0.5 v1.4 变更摘要（增补）

- 新增：**单模块单工作簿（强制）**：系统拆分多个子模块后，仍只交付 1 个 Excel 数值工作簿，避免主/子模块口径分裂。
- 新增：**主模块综合验算台（跨子模块）**：当存在“跨子模块联动/互为影响/综合评分或综合产出”时，必须在主模块工作簿中提供综合验算台。
- 新增：**配置覆盖矩阵（强制）**：数值工作簿必须覆盖该系统所有配置块的“数值相关可配内容”，并给出覆盖位置与自检结论（覆盖率=100%）。
- 新增：**模块级推演模板（员工六大状态示例）**：提供30天推演表结构、KPI输出与P50/P90风险口径（仅对概率事件）。
- 更新：生成指令与验收标准，强制检查“综合验算台”“配置覆盖矩阵”“跨子模块引用一致性”。


### 0.6 v1.5 变更摘要（增补）

- 新增：**通用组件库 Sheet（强制允许）**：用于集中承载跨子模块复用的口径（如 Buff/Debuff、曲线/映射/权重），降低 Sheet 数量并避免口径分裂。
- 新增：**通用组件库-效果（Buff/Debuff）最小标准结构（强制）**：子模块只能引用效果库，不得复制效果定义。
- 新增：**通用组件库-曲线（可选但推荐）**：统一分段/映射/权重/成长曲线口径，供各模块查表引用。
- 新增：**模块Sheet拆分原则（强制）**：同一模块优先“同Sheet分区块”，禁止为了拆表而拆出大量碎片Sheet；确需拆分仅允许“模块名-上/模块名-下”。
- 更新：**推荐落库路径**与“引用写法”对齐扁平目录（数值工作簿默认放 `00-主MDD/`）。

### 0.7 v1.6 变更摘要（增补）

- 新增：**结构化输入控件规范（强制）**：对有限集合输入、引用型输入、高误填风险输入建立统一的数据验证与输入约束规则。
- 新增：**输入字段类型划分（强制）**：将可编辑字段划分为连续数值输入、有限集合输入、引用型输入、计算输出。
- 新增：**下拉列表适用判定规则（强制）**：明确什么字段必须做成下拉，什么字段不应做成下拉。
- 新增：**候选值来源、默认值、空值、联动要求（强制）**：保证结构化输入可操作、可复算、可维护。
- 新增：**模拟与验算入口规则（强制）**：要求场景模拟表、综合验算台、批量推演区的路径切换输入优先做成下拉或等价控件。
- 更新：自检清单、AI 生成指令模板、验收标准，新增“输入方式匹配性”“枚举口径唯一性”“模拟入口可操作性”检查项。




## 1. 唯一交付物与边界

### 1.1 唯一交付物（强制）

- **仅输出 1 个 Excel 工作簿**：`.xlsx`（如需宏/批量模拟可用 `.xlsm`）
- **所有数值说明必须写在 Excel 内**：不再另出 Word/Markdown/PDF。

### 1.2 AI 的边界（强制）

- 只做“数值化/参数化/表格化/校验化”，不得：
  - 新增玩法规则
  - 改写 MDD 的规则含义
  - 重新定义模块结构与模块命名
- 若 MDD 缺少关键输入（如奖励池、成本、目标体验等）：
  - 可在《总览》Sheet 记录“待确认/假设”
  - 但不得把假设当作最终设计结论替代产品决策


### 1.3 单模块单工作簿（强制）

- 一个系统模块（主模块）在任意版本、任意拆分方式下，**只允许交付 1 个 Excel 数值设计工作簿**。
- 若该系统模块被拆分为多个子模块：  
  - 子模块数值说明文档（如有）只能引用同一个工作簿中的对应 Sheet/区块；  
  - **禁止**为不同子模块分别生成多个 Excel 工作簿（会导致口径分裂与不一致）。

**推荐落库路径：**
- `docs/design/{模块名称}/00-主MDD/数值-{模块名称}设计工作簿.v{版本}.xlsx`

**引用写法（示例）：**
- 在主MDD或子模块设计文档中引用：  
  `详见《数值-{主模块名称}设计工作簿》vX.X（Sheet：{Sheet名}；区块：{区块标题}）`



## 2. 命名与 Sheet 划分规则

### 2.1 Sheet 命名（必须）

- **每个 Sheet 名称必须与** **MDD** **中“系统模块名称”逐字一致**：
  - 可加编号前缀（如“01_”）
  - 不自创英文名
- 若同一模块内容过大需拆分：
  - `模块名（1）/ 模块名（2）` 或 `模块名-上/模块名-下`
  - **模块名部分必须与** **MDD** **一致**

### 2.2 Sheet 划分（必须）

- **按** **MDD** **系统模块划分**：一个模块对应一个 Sheet
- **禁止跨模块混写配置表**（例外：通用组件库Sheet 作为跨模块共享口径源，不属于任何单一模块）：
  - 该模块 Sheet 只包含该模块的可配置内容与设计思路
  - 其他模块仅能“引用/指向”，不得复制与重定义

### 2.3 允许新增 Sheet（例外规则，强制允许）

- 即使 MDD 没有，也允许新增以下固定名 Sheet（不视为新增玩法逻辑）：

1) **《总览》**（必做）  
用于承载：全局说明与基准、Sheet索引、全局校验看板、待确认与假设清单、配置覆盖矩阵。

2) **通用组件库 Sheet**（v1.5新增，按需）  
用于承载跨子模块复用口径，作为唯一口径源供各模块引用：  
- `通用组件库-效果`（Buff/Debuff/状态效果，存在效果时建议必做；结构见 2.4）  
- `通用组件库-曲线`（分段/映射/权重/成长曲线，可选但推荐）  
- `通用组件库-校验`（可选：通用断档/上限/预算校验口径）

3) **综合验算台 Sheet**（按触发器强制）  
当存在跨子模块联动/互为影响/综合评分或综合产出时，允许新增：`综合验算台-xxxx`（见 10.）。





### 2.4 通用组件库 Sheet（强制允许）

> 目标：在“单模块单工作簿”前提下，降低 Sheet 数量与阅读成本，同时保证跨子模块口径不分裂。

硬规则：
1. 通用组件库只承载“可复用口径”，禁止写入某个子模块专属语义字段。
2. 子模块Sheet **只能引用**通用组件库，不得复制一份效果表/曲线表。
3. 《总览》的配置覆盖矩阵中，通用组件库相关配置块必须标注覆盖位置与覆盖类型。

#### 2.4.1 通用组件库-效果（Buff/Debuff）最小标准结构（强制）

A）效果定义表（主表）

| 字段（中文） | 类型 | 说明 |
|---|---|---|
| 效果ID | 文本/数字 | 全工作簿唯一；用于被引用 |
| 效果名 | 文本 | 业务名词（纯中文） |
| 效果类型 | 枚举 | 增益/减益/光环/状态标记 |
| 作用对象 | 枚举 | 自身/目标/队伍/全局（模块内） |
| 作用维度 | 枚举 | 属性/效率/概率/成本/产出/冷却（可多选，用分号分隔） |
| 影响方式 | 枚举 | 加算/乘算/替换/夹紧（上限下限） |
| 影响目标（中文） | 文本 | 例如：工作效率/疲劳变化量/离职概率等（纯中文） |
| 参数来源 | 枚举 | 旋钮/曲线表/主表行（引用来源） |
| 参数A引用 | 引用/键 | 指向旋钮格/曲线ID/主表键（不手填静态值） |
| 参数B引用 | 引用/键 | 可选；用于分段/阈值/上下限等 |
| 生效条件引用 | 文本 | 条件描述（纯中文）；或“引用条件组：xxx” |
| 触发时机 | 枚举 | 即时/每日结算/事件触发/持续生效 |
| 持续类型 | 枚举 | 瞬时/持续天数/永久/直到条件不满足 |
| 持续值 | 数值 | 配合持续类型 |
| 叠加规则 | 枚举 | 不叠加/刷新持续/层数叠加/取最大/取最小 |
| 叠加上限 | 数值 | 层数叠加时必填 |
| 优先级 | 数值 | 多效果同时作用时的先后顺序（按项目口径） |
| 备注 | 文本 | 边界说明与口径补充 |

B）效果应用表（各子模块Sheet内使用，引用通用库）

| 应用ID | 引用效果ID | 应用来源（纯中文） | 应用对象 | 触发条件（纯中文） | 叠加层数（输入/计算） | 生效值（计算） | 备注 |
|---|---|---|---|---|---|---|---|

硬规则：
1. 子模块Sheet禁止复制“效果定义表”；必须通过“引用效果ID”引用 `通用组件库-效果`。
2. “生效值（计算）”不得手填，必须由“参数引用 + 影响方式口径”推导得到。
3. 在《总览》的配置覆盖矩阵中，效果相关配置块的“覆盖位置”必须指向 `通用组件库-效果`。

C）影响方式口径（建议统一写死）
- 加算：目标值 = 目标值 + 生效值
- 乘算：目标值 = 目标值 * (1 + 生效值)（或 * 生效倍率；二选一并固定）
- 替换：目标值 = 生效值
- 夹紧：目标值 = min(max(目标值, 下限), 上限)

#### 2.4.2 通用组件库-曲线（可选但推荐）

当存在大量分段/映射/权重/成长曲线时，可新增 `通用组件库-曲线` 作为统一口径源：

| 曲线ID | 曲线名 | 自变量口径（中文） | 分段点/区间 | 输出值 | 插值方式 | 备注 |
|---|---|---|---|---|---|---|

### 2.5 模块Sheet拆分原则（强制）

1. 同一模块的“旋钮区/参数/触发/效果引用/场景推演/校验”必须优先在 **同一Sheet内用区块组织**。
2. 仅当单Sheet确实无法阅读时，才允许拆为：`模块名-上 / 模块名-下` 两张Sheet。
3. 禁止为了拆表而拆出大量碎片Sheet（例如：`模块名-参数/模块名-事件触发/模块名-初始值` 等），避免Sheet爆炸与阅读成本上升。

> 历史遗留碎片Sheet可采用“新增汇总Sheet（可见）+ 隐藏明细Sheet（不删除）”方式过渡；如需删除与迁移属于重构动作，需谨慎。


## 3. 字段语言与可落地配置规则

### 3.1 字段语言规则（强制：全中文优先）

- 工作簿内：
  - 表头字段、参数名、注释、说明、口径、公式解释：**全部中文**
- 仅当需要对接程序导出字段时，允许在模块 Sheet 角落追加一个可选小表：
  - **《字段映射》**：`中文字段名 ↔ 程序字段名（英文）`
  - 英文只出现在这一小表中，不得扩散到主表

### 3.2 可维护性规则（强制）

- 模块内计算/推导尽量做到：
  - **关键数字来自“旋钮区/基准参数区”**，避免散落硬编码
  - 主配置表可直接复制为配置数据（纯数据），计算列可保留但要清楚标注“计算列/不导出”

## 3A. 结构化输入控件规范

### 3A.1 目标

工作簿不仅要“可配置”，还要“可操作”。
对于候选值有限、口径固定、频繁切换、误填成本高的字段，必须使用结构化输入控件，而不是默认自由手填。

结构化输入控件的目标：

- 降低误填与口径分裂风险
- 提高调参、验算、场景切换效率
- 保证输入项与公式、模拟、KPI结果自动联动

### 3A.2 输入字段类型划分（强制）

工作簿中的可编辑字段必须先按语义划分为以下四类：

1. **连续数值输入**
   - 例：阈值、倍率、概率、成本、权重、时间、数量
   - 默认使用普通输入格，不做下拉列表

2. **有限集合输入**
   - 例：状态、模式、档位、策略、阶段、类型、布尔值、风险等级、结算方式、触发时机
   - 默认使用下拉列表或等价的数据验证约束

3. **引用型输入**
   - 例：效果ID、曲线ID、配置ID、对象ID、资源ID、奖励池ID
   - 必须从显式口径源中选择；优先使用下拉列表，或使用引用表/搜索式选择机制

4. **计算输出**
   - 例：公式列、KPI、模拟结果、风险结论
   - 不允许手填，不使用下拉

### 3A.3 必须使用下拉列表的情形（强制）

当字段满足以下任一条件时，必须使用下拉列表或等价的数据验证约束：

- 字段值来自有限且稳定的候选集合
- 字段值参与条件判断、查表映射、分支计算、状态切换或模拟路径切换
- 手工输入错误会导致引用失效、口径不一致或结果不可复算
- 用户在调参、对比、验算过程中需要高频切换该字段
- 字段本质属于“类型/模式/状态/档位/策略/是否/阶段”等枚举语义

### 3A.4 不应使用下拉列表的情形

以下字段通常不应做成下拉：

- 连续数值字段
- 长文本说明字段
- 自由命名字段
- 纯公式输出字段
- 候选值规模过大、不适合人工下拉的字段

对于“候选值规模过大”的字段，应改用：

- 引用表
- 编码表
- 搜索式选择
- 受限输入 + 校验机制

### 3A.5 候选值来源要求（强制）

所有下拉列表或枚举型输入，其候选值必须满足：

- 候选值必须来自工作簿内显式维护的枚举区、组件库、参数区或引用表
- 禁止仅在说明文字、备注、注释中列出候选值
- 禁止在多个 Sheet 重复维护同一套候选值口径
- 若该候选值属于跨模块共享口径，必须统一放入：
  - `通用组件库`
  - 或 `通用校验区/枚举区`

### 3A.6 默认值与空值规则（强制）

每个结构化输入字段都必须定义：

- 默认值
- 是否允许留空
- 候选值来源位置

同时满足：

- 默认值必须是合法候选值之一
- 默认值应优先选取基准场景、最常用场景或最安全值
- 若允许空值，必须说明空值的业务语义
- 若不允许空值，应启用输入校验拦截非法输入

### 3A.7 联动要求（强制）

任何结构化输入控件一旦变更，相关区域必须自动联动更新，包括但不限于：

- 公式区
- 主配置表
- 场景模拟区
- 综合验算台
- KPI 输出区
- 风险提示区

禁止出现以下情况：

- 输入控件只改变显示文字，不改变计算结果
- 显示值与实际计算口径不一致
- 同一字段在不同 Sheet 切换后结果不一致

### 3A.8 高频输入优先规则（强制）

若某输入字段在单次验算流程中存在高频切换需求，则必须优先做成结构化控件。

建议判定标准：

- 用户单次验算中预计会修改该字段 3 次及以上
- 该字段用于对比不同方案、不同状态、不同路径
- 该字段是场景推演入口，而非单次初始化参数

### 3A.9 AI 执行要求（强制）

AI 在生成工作簿时，必须：

1. 识别所有有限集合输入与引用型输入
2. 判断该字段是否应使用下拉或其他结构化约束
3. 为适合的字段创建数据验证或等价控件
4. 在《总览》或对应模块中标注关键结构化输入字段及其来源位置

### 3A.10 建议增加的实现约定（推荐）

为便于 AI 与人工维护，推荐在工作簿中增加以下结构之一：

- `通用组件库-校验`
- `通用组件库-枚举`
- 模块内 `枚举区`
- 模块内 `输入控件清单`

推荐记录字段：

- 字段名
- 字段类型
- 控件类型
- 候选值来源
- 默认值
- 是否允许空值
- 联动区域

## 4.《总览》Sheet 规范（必须具备的最小内容）

《总览》目标：**打开就能知道“有哪些模块、改哪里、怎么验算”。**

### 4.1 必填区块

1. **版本与范围**

- 工作簿版本号、生成日期、对应 MDD 版本/日期
- 覆盖模块列表（=Sheet 列表）

1. **全局设计基准（必须清楚、可执行）**

- 时间口径：服务器时间/重置点/周月周期口径
- 概率口径：权重转概率方式、保底/重复规则的统一口径（若项目统一）
- 价值口径：价值单位（如“金币等价/积分等价/不统一”）与说明

1. **模块索引（总表索引）** 建议表格字段：

- `模块名（Sheet）`
- `该模块主要配置表/主表位置`
- `关键旋钮（在哪些格子/哪一块）`
- `是否需要场景模拟表（是/否/不适用）`
- `模拟表位置（Sheet名 + 区域标题）`
- `主要产出（给谁用：策划/程序/QA）`
- `高风险点（通胀/卡点/唯一解/爆表）`
1. **全局校验****看板****（强烈建议，若可算则必做）**

- 区间覆盖：等级段/名次段/档位段是否断档
- 产消/价值：关键资源日净流入/净流出（如涉及经济）
- 体验指标：例如“拉满需要几次/几天/多少资源”

1. **待确认与假设清单（****当且仅当****存在缺口）** 字段建议：

- `缺口项 / 影响模块 / 默认假设 / 风险 / 需要谁确认`

### 4.2 配置覆盖矩阵（强制）

> 目标：保证“数值设计表覆盖该系统所有配置块的数值相关内容”，避免漏项与主/子模块不一致。

在《总览》Sheet 增加一张 **配置覆盖矩阵**（可放在模块索引附近），用于逐条核对本系统的配置块是否已在工作簿中可调参/可复算/可推演。

**表头（建议固定）：**

| 配置块名（中文） | 归属（主模块共享/子模块） | 配置文档引用 | 本工作簿覆盖位置（Sheet+区块） | 覆盖类型（静态配置/公式联动/场景推演） | 覆盖自检（通过/不通过） | 不适用原因（如有） |
|---|---|---|---|---|---|---|

**硬规则：**
1. 覆盖自检必须为“通过”才算覆盖完成；覆盖率必须为 **100%**。  
2. “覆盖类型”用于约束输出质量：  
   - 静态配置：允许无公式，但必须写明“不需要推演”的原因；  
   - 公式联动：关键结果必须随旋钮变化自动更新；  
   - 场景推演：必须存在可复算的推演区（验算台/模拟表）。  
3. 配置块的字段结构与校验约束仍以《配置表设计说明》为准；数值工作簿只负责“数值相关可配内容”的调参与验算，不重复字段结构。

## 8. Excel 公式使用规则

### 1）总体原则（先结论）

Excel 公式的作用不是“炫技”，而是让工作簿满足三件事：

1. **可复算**：别人能按同样口径复算出同样结果
2. **可调参**：改旋钮（基准参数）后，关键结果能自动更新
3. **可校验**：能自动发现断档、超上限、期望不达标等问题

因此：

- **只有当“需要复算/需要调参联动/需要自动校验”时，才写公式。**
- 若只是静态配置（纯手填即可且不会推导），**不写公式**。

### 2）必须写公式的场景（强制）

以下任一情况成立，该模块 Sheet 必须写入 Excel 公式（写在同 Sheet 内，紧贴主表或作为计算列）：

#### 2.1 概率/权重相关（随机类必做）

当 MDD 涉及：权重、概率、随机池、掉落、词条、保底、重复限制等，必须写公式计算至少：

- `概率（计算） = 权重 / 权重总和`
- `期望获得数量（计算） = 概率 × 数量`
- `期望价值（计算） = 概率 × 数量 × 单件价值`
- 若有保底：至少给出“保底触发后的期望变化”的一个可复算口径（可简化）

目的：一眼看懂“权重怎么变概率、期望怎么来”。

#### 2.2 价值/定价/对齐基准（经济与奖励必做）

当模块涉及：奖励档位、礼包价值、兑换价格、积分价值、货币价值对齐等，必须写公式计算至少：

- `总价值（计算） = Σ（数量 × 单件价值）`
- `折扣/倍率（计算） = 总价值 / 基准价值`（或反过来）
- 若涉及“每日/每周预算”：写 `单位周期可获得价值（计算）` 与 `单位周期消耗价值（计算）`

目的：一眼看懂“为什么这档奖励值这个价”。

#### 2.3 曲线/分段规则（成长与成本必做）

当模块涉及：等级段、阶段、曲线、递增成本、递减收益、分段系数等，必须写公式计算至少其一：

- `需求值（计算） = 基准 × 段系数 × (等级或次数函数)`
- `单位收益（计算）`、`边际收益（计算）`（可选但强烈建议）
- `达成次数/达成天数（计算） = 目标值 / 单次收益`

目的：一眼看懂“拐点在哪里、变陡是因为什么”。

#### 2.4 上限/重置/次数/冷却引发的“周期校验”（周期类必做）

当模块涉及：每日/每周重置、次数上限、冷却、活动窗口等，必须写公式计算至少：

- `周期最大可获得（计算） = 单次产出 × 周期次数上限`
- `周期最大可消耗（计算） = 单次消耗 × 周期次数上限`
- `是否超上限（校验） = IF(实际>上限,"超标","正常")`
- `区间覆盖校验（断档/重叠）`（见 4.2）

目的：一眼看出是否“配置能跑”、是否“会通胀/会卡死”。

#### 2.5 多模块引用同一基准参数（联动必做）

当一个模块的输出依赖另一个模块的旋钮（例如积分价值/货币价值/活动日预算），必须写引用公式（跨表引用）以确保联动：

- 主配置表中的关键结果必须引用“旋钮区”单元格，而不是写死数值。

目的：改基准，所有相关表自动更新，不靠人工改 20 处。

### 3）建议写公式的场景（推荐）

满足以下情况建议写公式，但不强制：

- **敏感性分析**：关键旋钮 ±10% 后的结果变化（用两列对照即可）
- **覆盖率统计**：名次段、积分段、等级段是否覆盖 100%
- **QA** **用例区**：给 2–3 组输入，自动算输出（避免手算）
- **风险提示**：如“单次奖励价值超过日预算 X% 自动标红提示”（若你们有样式/条件格式要求可再补）

### 4）禁止写公式的场景（明确不写）

以下情况不应写公式，以免工作簿复杂、难维护：

#### 4.1 纯静态枚举配置

例如：固定文案ID、固定展示标签、固定开关枚举、资源路径等

 → 直接手填，不写公式。

#### 4.2 MDD 未定义口径且会引入玩法假设

例如：MDD 没说保底策略，AI不应通过公式“设计出一个保底体系”

 → 只能在《总览》列“待确认”，不写推导公式替代决策。

#### 4.3 公式过于复杂导致不可维护

例如：单元格内嵌超长嵌套 IF/LOOKUP 超过可读阈值

 → 应拆解为“中间列/中间表”，或改为更直观的分段表驱动（优先表驱动）。

### 5）公式写在哪里（放置规范）

由于你强调“结构按 MDD 配置表设计”，公式放置遵循以下规则：

1. **优先写成主表的“计算列”**（紧贴字段，不跳页）
   1. 例如：`概率（计算）/期望价值（计算）/总价值（计算）/达成次数（计算）`
2. **旋钮区必须是公式的输入源**
   1. 任何关键数值变化应来自顶部旋钮区引用
3. 若计算列会污染导出：
   1. 在列名中标注 `（计算）` 或 `（不导出）`
4. 若必须做中间推导：
   1. 放在同 Sheet 的右侧区域，命名为“中间量”，并在主表计算列引用

### 6）公式写法规范（让 AI 写得可读可维护）

- **引用旋钮，不硬编码**

   1. 除 0/1 等常量外，主表公式不得写死关键数值
- **能用表驱动就别用深嵌套**

   1. 分段系数/阈值优先做成小表，用 `XLOOKUP/INDEX-MATCH` 引用
- **单位与口径一律****显式**

   1. 百分比统一用一种口径（建议：Excel 单元格用 5% 展示，但内部仍是 0.05）
- **每个模块至少 3 个自动校验格**（强烈建议）

- 断档、超上限、总价值超预算/低于目标

  ## AI 生成流程（执行顺序）

- 读取 MDD 的模块目录 → 得到模块名列表（这些必须成为 Sheet 名）

- 创建《总览》Sheet（固定允许）
- 逐模块生成 Sheet：
   1. 先按 MDD 配置表设计搭“主表”
   2. 再补顶部“旋钮区”
   3. 按需补“概率/价值/基准/拐点”说明与计算列
   4. 给出 2–3 个可验算样例或校验结论
- 回到《总览》补：
   1. 模块索引（每个模块主表在哪、旋钮在哪）
   2. 全局校验看板（能算则算）
   3. 待确认与假设（如存在）


### 7）公式最小交付（强制验收门槛）

当某模块命中“必须写公式的场景（2.1–2.5）”中的任意一项时，该模块 Sheet 必须满足以下最小交付，否则视为不合格：

1. **计算列最小数量**：主表或紧贴主表必须至少包含 **3 列“计算列”**（列名必须包含“（计算）/（校验）/（不导出）”之一），用于把配置推导为关键结果（例如：概率、期望、总价值、达成次数等）。
2. **旋钮引用最小数量**：顶部旋钮区必须至少有 **5 个关键旋钮**被主表/计算列引用（不能写死）。若旋钮少于 5 个，需在自检写明原因（例如：模块确实只有 2 个关键旋钮）。
3. **自动校验最小数量**：每模块至少 **3 个自动校验格**（例如：断档/重叠、超上限、期望不达标、预算超标），并给出“通过/不通过”的可读结果。
4. **禁止手填输出**：任何“输出指标/验算结果/校验结论”不得手填静态数值，必须由旋钮区 + 主表配置 + 计算列推导得到。

> 备注：若模块属于“纯静态枚举配置”（4.1）或“不会推导”的纯手填表，可在自检写“公式联动：不适用（原因）”。

### 8）场景模拟表（重要场景推演，按触发器强制）

#### 8.1 定义
场景模拟表用于把“关键旋钮 + 主表配置”串成一段可复算的数值推演，支持快速验算体验与边界。  
结构必须包含：**输入（引用） → 推导（计算） → 输出指标（计算） → 校验结论（计算）**。

#### 8.2 表结构（建议固定列）
| 场景ID | 场景名 | 玩家分层 | 时间跨度 | 输入：关键旋钮（引用） | 输入：关键配置（引用） | 推导：中间量（计算） | 输出：关键指标（计算） | 校验（通过/不通过） |
|---|---|---|---|---|---|---|---|---|

#### 8.3 硬规则（强制）
1. **输出不得手填**：场景模拟表中“输出：关键指标（计算）”与“校验”列不得手填，必须为公式结果。
2. **输入必须引用**：场景模拟表的输入必须引用旋钮区或主表行（例如：引用某一档位、某一等级段、某一奖励行），禁止复制粘贴静态数。
3. **场景最小数量**：每个需要场景模拟表的模块，至少提供 **3 个场景**：
   - 基准场景（默认旋钮）
   - 上限/边界场景（次数上限/预算上限/极端概率/极端段位）
   - 高风险场景（通胀/卡点/爆表/唯一解等，来自《总览》高风险点）
4. **输出指标必须可读**：输出列必须产出可直接讨论体验的结果口径，例如：
   - “达到目标需要 X 次 / X 天”
   - “周期净流入 = 产出 - 消耗”
   - “期望价值 / 波动范围（可简化为上下界）”
5. **位置建议**：默认放在模块 Sheet 的右侧或下部，紧贴主表与校验小结，便于一屏查看。

### 9）如何判定必须设计场景模拟表（强制触发器）

模块命中以下任一项 → **必须**提供场景模拟表（见 8）：

1. 随机/概率/权重/保底/掉落/词条（对应 2.1）
2. 奖励/定价/兑换/价值对齐（对应 2.2）
3. 成长/曲线/分段/递增成本/递减收益（对应 2.3）
4. 次数/冷却/重置/活动窗口引发的周期校验（对应 2.4）
5. 多模块联动引用同一基准参数（对应 2.5）
6. 《总览》中被标记为高风险点（通胀/卡点/爆表/唯一解）

不触发上述条件的模块，可在《总览》标记为“是否需要场景模拟表：否”或“不适用（原因：纯静态枚举/无推导）”。

### 10）主模块综合验算台（跨子模块，强制）

#### 10.1 适用范围
当系统存在以下任一情况时，必须在主模块工作簿中提供 **综合验算台**（可单独一个Sheet，或在《总览》内以大区块呈现）：
1. **跨子模块联动**：同一核心对象的关键结果同时被 ≥2 个子模块改变。  
2. **互为影响/环形链路**：多个状态或多个数值项相互影响，存在正反馈/负反馈，需用推演验证稳定性。  
3. **综合评分/综合产出/综合风险**：汇总指标依赖多个子模块输入（例如：综合评分依赖多个加成项）。

#### 10.2 输出目标（强制）
综合验算台必须做到：**可调参 + 可复算 + 可推演**，并输出可讨论体验的指标（而不是静态填数）。

#### 10.3 区块结构（推荐固定）
综合验算台建议拆为 4 个区块（可同Sheet上下布局）：
1. **对象选择/场景选择区**：选择单对象、阵容/团队、玩家分层等；支持切换不同场景行。  
2. **旋钮区（参数输入）**：关键参数统一从旋钮区输入，并被所有计算与推演引用。  
3. **推演区**：
   - 一次性成型计算区（给定目标参数，直接输出最终结果）；  
   - 过程推演区（按天/按步滚动，状态由上一行推到下一行）；  
   - 参数扫表区（可选，用于敏感性分析）。  
4. **结果与校验区**：输出KPI与校验结论（通过/不通过），并标注风险点。

### 11）综合验算台示例：员工六大状态系统（30天推演，强制模板）

> 目标：验算“六大状态互为影响”在不同参数下对员工整体与团队产出的影响，并给出离职风险 P50/P90（仅对概率事件）。

#### 11.1 固定输出KPI（本示例强制）
- 工作效率：均值 / 最低值 / 波动幅度  
- 疲劳>80天数  
- 心情<40天数  
- 健康<30触发天数  
- 忠诚<30累计天数  
- 离职风险：P50 / P90（仅对离职概率事件）  
- 熟练度成长速度：达成80所需天数  
- 团队层（如适用）：项目进度加成/减速幅度（以团队效率聚合推导）

#### 11.2 旋钮区（示例字段）
- 初始状态：心情/忠诚/健康/疲劳/熟练度/压力（或其他六大状态）  
- 状态交互系数：每个状态对其他状态的影响系数（建议矩阵形式展示）  
- 工作强度：基础负载、加班强度、休假频率、福利强度  
- 恢复/衰减：自然恢复、自然衰减、阈值触发的额外变化  
- 效率映射：各状态对效率的权重或分段映射  
- 概率事件：离职基础概率、离职系数、触发阈值（例如忠诚低于某阈值）  

#### 11.3 推演区A：30天日推演表（强制）
粒度：按天（Day 1…Day 30），每行依赖上一行的“状态后值”。

| 天数 | 当日策略（加班/休假/福利） | 状态前：心情 | 状态前：忠诚 | 状态前：健康 | 状态前：疲劳 | 状态前：熟练度 | 推导：状态变化（计算） | 状态后：心情 | 状态后：忠诚 | 状态后：健康 | 状态后：疲劳 | 状态后：熟练度 | 当日效率（计算） | 离职概率p（计算） | 累计离职概率（计算） |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|

硬规则：
1. “状态后”必须由“状态前 + 状态变化（计算）”得到，且状态变化必须引用交互系数与策略输入。  
2. “当日效率”必须由状态后值映射得到（权重/分段表均可）。  
3. “离职概率p”仅用于概率事件：建议按“基础概率 + 状态触发项”计算，并夹紧到 0~1。  
4. “累计离职概率”建议用生存概率递推：  
   - 生存概率S(0)=1  
   - S(t)=S(t-1)*(1-p(t))  
   - 累计离职概率=1-S(t)

#### 11.4 推演区B：P50/P90离职风险口径（强制）
仅针对离职概率事件，输出 P50/P90（以“累计离职概率达到阈值的最早天数”表达）：
- P50天数：最早满足“累计离职概率 ≥ 0.50”的天数；若30天内未达到则返回“>30天”。  
- P90天数：最早满足“累计离职概率 ≥ 0.90”的天数；若30天内未达到则返回“>30天”。  

#### 11.5 推演区C：团队/项目进度聚合（可选但推荐）
当需要团队层输出时，建议增加团队区块：
- 团队构成：人数、角色权重（可简化为“平均/最弱/关键岗位”三类）  
- 团队效率聚合：用单人效率列聚合得到团队效率（均值/加权均值/最小值等）  
- 项目进度影响：用“团队效率”映射到“进度加成/减速幅度”（可用分段表）

#### 11.6 结果与校验区（强制）
输出以上KPI，并给出“通过/不通过”校验：
- 效率均值是否落在目标区间  
- 最低效率是否低于警戒线  
- 疲劳>80与健康<30是否超过容忍天数  
- P50/P90是否过低（风险过大）  
- 熟练度达成80的天数是否满足节奏目标  
- 团队进度是否可接受（如适用）


## 9. 自检清单（必须在每个模块 Sheet 留一行“自检结论”）

每个模块 Sheet 输出后，AI 必须确认并写出结论（通过/不通过 + 修正点）：

1. **可配置**：主表字段齐全、单位口径明确

2. **旋钮清晰**：顶部能找到关键可调参数

3. **可理解**：概率/价值/基准/拐点至少解释了关键决策

4. **可验算**：至少提供 2 个样例或可复算的校验结果

5. **边界完整**：区间覆盖无断档，上限/重置/冷却明确

6. **不串模块**：不混写其他模块的数据表与口径

7. **公式联动**：关键结果是否随旋钮调整自动更新（通过/不通过/不适用）

8. **场景模拟表**：是否按触发器提供模拟表并可复算（通过/不通过/不适用）

9. **配置覆盖矩阵**：覆盖率是否为100%，是否能定位到每个配置块的覆盖位置（通过/不通过）

10. **综合验算台**：是否命中触发器且已提供可推演验算台（通过/不通过/不适用）

11. **通用组件库**：存在效果类需求时是否已提供 `通用组件库-效果` 且子模块仅引用不复制（通过/不通过/不适用）

12. **Sheet可读性**：模块是否优先同Sheet分区块、未出现碎片化Sheet爆炸（通过/不通过）

13. **输入方式匹配性**：有限集合输入/引用型输入是否使用了合适的结构化控件（通过/不通过）

14. **枚举口径唯一性**：下拉候选值或引用候选值是否来自统一口径源、未重复维护（通过/不通过）

15. **模拟入口可操作性**：高频路径切换是否无需改公式即可完成（通过/不通过/不适用）

16. **输入方式匹配性**

    验收时必须检查：

    - 枚举型字段是否仍被设计为自由文本输入

    - 高频切换字段是否缺少结构化控件

    - 输入控件是否与字段语义匹配

17. **枚举口径唯一性**

    验收时必须检查：

    - 同一枚举口径是否被多个 Sheet 重复维护
    - 下拉候选值是否来自统一口径源
    - 输入显示值与公式引用值是否一致

18. **枚举口径唯一性**

    验收时必须检查：

    - 模拟路径切换是否可以不改公式完成
    - 是否支持快速切换典型场景
    - 高频枚举输入是否支持下拉或等价控件

## 10. 公式兼容性与报错防护

> 目标：避免工作簿在不同 Excel/WPS 环境中出现 `#NAME? / #N/A / #VALUE! / #REF!` 等报错，防止单点错误级联扩散，保证“可推演”稳定可用。

### 10.1 目标环境声明（强制）

- 默认目标环境：**WPS + 旧版 Excel 兼容模式**。
- 若项目确认使用 O365/新版 Excel 并允许新函数，必须在《总览》显式声明“允许的新函数清单”；否则一律按本章兼容规则执行。

### 10.2 公式函数白名单（强制）

工作簿公式仅允许使用以下函数（白名单）：

`IF, IFERROR, AND, OR, NOT, MIN, MAX, ROUND, ROUNDDOWN, ROUNDUP, INT, ABS,`
`SUM, SUMIF, SUMIFS, COUNT, COUNTIF, COUNTIFS, AVERAGE, AVERAGEIF, AVERAGEIFS,`
`LOOKUP, VLOOKUP, HLOOKUP, INDEX, MATCH,`
`LEFT, RIGHT, MID, LEN, VALUE, TEXT`

> 说明：使用白名单以保证在 WPS/旧 Excel 中不出现 `#NAME?`。

### 10.3 禁用函数清单与替代规则（强制）

禁止使用以下函数（在部分环境会直接 `#NAME?`）：

- `IFNA`
- `XLOOKUP`
- `FILTER`
- `LET`
- `LAMBDA`
- `SEQUENCE`
- `TEXTSPLIT`
- `STDEV.S`

替代规则（强制照抄）：
- `IFNA(a,b)` → `IFERROR(a,b)`
- `STDEV.S(range)` → `STDEV(range)`
- `XLOOKUP` → `INDEX + MATCH`（或 `VLOOKUP`）

### 10.4 查表键一致性与数据验证（强制，避免 #N/A）

适用范围：策略标签、效果ID、曲线ID、档位ID、阶段ID等所有“查表键”。

硬规则：
1. **键值必须唯一且完全一致**：禁止出现同义不同写（例如“996+Normal加班”与“996+Normal加班（高压默认）”）。
2. **键字段必须下拉选择（数据验证）**：  
   - 策略标签必须从“策略库标签列”下拉选择；  
   - 效果ID必须从“通用组件库-效果”的效果ID列下拉选择；  
   - 曲线ID必须从“通用组件库-曲线”的曲线ID列下拉选择。  
3. **键字段禁止手填自由文本**（除非是“新增配置录入区”，且必须同步补齐库表）。

### 10.5 查表公式兜底写法（强制，防止级联报错）

所有查表（`INDEX+MATCH` / `VLOOKUP` / `LOOKUP`）必须外层包裹兜底，禁止裸查表。

统一模板（强制）：
- `IFERROR(查表公式, 默认值)`

默认值口径（强制）：
- 数值型默认值：0 或“基准策略/基准曲线”的结果值（必须二选一并写死）
- 文本型默认值：空字符串或“基准”

示例（可复制）：
- `=IFERROR(INDEX(策略库参数列, MATCH(策略标签, 策略库标签列, 0)), 0)`

### 10.6 曲线库/效果库字段类型约束（强制，避免 #VALUE!）

1. 曲线库/效果库的“数值列”必须为 **数值或公式结果**。  
2. 禁止在数值列填“看起来像引用的文本”（例如 `'xx'!$B$14` 作为字符串）。  
3. 如需展示引用来源，必须新增“来源说明（文本）”列承载，禁止混入数值列。

### 10.7 报错扫描与验收口径（强制）

在《总览》Sheet 必须新增一个“错误扫描/校验区”（可用区块形式），至少覆盖：

- 策略标签匹配校验：通过/不通过
- 曲线ID存在校验：通过/不通过
- 效果ID存在校验：通过/不通过
- 推演区关键列报错校验：通过/不通过（不得出现 `#NAME?/#REF!`；`#N/A` 仅允许出现在“未选择输入”的提示格）

验收强制门槛：
- `#NAME? = 0`
- `#REF! = 0`
- 推演区不得出现连片 `#N/A`（若出现必须归因到“输入未选择”，并在校验区提示）

### 10.8 最小执行清单

- **函数白名单 + 禁用清单**（禁 IFNA / STDEV.S / XLOOKUP 等）

- **键字段必须下拉选择**（策略标签/曲线ID/效果ID）

- **所有查表必须 IFERROR 兜底**（禁止裸 INDEX+MATCH）

- **总览必须有“报错扫描/校验区” + 验收门槛**（#NAME?=0、#REF!=0）

### 10.9 硬验收

生成后必须在《总览》输出：策略校验=通过、曲线校验=通过、效果校验=通过、推演区报错=通过，否则视为不合格交付。

## 11. 可直接投喂 AI 的“生成指令模板”（推荐）

**任务**：根据提供的 MDD 与其配置表设计，生成《数值设计工作簿》（Excel）。 **规则**：

1. 仅输出一个 Excel，不另出说明文档；所有说明写在 Excel 内。
2. Sheet 名必须与 MDD 的系统模块名逐字一致；允许新增一个《总览》Sheet。
3. 每个 Sheet 的表结构以 MDD 的“配置表设计”优先；按需加入旋钮区、概率/价值/期望等设计思路与计算列。
4. 字段全中文；如需对接导出字段，仅在角落提供“中文字段名-英文导出字段名”对照表（可选）。
5. 输出必须一眼看懂：旋钮在顶部、主配置表在中部、关键口径与校验结论在旁边或下部。
6. 不新增玩法规则；信息缺口写进《总览》的“待确认与假设”。
7. 对命中“场景模拟表触发器”的模块，必须在该模块 Sheet 增加‘场景模拟表（验算表）’区：输入引用旋钮/主表，输出为公式结果，并至少提供基准/边界/高风险 3 个场景。
8. 对命中“必须写公式”的模块，必须满足‘公式最小交付’：至少 3 列计算列、至少 3 个自动校验格，并在自检结论写明“公式联动/场景模拟表”的通过情况。

9. **单模块单工作簿**：若系统已拆分多个子模块，仍只输出 1 个 Excel 工作簿；不同子模块内容以不同 Sheet/区块承载。
10. **配置覆盖矩阵**：在《总览》Sheet 增加“配置覆盖矩阵”，覆盖率必须100%，并标注每个配置块在工作簿中的覆盖位置与覆盖类型。
11. **综合验算台（跨子模块）**：若命中触发器（跨子模块联动/互为影响/综合评分或综合产出），必须在主模块工作簿中提供综合验算台，并在《总览》登记位置。
12. **通用组件库（v1.5）**：若系统存在 Buff/Debuff/状态效果，必须新增 `通用组件库-效果` 并按本规范的最小结构组织；各子模块只引用效果库，不得复制效果定义表。
13. **控制Sheet数量**：同一模块优先在同Sheet分区块，禁止为了拆表拆出大量碎片Sheet；确需拆分仅允许“模块名-上/模块名-下”。
14. **结构化输入控件（v1.6）**：有限集合输入、引用型输入、模拟路径切换输入，必须使用下拉列表或等价数据验证；候选值必须来自统一枚举区、组件库或引用表。
15. **模拟入口可操作性（v1.6）**：场景模拟表与综合验算台应设置独立输入区；若存在基准方案与逐行差异，推荐同时提供“默认方案 + 行级覆盖”。



## 12. 验收标准（工作簿是否合格）

工作簿被视为合格，当且仅当满足：

- 有《总览》Sheet，且能指引读者快速找到每个模块的“主表”和“旋钮”
- 每个 MDD 模块都有同名 Sheet
- 每个模块 Sheet 都能同时回答：
  - **怎么配**（主表字段与口径明确）
  - **为什么这样配**（概率/价值/基准/拐点至少一项解释且可验算）
