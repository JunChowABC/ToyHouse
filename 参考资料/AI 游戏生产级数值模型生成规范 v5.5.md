# AI 游戏生产级数值模型生成规范 v5.5

> 本规范用于指导 AI 根据 GDD、MDD、NDD、配置表、参考工作簿、测试数据和策划说明，生成可计算、可调参、可追踪、可验证、可导出的游戏数值工作簿。
>
> 数值工作簿的核心职责，是把玩家体验目标转化为可计算的成长目标、资源需求、系统价值、配置结果和验证结论。AI 输出不得停留在“系统配置表集合”，也不得以综合模拟代替系统模型。

| 默认交付目标 | P3；必须同时声明 C0-C3 可信度 |
| 默认文件格式 | `.xlsx` |

| 核心关键词 | 目标驱动、生命周期、成长反推、资源闭环、系统价值、真实公式链、结果归因、最低执行粒度、来源ID继承、主键治理、可调参、可验证 |

规范词含义：

- **必须**：不满足即不能通过对应交付等级验收。
- **不得**：触发即为一票否决或必须整改。
- **应当**：原则上必须满足，确有项目原因时须说明。
- **建议**：有助于模型维护和调参，但不作为硬性验收项。
- **可选**：根据项目类型、资料成熟度和用户目标决定。

# 1. 规范目标

AI 生成的数值工作簿必须同时满足以下目标。

## 1.1 可运行

核心结果必须由输入参数、配置数据和公式推导产生。

不得：

- 手填最终结果或校验结论；
- 用静态示例代替完整核心轴；
- 用文字说明替代应有的计算；
- 在展示区维护一套与计算区脱节的数据。

## 1.2 可调参

关键设计变量必须集中管理，并明确：

- 参数名称；
- 当前值；
- 单位；
- 有效范围；
- 影响范围；
- 来源等级；
- 调整风险。

修改关键参数后，相关系统结果、玩家状态、资源库存、目标达成时间、风险结论和导出配置必须自动更新。

## 1.3 可追踪

任何核心结果必须能够追溯至：

```text
体验或业务目标
→ 目标指标
→ 系统价值链
→ 计算公式
→ 中间变量
→ 输入参数或配置
→ 来源资料或假设
```

工作簿必须能够说明某项结果由哪些系统、参数和配置共同造成。

对于来源文档或现有配置中已经存在的对象、资源、内容和配置记录，还必须能够追溯：

```text
模型记录
→ 来源对象ID
→ 来源文档或配置表
→ 来源版本
→ 下游引用与程序导出ID
```

名称、排序、分类或展示位置发生变化，不得改变来源对象 ID。

## 1.4 可验证

模型必须能够验证：

- 生命周期目标是否可达；
- 成长节奏是否符合预期；
- 资源需求与投放是否闭合；
- 各系统的价值贡献是否合理；
- 是否存在资源断档、长期通胀或成长停滞；
- 是否存在单一系统垄断成长或唯一最优路径；
- 不同玩家分层的体验差距是否合理。

## 1.5 可归因

当模拟或校验发现异常时，模型必须能够定位到：

```text
异常结果
→ 受影响指标
→ 主要贡献系统
→ 关键参数或配置
→ 推荐调整方向
```

只显示“未达标”“资源不足”“成长过快”等结论，不提供原因定位，不视为完整验证。

## 1.6 可扩展

核心模型必须支持项目内容扩充。新增等级、阶段、对象、关卡、资源、渠道或活动时，不应要求重建主要计算链。

扩展必须依赖：

- 稳定主键；
- 参数化规则；
- 明确的数据粒度；
- 单一权威数据源；
- 可复制且一致的公式结构。

## 1.7 可导出

生产级模型必须提供与程序消费粒度一致的配置导出区域。

导出数据必须：

- 一行一条可执行记录；
- 使用稳定且唯一的主键或复合键；
- 引用权威计算结果；
- 不存在公式错误和外部断链；
- 不依赖颜色、合并单元格或人工理解表达数据关系。

# 2. 核心建模原则

## 2.1 目标驱动原则（最高优先级）

所有生产级数值模型必须遵循：

```text
玩家体验与业务目标
→ 生命周期目标
→ 阶段成长目标
→ 系统价值贡献
→ 资源与能力需求
→ 专项模型
→ 配置结果
→ 综合验证
```

不得按照 GDD 或 MDD 章节顺序机械建立 Sheet，再把独立配置表拼接为所谓“数值母表”。

## 2.2 玩家状态优先原则

全局模型首先描述玩家或核心对象在关键时间点、阶段或内容节点应处于什么状态。

状态应根据项目实际选择，至少包含以下适用维度：

- 进度；
- 能力；
- 资产或内容拥有情况；
- 资源库存；
- 核心系统参与状态；
- 可执行目标；
- 风险或卡点状态。

## 2.3 总需求优先原则

对于存在成长成本、资源消耗或内容门槛的项目，必须先计算目标状态对应的总需求，再反推周期投放和渠道分配。

不得先随意设计各渠道产出，再观察结果是否足够。

## 2.4 系统价值链原则

每个核心系统必须建立完整价值链：

```text
系统输入
→ 系统规则或行为
→ 系统直接输出
→ 玩家价值变化
→ 生命周期或阶段目标影响
```

系统价值可以表现为：

- 能力提升；
- 资源产出；
- 消耗降低；
- 效率提升；
- 内容解锁；
- 风险降低；
- 策略空间扩展；
- 其他可计算的体验或业务价值。

仅有成本、等级、奖励或属性配置，不构成完整系统模型。

## 2.5 价值转换原则

系统直接输出必须继续转换为可讨论的玩家结果。

例如，模型不应停留在“数值提升 X%”，还应尽可能计算其对以下指标的影响：

- 单位周期产出；
- 目标达成时间；
- 内容推进速度；
- 成功率或容错；
- 资源缺口；
- 综合能力或效率；
- 其他项目核心 KPI。

若某项输出无法直接量化，应明确其代理指标、适用边界和待验证方式。

## 2.6 单一数据源原则

同一字段、参数、规则或配置只能有一个权威维护位置。

其他 Sheet 必须通过公式、稳定 ID 或明确引用关系获得，不得复制并独立维护。

## 2.7 综合模拟边界原则

玩家路径、长期沙盘、经营模拟、战斗仿真或蒙特卡洛模拟属于集成验证层。

综合模拟可以：

- 组合行为频率和玩家分层；
- 调用各专项模型；
- 累计状态；
- 输出体验结果；
- 比较不同场景。

综合模拟不得：

- 成为多个核心系统的唯一公式载体；
- 重新定义专项模型规则；
- 复制一套独立配置；
- 因自身能够运行而替代系统覆盖、价值链和配置导出。

## 2.8 结果归因原则

所有跨系统结果必须保留贡献来源。

当一个结果由多个系统共同影响时，必须能够计算或说明：

- 各系统的贡献值；
- 各系统的贡献比例；
- 主要正向和负向来源；
- 参数变化对最终结果的传导路径。

## 2.9 颗粒度保持原则（强制）

模型颗粒度必须由以下因素共同决定：

- 程序实际消费粒度；
- 策划实际调参粒度；
- 模型计算与汇总粒度；
- 综合模拟引用粒度；
- 验收与问题定位粒度；
- 数据规模与性能边界。

目标驱动、系统价值闭环、参数化复用和可信度控制，不得成为降低核心配置颗粒度的理由。

强制要求：

1. 需要逐等级、逐时间单位、逐关卡、逐配置 ID、逐有效状态或逐对象展开的核心数据，必须按最低执行粒度完整展开。
2. 公共规则或公共曲线可以集中维护，但不得替代具有独立输入、成本、收益、状态、解锁条件或导出记录的实例明细。
3. 资料可信度较低时，应生成全量可替换结构，并将缺失值集中标记为 B/T 类假设；不得通过减少记录数、只保留代表对象或缩短核心轴规避假设。
4. 不得使用少量阶段点、代表行或样本对象冒充完整生产模型。
5. 不得生成业务上无效的笛卡尔积；未展开的组合必须有明确规则证明其无独立配置或计算价值。

## 2.10 四条真实公式链强制落地原则（强制）

P3 模型不得只在说明、蓝图或流程图中描述价值关系。以下四条公式链必须在工作簿中形成真实单元格引用、计算结果和下游联动。

### 公式链 A：专项系统状态到生命周期结果

```text
专项系统当前状态
→ 核心玩法或业务结果
→ 单位周期资源/能力变化
→ 累计状态
→ 生命周期实际达成时间
```

要求：

- 专项系统当前状态必须引用权威配置和实际累计状态；
- 核心玩法结果不得使用与专项系统脱节的替代曲线；
- 单位周期变化和累计状态必须由公式计算；
- 生命周期达成时间必须由累计状态达到目标条件的最早时间计算；
- 任一专项参数变化后，达成时间必须联动变化。

### 公式链 B：渠道实际配置到真实投放缺口

```text
渠道实际配置
→ 单次产出 × 可用次数 × 参与率 × 完成率 × 开放周期
→ 实际周期投放
→ 目标需求与实际消耗比较
→ 缺口、溢出与来源归因
```

要求：

- 实际投放必须从渠道配置正算，不得由目标需求按比例反向分完；
- 渠道产出、次数、参与率、完成率和开放周期必须有独立来源；
- 目标配额与实际投放必须分开管理；
- 缺口必须设置合理数值容差，禁止将浮点误差判定为业务缺口；
- 关闭或调整任一渠道后，缺口和库存必须自动变化。

### 公式链 C：多门槛条件到实际达成日

```text
进度条件 + 资源条件 + 其他适用成长门槛
→ 全部门槛满足判定
→ 实际升级/解锁/成型日
→ 与目标节点的偏差
```

要求：

- 实际达成不得仅使用单一经验、积分或时间条件；
- 所有项目已定义且会阻塞成长的条件必须进入判定；
- 资源条件必须使用扣除实际消耗后的可用库存；
- 实际达成日必须取全部适用条件首次同时满足的时间；
- 未计算或超出模拟范围时必须返回明确状态，不得用 0 代替。

### 公式链 D：参数情景到敏感性结果与归因

```text
低情景 / 基准情景 / 高情景参数
→ 分别重新计算专项模型与综合模拟
→ 输出结果差值、变化率和弹性
→ 定位主要传导系统、风险与调整入口
```

要求：

- 低、基准、高情景必须分别进入真实模型计算；
- 不得只计算扰动后的参数值而继续引用同一个基准结果；
- 必须输出各情景结果、相对基准差值、变化率和敏感度；
- 必须说明参数通过哪些系统传导到目标；
- 情景切换后，校验、玩家路径和配置导出必须按适用范围联动。

若某条公式链确实不适用于本次交付，必须在生成前置报告中说明不适用原因和替代验收方式。全项目母表、经济投放模型和包含长期成长的专项模型，原则上不得将四条公式链全部标记为不适用。

## 2.11 来源 ID 继承原则（强制）

项目资料中已经定义的对象 ID、资源 ID、配置 ID、内容 ID 或其他稳定标识，属于项目权威数据，不得由 AI 重新编号、替换或另建一套并行 ID。

强制规则：

1. **已有 ID 必须原样继承**
   - 必须保留原值、字符大小写、前缀、分隔符和前导零；
   - ID 列默认按文本处理，禁止因 Excel 数值格式导致前导零丢失；
   - 不得按工作簿行号、分类顺序、生成顺序或 AI 自定规则重新编号。

2. **来源 ID 与模型记录 ID 必须分离**
   - 来源对象 ID 用于标识项目中的原始对象；
   - 模型记录 ID 用于标识该对象在等级、阶段、状态、渠道等维度展开后的具体记录；
   - 新增模型记录 ID 时，必须保留独立的 `来源对象ID` 字段，不得用模型记录 ID 覆盖来源 ID。

3. **程序导出 ID 必须有明确来源**
   - 若程序继续使用来源 ID，导出表必须原样输出；
   - 若程序配置要求复合键或独立记录 ID，必须根据已确认规则生成，并同时保留来源对象 ID；
   - 未经用户或项目规则授权，AI 不得自行设计正式程序 ID 规则。

4. **资料中不存在的对象不得擅自分配正式 ID**
   - 可使用明确标记的临时 ID、占位 ID 或“待分配”状态；
   - 临时 ID 必须集中管理，并标记为不可正式导出；
   - 只有项目已提供 ID 分配规则且用户授权时，AI 才可按规则生成新 ID。

5. **来源冲突不得静默处理**
   - 同一对象在多个资料中出现不同 ID，或同一 ID 指向不同对象时，必须列入冲突清单；
   - 未确认前不得自行选择、合并、覆盖或重编号；
   - 冲突记录不得进入 P3 正式导出。

6. **所有跨表关联必须使用稳定 ID**
   - 禁止依赖对象名称、行号、颜色、排序或单元格位置建立关联；
   - 名称仅用于展示，不得作为唯一关联键；
   - 外键必须检查来源 ID 是否存在及引用是否完整。

# 3. 数值模型四层架构

P3 及以上模型必须按照“目标层—模型层—价值层—配置层”组织。四层可以位于不同 Sheet，也可以在同一 Sheet 中分区，但职责必须清晰。

## 3.1 目标层

回答：

> 为什么需要这套数值，以及希望达到什么结果？

至少包含：

- 生命周期或阶段目标；
- 核心体验指标；
- 业务边界；
- 目标区间；
- 允许偏差；
- 高风险点。

## 3.2 模型层

回答：

> 数值如何计算？

至少包含：

- 输入参数；
- 核心规则；
- 中间变量；
- 正算；
- 累计；
- 反算或目标校准；
- 边界处理。

## 3.3 价值层

回答：

> 计算结果如何改变玩家状态和整体目标？

至少包含：

- 系统直接输出；
- 玩家价值转换；
- 目标指标影响；
- 系统贡献值或贡献比例；
- 回报周期或达成时间变化；
- 跨系统传导关系。

## 3.4 配置层

回答：

> 最终如何落表并提供程序使用？

至少包含：

- 配置粒度；
- 稳定主键；
- 字段和单位；
- 可编辑列与计算列；
- 导出规则；
- 关联键；
- 版本信息。

# 4. 数值模型类型判定与最低标准

AI 在生成前必须先判断交付物类型。禁止默认生成覆盖所有系统的“万能数值母表”。

## 4.1 模型类型

| 模型类型 | 核心职责 | 主要回答问题 |
| --- | --- | --- |
| 全项目数值母表 | 管理整体生命周期、成长、经济与系统价值关系 | 项目长期节奏如何形成？ |
| 经济投放模型 | 管理资源总需求、来源、消耗、库存和缺口 | 资源是否能够支撑目标成长？ |
| 属性或能力成长模型 | 管理能力来源、成长曲线和最终强度 | 核心能力为什么增长？ |
| 单系统专项模型 | 深入设计一个系统的目标、规则、价值和配置 | 该系统参数如何设计与验证？ |
| 综合模拟模型 | 验证多个系统联动后的长期结果 | 整体体验是否符合目标？ |
| 配置导出模型 | 输出程序可消费的扁平配置 | 程序最终读取什么？ |
| 数值分析报告 | 分析问题、缺口和风险，不承担完整调参 | 当前主要问题是什么？ |

## 4.2 类型选择规则

- 用户要求“完整数值模型”时，默认规划为：全项目数值母表 + 必要专项模型 + 综合验证层。
- 用户指定某类参考工作簿时，必须优先匹配参考工作簿的实际职责和操作方式。
- 用户只要求单一系统时，只生成满足该系统目标的专项模型及必要的上下游引用，不得无依据扩展成全项目母表。
- 用户需求不明确时，必须在生成前置报告中给出判型结论和不包含范围。

## 4.3 全项目数值母表最低标准

全项目数值母表不是所有系统配置的集合，必须至少具备：

1. **生命周期或阶段轴**：关键时间、进度或版本节点的玩家目标状态。
2. **成长轴**：能力、进度、内容解锁和成长速度。
3. **资源轴**：产出、消耗、库存、净变化和缺口。
4. **系统价值轴**：各系统的输入、输出、价值类型、贡献指标和目标影响。
5. **玩家分层轴**：不同活跃、行为或商业化路径的结果差异。
6. **目标校准层**：目标值、实际值、偏差、原因和调整建议。

以下形式不属于全项目数值母表：

```text
系统 A 配置
+ 系统 B 配置
+ 系统 C 配置
+ 汇总页
```

若无法说明玩家整体状态和系统间价值关系，只能视为系统配置集合。

## 4.4 经济投放模型最低标准

经济投放模型必须建立：

```text
成长或消费目标
→ 资源总需求
→ 周期需求
→ 渠道投放
→ 周期产出
→ 消耗与库存
→ 缺口或溢出
→ 调整方案
```

至少包含：

- 资源价值或明确的不可换算说明；
- 目标阶段的总需求；
- 资源来源和消耗去向；
- 周期产出与周期消耗；
- 库存变化；
- 需求与投放偏差；
- 关键资源的达成时间；
- 资源投放如何推动系统成长和阶段目标。

仅包含资源配置、奖励配置、价格配置或商品列表，不属于经济投放模型。

## 4.5 属性或能力成长模型最低标准

属性或能力成长模型必须建立：

```text
基础能力
+ 固定成长
+ 比例成长
+ 系统加成
+ 条件修正
= 最终能力
→ 玩法结果变化
→ 阶段目标影响
```

至少包含：

- 能力来源拆解；
- 各来源贡献值；
- 各来源贡献比例；
- 最终能力计算；
- 不同阶段的成长状态；
- 能力变化对成功率、效率、产出、推进速度或其他核心结果的影响；
- 异常跳跃、单来源垄断和边际收益检查。

直接配置“等级—最终能力”而不解释来源和价值转换，不属于完整成长模型。

## 4.6 单系统专项模型最低标准

每个核心专项模型必须同时具备：

| 层级 | 必须回答的问题 |
| --- | --- |
| 目标层 | 该系统要解决什么体验或业务问题？ |
| 模型层 | 输入、规则和输出如何计算？ |
| 价值层 | 输出如何改变玩家状态和整体目标？ |
| 配置层 | 如何按可执行粒度配置和导出？ |
| 验证层 | 如何判断该系统设计合理？ |

只有配置表和少量公式，不构成完整专项模型。

## 4.7 综合模拟模型最低标准

综合模拟模型必须：

- 引用专项模型和公共参数；
- 按明确玩家分层或场景输入运行；
- 展开足够的时间、内容或行为周期；
- 输出状态变化、目标达成、资源变化和风险；
- 对异常结果给出系统和参数归因。

综合模拟不得成为多个核心系统的唯一实现位置。

# 5. 交付等级与可信度

## 5.1 完整度等级

| 等级 | 名称 | 主要交付 |
| --- | --- | --- |
| P0 | 数值分析 | 系统关系、问题、风险和缺失项 |
| P1 | 模型骨架 | 输入结构、公式原型和少量示例 |
| P2 | 可运行模型 | 完整核心轴、主要计算链和基础校验 |
| P3 | 生产级模型 | 全量核心配置、价值闭环、综合验证、敏感性和导出 |
| P4 | 运营级模型 | 多版本、多活动、商业化分层、数据回归和长期运营模拟 |

P3 必须至少满足：

- 目标层完整；
- 核心专项模型具备目标、模型、价值、配置和验证；
- 系统价值链可追踪；
- 生命周期或适用周期可验证；
- 资源、能力或概率模型按项目需要完整闭环；
- 结果异常可归因；
- 关键参数可做敏感性分析；
- 存在可用配置导出。

## 5.2 可信度等级

| 等级 | 名称 | 资料与校准状态 |
| --- | --- | --- |
| C0 | 假设驱动 | 核心结果主要依赖基准或待调假设 |
| C1 | 文档校准 | 核心目标由项目文档或策划确认 |
| C2 | 测试校准 | 已使用试玩、仿真或 QA 数据校准 |
| C3 | 线上验证 | 已使用稳定线上数据完成回归 |

模型状态必须写成 `P等级/C等级（状态说明）`。

公式无错误、工作簿可打开或模拟可运行，不代表已验证。

# 6. 生成前强制流程

正式生成工作簿前，AI 必须完成以下流程。

## 6.1 资料盘点

| 类型 | 应提取内容 |
| --- | --- |
| GDD | 核心循环、目标体验、系统范围、商业目标 |
| MDD | 系统规则、输入输出、状态、配置边界 |
| NDD或数值说明 | 目标曲线、价值口径、公式和参数 |
| 配置表 | 主键、字段、粒度、现有数值 |
| 参考工作簿 | 模型职责、主轴、公式链、操作方式和深度 |
| 测试或线上数据 | 实际速度、分布、偏差和校准依据 |

每项资料必须记录版本、用途、来源等级和可用状态。

### 6.1.1 ID 权威源盘点（强制）

生成前必须识别并登记所有已有 ID 体系。

| 对象或配置类型 | 来源文档/配置表 | ID字段名 | ID示例 | 数据类型 | 是否包含前导零 | 权威状态 | 冲突情况 | 下游用途 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

权威来源的选择顺序必须在前置报告中明确。默认应优先采用：

1. 用户明确指定的 ID 来源；
2. 已上线或程序正在消费的正式配置；
3. 已确认的 MDD 配置与对象定义；
4. 已确认的 NDD、GDD 或其他设计资料；
5. 临时录入或待分配清单。

当不同资料的 ID 不一致时，必须由用户或项目规则确定权威来源，AI 不得自行推断。

## 6.2 参考模型可用性检查

用户指定参考工作簿时，必须实际读取并至少检查：

- Sheet 清单与职责；
- 代表性输入区；
- 代表性公式和中间变量；
- 汇总、校验和导出方式；
- 主轴、记录粒度和规模；
- 调参入口和视觉操作方式。

未实际读取，不得声明已对齐参考模型。

## 6.3 交付物判型

必须明确：

- 主要模型类型；
- 辅助模型类型；
- 不包含内容；
- 目标 P 等级；
- 预计 C 等级；
- 模型的核心问题。

## 6.4 生命周期与目标定义

全项目模型或长期专项模型必须先定义：

- 关键时间、阶段或内容节点；
- 每个节点的目标状态；
- 核心 KPI；
- 允许偏差；
- 不可由 AI 假设替代的核心缺失项。

## 6.5 系统价值覆盖矩阵

生成前必须建立：

| 系统或模块 | 来源 | 来源对象ID字段 | 输入 | 直接输出 | 玩家价值 | 目标指标 | 目标模型位置 | 覆盖状态 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

覆盖状态：

- 完整建模；
- 静态配置；
- 参数化公共规则；
- 仅模拟引用；
- 不适用；
- 待补资料。

核心系统不得处于“仅模拟引用”状态。

## 6.6 核心数值链

每条核心数值链必须写成：

```text
目标
→ 输入
→ 转换规则
→ 中间变量
→ 系统输出
→ 玩家价值
→ 累计状态
→ 目标校验
→ 下游系统或配置
```

生成前必须额外建立《四条真实公式链覆盖表》：

| 公式链 | 是否适用 | 权威输入位置 | 核心计算位置 | 累计/情景位置 | 目标或缺口输出 | 下游联动 | 验收方式 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A 专项状态→生命周期 | 是/否 |  |  |  |  |  |  |
| B 渠道配置→投放缺口 | 是/否 |  |  |  |  |  |  |
| C 多门槛→实际达成日 | 是/否 |  |  |  |  |  |  |
| D 参数情景→重算归因 | 是/否 |  |  |  |  |  |  |

“已在说明中描述”“已在模拟中大致体现”不能视为覆盖。覆盖状态必须有可定位的 Sheet、区块、公式范围或命名单元格作为证据。

## 6.7 工作簿蓝图

蓝图至少包含：

- Sheet 名称和职责；
- 每个 Sheet 的记录粒度；
- 主键或关联键；
- 来源对象 ID、模型记录 ID 和程序导出 ID 的字段划分；
- ID 权威来源、继承规则、复合键规则和临时 ID 处理方式；
- 输入、计算、价值、校验和导出位置；
- 系统价值链映射；
- 综合模拟如何引用专项模型；
- 预计行列规模和公式区域；
- 核心假设和可信度上限。

用户必须确认蓝图，或明确免确认后继续。

## 6.8 主轴与规模预算

必须定义适用主轴：

- 时间或阶段轴；
- 成长轴；
- 内容轴；
- 对象轴；
- 玩家分层轴；
- 资源或能力轴；
- 配置主键。

同时估算：

- Sheet 数量；
- 核心明细规模；
- 公式规模；
- 模拟周期；
- 导出记录数量；
- 高敏感假设数量。

## 6.9 颗粒度预算与展开计划（强制）

生成前必须逐个核心模型声明最低执行粒度、理论记录数和计划记录数。

| 模型或配置块 | 最低执行粒度 | 理论记录数 | 计划记录数 | 是否全量展开 | 公共规则位置 | 实例明细位置 | 未展开原因 |
| --- | --- | ---: | ---: | --- | --- | --- | --- |

最低执行粒度必须说明每行代表什么，例如：

- 每等级一条；
- 每时间单位一条；
- 每关卡或内容 ID 一条；
- 每配置 ID 一条；
- 每对象与有效状态组合一条；
- 每资源、渠道与阶段组合一条；
- 每属性来源、作用对象与状态组合一条。

硬规则：

1. 计划记录数低于理论记录数时，必须列出未展开维度及原因。
2. 若未展开维度会产生独立成本、收益、状态、条件、结果或导出记录，则不得省略。
3. 代表样本仅允许用于 P1、公式验证或用户明确要求的示例版。
4. C0/C1 只限制结论可信度，不自动降低核心轴长度和实例展开范围。
5. 生成后必须将实际记录数与本表回填对比。

# 7. 玩家生命周期与阶段目标模型

## 7.1 模型定位

生命周期模型用于定义玩家或核心对象在关键节点应达到的状态，是全项目模型和长期专项模型的顶层目标。

## 7.2 阶段划分

阶段不得固定套用统一天数。应根据项目实际使用：

- 时间节点；
- 等级段；
- 章节段；
- 内容周期；
- 赛季阶段；
- 其他可判定进度节点。

推荐结构：

| 节点 | 阶段 | 目标进度 | 目标能力 | 资源状态 | 核心行为 | 风险边界 |
| --- | --- | --- | --- | --- | --- | --- |

## 7.3 生命周期校验

必须能够回答：

- 目标节点是否可达；
- 实际达成时间与目标差异；
- 哪些系统推动该节点；
- 哪些资源或能力形成限制；
- 是否存在阶段断档或长期无目标；
- 调整哪个参数可以改变结果。

---

# 8. 成长目标反推模型

## 8.1 反推原则

成长设计必须优先从目标状态和目标时间反推需求、速度和配置。

```text
目标状态
→ 总成长需求
→ 允许周期
→ 单位周期所需成长
→ 各系统应承担的贡献
→ 具体成本、收益与投放
```

## 8.2 目标校准结构

| 目标节点 | 目标指标 | 目标值 | 模型实际值 | 偏差 | 偏差率 | 主要原因 | 调整入口 |
| --- | --- | ---: | ---: | ---: | ---: | --- | --- |

目标校准不得只给出“通过/不通过”，必须保留原因和调整入口。

---

# 9. 系统价值模型（强制）

## 9.1 模型定位

系统价值模型连接专项配置与玩家生命周期，回答每个系统为什么存在、产生什么价值、贡献多少以及如何影响整体目标。

## 9.2 系统价值链

每个核心系统必须建立：

```text
输入资源或条件
→ 核心规则或行为
→ 直接数值输出
→ 玩家价值转换
→ 目标指标变化
→ 生命周期或阶段贡献
```

## 9.3 系统价值矩阵

| 系统或模块 | 输入 | 直接输出 | 价值类型 | 影响指标 | 贡献值 | 贡献比例 | 生效阶段 | 备注 |
| --- | --- | --- | --- | --- | ---: | ---: | --- | --- |

## 9.4 贡献计算

当多个系统共同作用于同一指标时，应计算：

```text
单系统贡献值 = 启用该系统后的结果 - 基准结果
单系统贡献比例 = 单系统贡献值 / 全部有效贡献值
```

若系统存在非线性、互相放大或互斥关系，应：

- 明确贡献计算口径；
- 标注是否为边际贡献、独立贡献或组合贡献；
- 避免简单相加造成重复统计；
- 对组合效应单列中间量或校验区。

## 9.5 系统价值校验

必须检查：

- 是否存在投入明显高于输出的系统；
- 是否存在长期没有有效价值的系统；
- 是否存在单系统贡献过高；
- 是否存在多个系统重复提供同一价值；
- 是否存在价值只能在模拟中看到、专项模型无法解释；
- 调整系统参数后，价值指标和目标状态是否联动变化。

## 9.6 专项系统到生命周期公式链（强制）

每个会影响长期成长、资源、能力或进度的核心专项系统，必须建立以下真实计算链：

```text
专项系统当前状态
→ 核心玩法或业务结果
→ 单位周期资源/能力变化
→ 累计状态
→ 生命周期实际达成时间
```

验收要求：

- 专项系统当前状态必须来自该专项模型的权威明细，不得在玩家路径中重写；
- 核心玩法结果必须消费专项模型输出，不得使用仅随总等级变化的替代倍率；
- 单位周期变化必须可区分该系统启用前后结果；
- 累计状态必须体现真实消耗、获得和状态变化；
- 实际达成时间必须由目标首次满足的位置计算；
- 模型必须能够回答该系统对目标达成时间提前或延后多少。

若某专项系统只提供静态展示、无数值影响，可以标记为静态配置；不得将其伪装成完整专项模型。

# 10. 资源总需求与投放模型

## 10.1 总需求

总需求必须从目标状态反推：

| 目标节点 | 系统或用途 | 资源 | 总需求 | 周期 | 单位周期需求 | 来源 |
| --- | --- | --- | ---: | ---: | ---: | --- |

必须明确每行是：

- 截止目标节点的累计需求；
- 当前阶段新增需求；
- 单对象需求；
- 多对象总需求；
- 或其他项目适用口径。

同一字段在不同记录中不得混用不同语义。

## 10.2 投放与消耗

| 资源 | 来源或去向 | 类型 | 单次量 | 可用次数 | 参与率 | 完成率 | 开放周期 | 实际周期总量 | 影响阶段 | 价值 |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | --- | ---: |

类型至少区分：

- 产出；
- 消耗；
- 回收；
- 转换；
- 商业化补充；
- 其他项目适用类型。

实际周期投放必须按渠道正算：

```text
实际周期投放
= 单次产出
× 可用次数
× 参与率
× 完成率
× 开放周期
```

目标投放配额可以用于规划，但不得直接代替实际投放。禁止使用“总需求 × 固定比例并归一化至 100%”的方式，让实际投放天然等于目标需求。

阶段投放不得简单使用全周期总量平均拆分。必须按实际开放天数、渠道配置、玩家参与和完成情况计算，或在逐日模型中累计。

## 10.3 库存与缺口

必须计算：

```text
周期净流入 = 实际周期投放 - 实际周期消耗
期末库存 = 期初库存 + 周期净流入
实际可用量 = 期初库存 + 实际周期投放 - 已发生消耗
资源缺口 = 目标需求 - 实际可用量
```

输出至少包含：

| 资源 | 目标需求 | 目标配额 | 实际投放 | 实际消耗 | 期末库存 | 缺口或溢出 | 状态 | 主要来源/原因 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- | --- |

缺口状态必须设置数值容差。绝对缺口不超过容差时，应判定为“覆盖”或“平衡”，不得将浮点误差标记为业务缺口。

## 10.4 经济价值闭环

经济模型必须继续说明：

```text
资源投放
→ 支撑哪些系统行为
→ 产生哪些玩家价值
→ 推动哪些目标指标
→ 是否形成下一阶段需求
```

## 10.5 渠道实际配置到缺口公式链（强制）

必须建立：

```text
渠道实际配置
→ 单次产出 × 可用次数 × 参与率 × 完成率 × 开放周期
→ 实际周期投放
→ 目标需求与实际消耗比较
→ 缺口、溢出与来源归因
```

模型至少支持以下验证：

- 某渠道关闭；
- 某渠道次数变化；
- 玩家参与率或完成率变化；
- 开放周期变化；
- 单次产出变化。

以上变化必须真实影响投放、库存、缺口、目标达成时间和风险结论。

---

# 11. 专项模型生成规范

## 11.1 专项模型标准结构

所有核心专项模型必须包含：

1. **目标区**：体验目标、业务目标、目标指标和边界。
2. **输入区**：参数、配置、外部引用和假设。
3. **计算区**：核心规则、中间变量、正算、累计和反算。
4. **价值区**：直接输出、玩家价值、目标贡献和回报指标。
5. **配置区**：最低可执行粒度的配置明细。
6. **验证区**：目标偏差、边界、风险和自检结论。
7. **导出区**：程序可用记录或对导出 Sheet 的明确引用。

## 11.2 专项模型必须回答

- 为什么设计这套数值；
- 输入和约束是什么；
- 数值如何计算；
- 结果如何改变玩家状态；
- 对整体目标贡献多少；
- 如何配置；
- 如何验证；
- 出现异常时调整什么。

## 11.3 专项模型禁止形式

以下形式不属于完整专项模型：

- 只有等级、成本、奖励或属性明细；
- 只有配置和几个公式；
- 只有模拟结果，没有专项计算链；
- 只有最终输出，没有中间量和来源；
- 只有“系统有用”的文字说明，没有价值计算或代理指标。

---

# 12. 经济模型规范

## 12.1 模型目标

经济模型必须建立资源价值、总需求、来源、消耗、库存、缺口、达成时间和系统价值之间的闭环。

## 12.2 资源价值

核心资源必须具有：

- 单位价值；
- 价值锚点；
- 换算关系；
- 不可直接换算时的代理评价；
- 来源等级；
- 适用边界。

## 12.3 经济健康指标

根据项目选择适用指标：

- 周期净流入；
- 库存变化；
- 资源缺口；
- 达成时间；
- 资源消耗率；
- 通胀或通缩风险；
- 关键消费间隔；
- 投放渠道占比；
- 免费与商业化路径差异。

## 12.4 经济结果归因

当出现缺口或溢出时，必须定位：

- 需求增长来源；
- 投放不足或过量渠道；
- 主要消耗系统；
- 受影响阶段；
- 高敏感参数；
- 建议调整方向。

# 13. 成长模型规范

## 13.1 成长链

成长模型必须建立：

```text
成长目标
→ 成长成本
→ 成长结果
→ 边际收益
→ 玩家价值
→ 目标达成时间
```

## 13.2 成本与收益

必须明确：

- 成本曲线；
- 累计成本；
- 收益曲线；
- 累计收益；
- 单位成本收益；
- 边际收益；
- 回本或达成周期；
- 阶段拐点。

## 13.3 成长价值转换

成长结果必须继续转换到项目核心指标。

通用结构：

```text
成长数值变化
→ 能力、效率或资源变化
→ 玩法结果变化
→ 推进或达成时间变化
```

不得只计算“成长后增加多少”，而不说明其实际价值。

## 13.4 多门槛实际达成日（强制）

存在多个成长限制时，必须建立：

```text
进度条件 + 资源条件 + 其他适用成长门槛
→ 全部门槛满足判定
→ 实际升级/解锁/成型日
→ 与目标节点的偏差
```

要求：

1. 进度条件可以是经验、积分、章节、任务、时间或项目定义的其他进度口径。
2. 资源条件必须使用扣除真实消耗后的可用库存，不得使用累计总收入代替库存。
3. 其他适用门槛包括项目已定义且会阻塞成长的能力、评分、对象数量、前置状态、内容条件等。
4. 实际达成日必须取全部适用门槛首次同时满足的时间。
5. 未满足、超出模拟范围或资料未覆盖时，应返回明确文本状态，不得返回 0 冒充结果。
6. 生命周期校准必须读取实际达成日，不得仅读取单一进度条件的理论达成日。

## 13.5 成长轴颗粒度

存在逐级、逐阶段、逐突破或其他离散成长节点时，必须按每个有效节点展开。

阶段汇总、关键节点展示或公共曲线可以存在，但只能建立在完整底层明细之上，不能替代实际成长记录。

---

# 14. 属性或能力模型规范

## 14.1 来源拆解

最终能力应拆分为：

```text
基础值
+ 固定成长
+ 比例成长
+ 系统加成
+ 条件修正
= 最终能力
```

项目不存在传统属性时，可替换为效率、产能、评分、队伍能力、解题能力或其他统一能力指标。

## 14.2 能力贡献

必须记录：

| 来源 | 基础贡献 | 固定贡献 | 比例贡献 | 特殊修正 | 最终贡献 | 贡献比例 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |

## 14.3 能力价值转换

必须尽可能计算：

```text
最终能力
→ 核心玩法结果
→ 成功率、效率、产出或推进速度
→ 目标节点影响
```

若无法直接计算，应使用明确代理指标，并说明验证计划。

---

# 15. 概率模型规范

概率模型必须包含：

```text
概率或权重
→ 期望
→ 波动
→ 保底或补偿
→ 成本
→ 资源与玩家价值影响
```

至少验证：

- 概率和；
- 单次期望；
- 周期期望；
- 保底后的真实期望；
- 重复结果的处理价值；
- 极端路径；
- 对资源投放和目标达成的影响。

复杂概率不得用单次随机结果证明稳定性，也不得简单使用 `1/概率` 替代存在保底或状态变化的真实期望。

---

# 16. 玩家路径与综合模拟规范

## 16.1 模型定位

玩家路径用于验证既有专项模型，不得定义专项规则。

## 16.2 玩家分层

玩家分层应根据项目实际定义，可基于：

- 活跃度；
- 完成率；
- 行为偏好；
- 策略选择；
- 广告使用；
- 付费程度；
- 其他会影响数值结果的特征。

不得强制所有项目使用同一套固定分层。

## 16.3 模拟结构

模拟必须包含：

```text
场景或玩家输入
→ 引用专项模型
→ 行为序列
→ 当期产出与实际消耗
→ 多维状态累计
→ 多门槛达成判定
→ 目标结果
→ 风险检查
→ 原因归因
```

模拟至少按项目适用范围追踪：

- 主要成长状态；
- 核心资源可用库存；
- 关键专项系统状态；
- 主要能力、效率或评分；
- 内容或功能解锁状态；
- 实际消耗和资源竞争；
- 目标首次达成时间。

累计总收入、累计总经验或单一等级曲线，不能替代可用库存和多系统状态。

## 16.4 模拟结果归因（强制）

发现异常时必须输出：

| 异常节点 | 异常指标 | 目标值 | 实际值 | 主要贡献系统 | 关键参数 | 影响程度 | 建议调整 |
| --- | --- | ---: | ---: | --- | --- | --- | --- |

模拟结果必须能返回专项模型定位具体参数，不得只给出“增加投放”“降低成本”等模糊建议。

## 16.5 模拟范围边界

生命周期目标必须落在模拟周期内。

当目标节点超出模拟范围时，必须：

- 扩展模拟周期；
- 或返回“超出模拟范围”。

不得返回 0、空白数值或默认等级并将其纳入偏差计算。

---

# 17. 颗粒度保持规范（强制）

## 17.1 基本定位

颗粒度保持规范用于保证工作簿在目标驱动和系统价值闭环正确的同时，仍保留真实调参、计算、模拟和配置导出所需的底层明细。

模型架构正确，不代表颗粒度可以降低；颗粒度完整，也不能替代目标与价值闭环。两者必须同时通过。

## 17.2 最低执行粒度

每个核心模型必须声明最低执行粒度。最低执行粒度由以下口径共同决定：

- 程序消费口径；
- 策划调参口径；
- 数值推导口径；
- 综合模拟引用口径；
- 验收和归因口径。

常见但非固定的执行粒度包括：

- 每等级一条；
- 每时间单位一条；
- 每关卡、章节或内容 ID 一条；
- 每配置 ID 一条；
- 每对象与有效状态组合一条；
- 每资源、来源、去向与阶段组合一条；
- 每属性来源、作用对象与生效状态组合一条。

不得以固定模板替代项目真实粒度判断。

## 17.3 公共规则与实例明细

公共规则、公共参数和公共曲线用于复用计算口径。

当实例在以下任一方面产生独立结果时，必须生成实例明细：

- 输入值；
- 成本；
- 收益；
- 状态；
- 解锁条件；
- 作用对象；
- 生效阶段；
- 下游配置记录；
- 模拟或汇总结果。

公共规则不能代替实例配置。实例明细应通过稳定 ID 引用公共规则，避免复制公式逻辑。

## 17.4 缺失资料处理

资料不足时必须区分：

1. **规则明确、数值缺失**：按完整粒度展开，数值使用集中管理的 B/T 类参数。
2. **对象清单明确、配置缺失**：按对象完整展开，标记来源等级和替换入口。
3. **理论规模已知、对象清单缺失**：建立全量录入模板和生成规则，明确理论记录数与待补范围。
4. **核心维度完全未知**：降低交付等级并标记阻塞，不得用少量样本冒充完整模型。

可信度等级只描述数据和结论可信程度，不直接决定记录数量。

## 17.5 代表样本使用限制

代表样本只允许用于：

- P1 模型骨架；
- 公式验证；
- 结构预览；
- 用户明确要求的示例版。

使用代表样本时必须同时标记：

- 当前为样本级而非全量模型；
- 理论完整记录数；
- 已覆盖和未覆盖维度；
- 不可用于正式配置导出；
- 不可判定为 P3。

## 17.6 颗粒度覆盖矩阵

工作簿蓝图和生成后验收均必须包含：

| 模型或配置块 | 最低执行粒度 | 理论记录数 | 计划/实际记录数 | 全量展开状态 | 未展开维度 | 公共规则位置 | 实例明细位置 | 导出记录数 | 结论 |
| --- | --- | ---: | ---: | --- | --- | --- | --- | ---: | --- |

## 17.7 颗粒度验收

必须检查：

- 核心等级、时间、内容和配置轴是否完整；
- 计划记录数与实际记录数是否一致；
- 实例明细是否被公共规则错误替代；
- 是否存在样本级结构被描述为完整模型；
- 下游汇总是否覆盖全部有效记录；
- 导出记录数是否与程序消费粒度一致；
- 维度展开后是否发生重复计数或遗漏；
- 低可信度资料是否导致无依据的结构缩水。

---

## 17.8 颗粒度展开中的 ID 保留（强制）

对象按等级、阶段、状态、时间、渠道或其他维度展开时，必须同时保留：

- 来源对象 ID；
- 展开维度字段；
- 模型记录 ID 或复合键；
- 来源版本；
- 有效状态。

推荐关系：

```text
来源对象ID + 展开维度
→ 唯一模型记录
```

要求：

1. 来源对象 ID 在所有展开记录中保持不变。
2. 模型记录 ID 只用于定位展开后的记录，不得替代来源对象 ID。
3. 同一来源对象的多条展开记录必须能够按来源对象 ID 正确汇总。
4. 配置导出按程序消费粒度输出时，必须明确导出主键与来源对象 ID 的关系。
5. 不得将对象在工作簿中的行序号作为来源对象 ID 或正式配置 ID。

---

# 18. 来源 ID 继承与主键治理规范（强制）

## 18.1 三类 ID 的职责

工作簿必须区分以下三类 ID：

| ID类型 | 核心职责 | 是否允许AI新增 | 是否可替代来源ID |
| --- | --- | --- | --- |
| 来源对象ID | 继承 MDD、正式配置或其他权威资料中的对象标识 | 否；资料无ID时只能标记待分配 | 否 |
| 模型记录ID | 标识对象在等级、阶段、状态等维度展开后的记录 | 可按已声明规则生成 | 否 |
| 程序导出ID | 满足程序消费的一行一记录主键 | 仅按已确认程序规则生成 | 否；必须保留来源对象ID |

## 18.2 来源 ID 继承表

生成前和工作簿内必须建立《来源 ID 继承表》。

| 对象类型 | 来源文档 | 来源版本 | 来源对象ID | 对象名称 | 模型Sheet | 模型记录ID规则 | 程序导出ID规则 | 继承状态 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

继承状态固定为：

- 已原样继承；
- 待分配；
- 存在冲突；
- 不适用；
- 用户确认映射。

## 18.3 ID 原样保留要求

来源 ID 必须按文本原样写入工作簿。

不得：

- 去除前导零；
- 自动转换为科学计数法；
- 改变大小写；
- 增删前缀或分隔符；
- 按分类重新连续编号；
- 因对象名称修改而修改 ID；
- 使用工作簿行号代替 ID。

对于超长数字型 ID，应使用文本格式或显式文本字段，避免精度丢失。

## 18.4 新对象与临时 ID

当模型需要承载来源资料中尚未定义的对象时：

1. 必须标记为“新增待确认对象”；
2. 必须使用独立的临时 ID 字段或“待分配”状态；
3. 临时 ID 应采用统一、显式的临时前缀或占位规则；
4. 临时 ID 不得与正式 ID 混用；
5. 临时 ID 记录不得进入正式程序导出；
6. 正式 ID 回填后，所有引用必须通过映射表自动更新。

## 18.5 派生记录与复合键

当一个来源对象被展开为多条可执行记录时，应使用：

```text
来源对象ID + 有效维度
```

形成复合键，或建立独立模型记录 ID。

有效维度可以包括项目实际需要的等级、阶段、状态、品质、渠道、时间、版本或其他维度。

硬规则：

- 复合键必须唯一；
- 每个派生记录必须保留来源对象 ID；
- 汇总和模拟必须能够回溯到来源对象；
- 不得将派生记录 ID 误写回来源对象 ID 字段；
- 导出规则必须说明程序读取来源 ID、派生 ID 还是复合键。

## 18.6 ID 映射与历史兼容

若旧工作簿、旧配置或外部资料已经存在另一套 ID，必须建立显式映射：

| 映射类型 | 旧ID | 权威来源ID | 对象名称 | 生效版本 | 映射状态 | 冲突说明 |
| --- | --- | --- | --- | --- | --- | --- |

禁止：

- 删除旧 ID 后只保留新 ID；
- 仅按名称模糊匹配；
- 在没有映射记录的情况下批量替换；
- 将多个旧 ID 无说明地合并为一个来源 ID。

## 18.7 外键与引用完整性

所有引用型字段必须：

- 从权威 ID 列表选择；
- 检查被引用 ID 是否存在；
- 检查对象类型是否匹配；
- 检查引用版本是否有效；
- 使用兼容方式处理未匹配状态，但不得用默认对象静默替代错误 ID；
- 在校验看板输出缺失引用、重复主键和孤立记录数量。

## 18.8 ID 变更规则

来源 ID 原则上不可由数值工作簿修改。

若项目确认需要变更：

- 必须记录旧 ID、新 ID、变更原因、生效版本和影响范围；
- 必须更新映射表；
- 必须检查全部公式、模拟、导出和外键引用；
- 必须保留历史追踪；
- 未完成影响检查前不得标记为 P3。

# 19. 工作簿架构规范

P3 工作簿应具备以下逻辑职责，Sheet 名和拆分方式由项目实际决定：

| 逻辑层 | 核心职责 |
| --- | --- |
| 说明与来源 | 版本、P/C状态、使用说明、资料和假设 |
| 目标与生命周期 | 阶段目标、KPI和偏差 |
| 参数与公共规则 | 全局旋钮、曲线、枚举和价值口径 |
| 系统价值 | 系统输入、输出、价值转换和贡献 |
| 专项模型 | 成长、经济、能力、概率或项目特有模型 |
| 汇总 | 资源、能力、进度和目标状态汇总 |
| 综合模拟 | 玩家分层或场景验证 |
| 归因与校验 | 异常定位、敏感性和风险 |
| 配置导出 | 程序消费数据 |

## 18.1 Sheet 拆分原则

- 高度相关、粒度一致、更新频率一致的数据应优先集中管理。
- 输入、计算、价值、汇总、验证和导出职责明显不同时可以拆分。
- 不得以 Sheet 数量作为专业程度指标。
- 不得为了分类展示复制整套明细或公式。
- 同一专项模型优先通过同 Sheet 分区保持完整价值链；确需拆分时必须清晰引用。

## 18.2 数据归属

每个核心 Sheet 必须说明：

- 职责；
- 输入来源；
- 记录粒度；
- 主键；
- 权威字段；
- 下游用途。

# 20. 公式与计算规范

## 19.1 基本原则

公式用于保证可复算、可调参、可追踪和可验证，不用于制造复杂度。

## 19.2 公式分层

复杂计算应拆为：

```text
基础值
→ 固定修正
→ 比例修正
→ 条件修正
→ 直接输出
→ 价值转换
→ 最终指标
```

## 19.3 参数引用

除 0、1 等数学常量外，业务参数不得硬编码在公式中。必须引用参数、曲线或配置。

## 19.4 必须支持的计算

核心模型按适用情况必须支持：

- 正算；
- 反算；
- 累计；
- 目标与实际偏差；
- 贡献拆解；
- 价值转换；
- 敏感性；
- 边界校验。

## 19.5 公式可维护性

- 一个公式解决一个明确问题；
- 复杂逻辑使用辅助列；
- 查表使用稳定键；
- 除数处理为零；
- 查找处理缺失；
- 累计处理首行；
- 公式填充保持一致；
- 不生成未解析外部链接；
- 计算列必须标注单位和是否导出。

# 21. 敏感性与联动分析规范

## 20.1 分析目标

敏感性分析必须回答：

- 哪些参数最影响目标；
- 影响通过哪些系统传导；
- 调整后的收益和风险；
- 是否引发其他系统失衡。

## 20.2 最低要求

P3 至少选择 5 个高影响参数，测试低、基准、高情景；建议扩展为上下多个档位。

每个情景必须分别重新计算专项模型和综合模拟，不得只展示扰动后的参数值。

输出至少包含：

| 参数 | 情景 | 参数值 | 专项模型结果 | 生命周期/目标结果 | 相对基准差值 | 变化率 | 弹性 | 主要传导系统 | 关联风险 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | --- | --- |

## 20.3 模型联动验收

修改任一高影响参数后，必须自动联动：

- 专项模型输出；
- 系统价值指标；
- 生命周期或目标校准；
- 玩家路径结果；
- 风险结论；
- 配置导出。

必须验证以下公式链：

```text
低/基准/高参数情景
→ 各情景重新计算专项模型与综合模拟
→ 结果差值、变化率和弹性
→ 主要传导系统、风险与调整入口
```

只改变局部单元格、不改变下游结果，或不同情景继续引用同一个基准结果的敏感性表，不视为有效分析。

# 23. 配置导出规范

导出表必须：

- 一行一条记录；
- 使用唯一主键；
- 与程序消费粒度一致；
- 引用权威结果；
- 不维护独立计算逻辑；
- 不包含合并单元格；
- 不存在公式错误；
- 不存在外部断链；
- 包含版本与更新时间；
- 校验记录数、主键唯一性和关联完整性。

## 23.1 ID 导出要求（强制）

1. 来源资料已有正式 ID 时，导出必须原样继承，不得输出 AI 自编 ID。
2. 派生记录必须同时输出程序主键和来源对象 ID，除非程序字段规范明确只需要复合主键且仍可反查来源对象。
3. 临时 ID、待分配 ID 和冲突 ID 不得进入正式导出。
4. 导出前必须检查：
   - 来源 ID 覆盖率；
   - 来源 ID 与对象名称匹配率；
   - 主键唯一性；
   - 外键存在率；
   - 临时 ID 数量；
   - 冲突 ID 数量；
   - 与来源配置记录数的一致性。
5. ID 为长数字或包含前导零时，必须按文本导出，避免格式或精度变化。

## 23.2 ID 导出校验表

| 校验项 | 目标 | 实际 | 状态 | 异常记录位置 |

| 临时ID数量 | 0 |  |  |  |
| 冲突ID数量 | 0 |  |  |  |
| ID格式变化数量 | 0 |  |  |  |

# 24. 验证与校验体系

## 23.1 总体验收问题

模型必须回答：

1. 目标是否可达；
2. 资源或能力是否闭环；
3. 每个系统贡献什么价值；
4. 贡献比例是否合理；
5. 参数是否真正联动；
6. 异常是否能够归因；
7. 配置是否可导出；
8. 结果是否符合声明的可信度。

## 23.2 校验看板

推荐包含：

| 校验项 | 目标 | 实际 | 偏差 | 状态 | 主要原因 | 调整入口 |
| --- | ---: | ---: | ---: | --- | --- | --- |

## 23.3 专项校验

按适用模型检查：

- 资源负数、断供、溢出和通胀；
- 成长断档、成本倒挂和边际收益异常；
- 能力来源垄断和属性跳跃；
- 概率和、保底、波动与期望；
- 系统价值缺失或重复；
- 模拟结果无法归因；
- 参数调整不联动；
- 导出粒度和主键异常。

# 25. 生成后强制验收

## 24.1 结构验收

确认是否具备：

- 目标层；
- 模型层；
- 价值层；
- 配置层；
- 验证与归因层；
- 来源和可信度说明。

## 24.2 系统价值验收

每个核心系统必须存在：

```text
输入
→ 规则
→ 直接输出
→ 玩家价值
→ 目标贡献
```

## 24.3 联动验收

抽查至少 5 个关键参数，确认修改后会影响：

- 系统输出；
- 价值指标；
- 目标结果；
- 模拟结果；
- 校验结论；
- 导出配置。

## 24.4 归因验收

至少对以下异常场景执行归因：

- 目标未达；
- 资源缺口；
- 成长过快或过慢；
- 单系统贡献过高；
- 极端概率或边界路径。

## 24.5 规模与完整度验收

确认：

- 实际规模与生成前预算一致；
- 核心轴完整展开；
- 不使用少量示例冒充完整模型；
- 没有无效笛卡尔积；
- 主键与关联键完整；
- 没有重复维护。

## 24.6 四条真实公式链验收

逐条检查：

| 公式链 | 是否适用 | 输入是否真实引用 | 中间计算是否完整 | 输出是否为公式 | 下游是否联动 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| A 专项状态→生命周期 |  |  |  |  |  |  |
| B 渠道配置→投放缺口 |  |  |  |  |  |  |
| C 多门槛→实际达成日 |  |  |  |  |  |  |
| D 参数情景→重算归因 |  |  |  |  |  |  |

## 24.7 颗粒度验收

必须将《颗粒度覆盖矩阵》的计划值与实际值逐项对比，并确认：

- 核心记录达到最低执行粒度；
- 公共规则未替代需要独立调参的实例；
- 样本结构未冒充全量结构；
- 模拟、汇总和导出均引用全量有效记录；
- 低可信度没有导致未经说明的行数、等级点、时间轴或对象规模缩减。

# 26. 一票否决项（Fail Gate）

触发任一项，不得标记为 P3。

| 编号 | 一票否决项 |
| --- | --- |
| FG1 | 没有生命周期、阶段目标或其他适用的顶层目标模型 |
| FG2 | 按系统目录机械生成配置表，核心系统之间没有价值关系 |
| FG3 | 只有配置，没有设计目标、计算链、价值层或验证 |
| FG4 | 核心结果、KPI、模拟输出或校验结论为手填值 |
| FG5 | 需要价值比较的资源没有统一价值或不可换算说明 |
| FG6 | 经济模型只有产出，没有消耗、库存、缺口或目标需求 |
| FG7 | 长期或阶段型项目没有适用周期的玩家路径或综合验证 |
| FG8 | 多个核心系统的唯一逻辑集中在综合模拟中 |
| FG9 | 同一参数或配置存在多个独立维护入口 |
| FG10 | 指定参考工作簿未实际读取和分析即声明已对齐 |
| FG11 | 核心系统只有输入、成本或直接输出，没有玩家价值和目标贡献 |
| FG12 | 成长或能力结果无法解释其对玩法结果、推进速度或核心指标的影响 |
| FG13 | 专项模型无法连接目标模型、资源模型或综合模拟，形成系统孤岛 |
| FG14 | 模拟发现异常，但无法定位主要系统、关键参数和调整入口 |
| FG15 | 高影响参数调整后，下游目标、模拟或导出不联动 |
| FG16 | 工作簿实际类型与生成前判型不一致，或以系统配置集合冒充全项目母表 |
| FG17 | 核心配置未达到程序、调参或验收所需的最低执行粒度 |
| FG18 | 未声明 P/C 状态，或把公式可运行描述为已验证 |
| FG19 | 实际投放由目标需求按比例直接分配，未从渠道单次产出、次数、参与率、完成率和开放周期正算 |
| FG20 | 生命周期或成长达成日只使用单一进度条件，遗漏项目已定义的资源条件或其他阻塞门槛 |
| FG21 | 敏感性分析只计算参数扰动值，没有分别重算低、基准、高情景的下游结果 |
| FG22 | 资料可信度较低时，通过减少等级点、时间轴、对象或配置记录规避假设，并将样本结构描述为完整模型 |
| FG23 | 实例存在独立成本、收益、状态、条件或导出记录，但工作簿仅提供公共规则或代表样本 |
| FG24 | 四条真实公式链中适用链路只存在文字说明、流程图或静态结果，没有真实公式引用和下游联动 |
| FG25 | 来源 MDD、正式配置或用户指定资料已有对象 ID，但工作簿为这些对象自行编制了另一套 ID |
| FG26 | 派生记录使用模型记录 ID 覆盖来源对象 ID，导致无法回溯原始对象 |
| FG27 | 来源 ID 冲突、重复主键、缺失外键或对象类型不匹配，仍进入正式模型或导出 |
| FG28 | 临时 ID、待分配 ID 或未经确认的 AI 生成 ID 进入正式程序导出 |
| FG29 | ID 在导入工作簿后发生前导零丢失、大小写变化、科学计数法或长数字精度损失 |

# 30. 快速判断标准

判断一个数值工作簿是否达到生产级，不看 Sheet 数量、公式数量或表格数量，优先检查其能否回答：

## 目标层

- 玩家或核心对象在关键阶段应达到什么状态？
- 当前模型是否能够达到目标？

## 资源与能力层

- 达成目标需要哪些资源或能力？
- 这些资源和能力从哪里产生、消耗在哪里？

## 系统价值层

- 每个核心系统产生什么直接输出？
- 输出如何转换为玩家价值？
- 每个系统对目标贡献多少？
- 是否存在无效、重复或垄断价值的系统？

## 真实公式链层

- 专项系统状态是否真实影响单位周期结果和生命周期达成时间？
- 实际投放是否由渠道配置正算，而不是由需求比例倒填？
- 实际达成日是否同时检查全部适用门槛？
- 敏感性情景是否分别重算完整下游结果？

## 调整与归因层

- 修改关键参数后，哪些系统、玩家状态和目标结果会变化？
- 出现异常时，能否定位主要系统、关键参数和调整入口？

## 颗粒度层

- 核心数据是否达到程序、调参、模拟和验收所需的最低执行粒度？
- 公共规则是否保留了需要独立调参的实例明细？
- 低可信度是否只降低结论可信度，而没有无依据缩减核心轴和记录规模？
- 配置导出是否覆盖全部有效记录？

## ID 与主键层

- 现有对象是否原样继承 MDD、正式配置或用户指定资料中的 ID？
- 来源对象 ID、模型记录 ID 和程序导出 ID 是否职责清晰？
- 派生记录是否仍能回溯到来源对象？
- 是否存在 AI 自编正式 ID、临时 ID 混入导出、重复主键或缺失外键？
- 前导零、大小写、前缀和长数字精度是否保持不变？

## 配置层

- 程序最终读取什么？
- 导出数据是否与模型权威结果保持联动？
- 导出 ID 是否与来源资料和程序字段规则一致？

若无法回答以上问题，即使工作簿具有大量 Sheet、公式和长期模拟，也不能称为生产级数值模型。
