# UI-ADD 美术需求模版规范 v1.5

## 写作原则

## 0. 文档定位

ADD（Art Design Document，美术需求文档）用于把策划、交互、数值、关卡包装等需求，整理成可直接交付给 AI、美术、动效、UI 协作方的标准化需求文档。

本文档聚焦 **UI 模块**，覆盖独立页面、弹窗、结果页、页面背景、页面依附型图标等所有 UI 层视觉资源的需求书写规范。

ADD 的目标不是"描述系统功能"，而是把需求翻译成**可直接拆任务、可直接开画、可直接验收**的美术语言。

ADD 需要解决四件事：

1. 让 AI 或美术明确知道"要画什么"
2. 让需求方明确知道"哪些资源必须交付"
3. 让协作方明确知道"哪些内容属于 UI、哪些属于原画、哪些属于特效"
4. 防止来源文档中的页面、弹窗、背景、场景、图标、资源层被遗漏

## 1. 核心原则

### 1.1 ADD 是"来源文档的美术覆盖映射文档"

ADD 不是自由整理文档，而是来源 MDD 文档中所有需要美术承接内容的覆盖映射文档。

在生成 ADD 前，必须先从以下来源中提取美术对象：

- UI 交互说明
- 美术元素资产清单
- GDD
- MDD
- 其他经确认的需求文档

未进入覆盖清单的对象，不允许在 ADD 中被默认省略。

### 1.2 ADD 的重点是"长什么样"，不是"能做什么"

ADD 中的需求描述应优先回答：

- 这是什么东西
- 放在哪里
- 长什么样
- 用什么包装语义
- 有哪些关键状态差异
- 美术交付时至少要做几套

禁止把 ADD 写成偏功能说明的文档。

### 1.3 一条需求只描述一个美术对象

不要把"按钮 + 图标 + 特效 + 文案 + 底板"混在一条里写。应按可交付对象拆开写。

### 1.4 UI 先写整页，再拆模块，再补状态（UI 专属原则）

UI 章节必须按照以下顺序组织：

1. 页面信息
2. 整页原型图占位
3. 页面外观总述
4. UI 清单
5. 状态示意图占位

### 1.5 复用不等于不用写

若某资源在当前系统中有独立展示位置、独立状态或独立视觉要求，即使是复用已有功能，也必须写进 ADD。只有"完全复用旧资源、当前系统无新增展示要求"时，才允许写"完全复用，不展开"。

### 1.6 页面、弹窗、背景、场景都属于正式覆盖对象

ADD 不只覆盖按钮、图标等单资源，也必须覆盖：

- 独立页面
- 独立弹窗
- 页面背景
- 弹窗遮罩 / 弹窗底板
- 关卡场景整体
- 关卡场景背景
- 缩略图 / 预览图
- 结果页包装层

凡是来源文档中已经独立存在、且美术需要承接的视觉对象，都必须进入 ADD。

## 2. 适用范围

UI-ADD 覆盖以下资源类型：

- 独立页面（主页面、子页面、列表页面、玩法页面、结果页）
- 弹窗（暂停弹窗、确认弹窗等）
- Tips / 浮层
- 页面背景 / 弹窗遮罩 / 弹窗底板
- UI 模块（按钮、卡片、信息区等）
- 页面依附型图标（详见第 5 章）
- 结果页包装层
- 缩略图 / 预览图（依附于 UI 页面的）

**不在 UI-ADD 覆盖范围内：**

- 系统资源型图标（货币、道具、奖励等）→ 写进原画-ADD
- 关卡场景及场景背景 → 写进原画-ADD
- 特效资源 → 写进特效-ADD
- 角色动作 → 写进动作-ADD

## 3. 生成 ADD 前的强制步骤

| UI交互说明 | 退出确认弹窗 | 二级页面 | 弹窗     | 是           | 是/否          |

- 主页面
- 子页面
- 列表页面

- 结果页

- 浮层

- UI 交互说明中出现的每个独立页面、独立弹窗、独立结果页，都必须先进入页面树，再进入 ADD
- 未进入页面树的页面，不允许在 ADD 中被省略
- 子页面、列表页面、路线板页面不能默认并入上级页面，必须先判断是否独立成章

- 漏关卡场景
- 漏原画资源层
- 漏特效资源层

## 5. 图标归属规则（强制）

### 5.1 页面依附型图标：写进 UI 页面清单

凡是依附于某个 UI 页面存在，并主要服务于该页面操作、状态表达或页面内信息提示的图形资源，统一写入该页面的 UI 清单中，不单独拆到"图标需求"小节。

包括但不限于：

- 设置图标
- 返回图标
- 暂停图标
- 锁定图标
- 星级表现图标
- 广告标识小图标
- 去广告入口图标
- 皮肤入口图标
- 章节节点状态图标
- 失败原因辅助图标
- 引导手势小图标
- 按钮上的小图形装饰

### 5.2 系统资源型图标：单独写进原画-ADD 的"图标需求"小节

凡是不依附于某个单一页面，而是作为系统资源在多个页面、多个系统中复用的图标，统一放在原画-ADD 的"图标需求"小节，**不写进 UI-ADD**。

包括但不限于：

- 货币图标
- 道具图标
- 奖励图标
- 材料图标
- 消耗品图标
- 宝箱图标
- 票券图标
- 钥匙图标
- 结算奖励图标
- 掉落物图标

### 5.3 判定规则

#### 归入 UI 页面清单的条件

满足以下任一条件，归入页面 UI 清单：

- 只在某个页面内承担按钮、状态、入口、提示作用
- 离开该页面就没有独立使用价值
- 外观需要跟随该页面整体按钮 / 卡片 / 弹窗风格一起设计

#### 归入原画"图标需求"小节的条件

满足以下任一条件，归入原画-ADD 图标需求小节：

- 属于货币、奖励、道具、材料等系统资源
- 会在多个页面中复用
- 独立于具体页面存在，是系统资产
- 未来可能进入背包、奖励、商店、掉落、结算等多个场景

### 5.4 双重属性资源的处理方式

若某图标既是系统资源，又在某个页面中有具体展示要求，则：

- 在原画-ADD"图标需求"小节中建立母资源说明
- 在对应 UI 页面清单中只写它在页面中的展示方式和表现要求

### 5.5 Fail Gate

- 页面依附型图标未写进对应 UI 页面清单：不合格
- 系统资源型图标误写进 UI 清单而未在原画-ADD 建立母资源：不合格

## 6. 页面背景与场景背景归属规则

### 6.1 页面背景：写进对应 UI 页面清单

凡是服务于某个具体页面，用于承托该页面布局、氛围、层级关系的背景资源，统一写进该页面的 UI 清单中，不允许只写在"页面外观总述"里。

包括但不限于：

- 主界面背景
- 章节界面背景
- 章节关卡列表背景
- 成功结算背景
- 失败重来背景
- 暂停弹窗遮罩与背景
- 退出确认弹窗遮罩与背景

### 6.2 关卡场景背景：写进原画-ADD 的"关卡场景需求"

凡是服务于玩法局内场景、且不属于单一 UI 页面的背景资源，统一写进原画-ADD 的"关卡场景需求"中，**不写进 UI-ADD**。

### 6.3 Fail Gate

- 页面背景只写在页面外观总述中，未进入 UI 清单：不合格
- 存在玩法局内场景背景，误写进 UI-ADD：不合格

## 7. 文档标准结构

推荐 UI-ADD 按以下结构写：

### 0. 文档基本信息

#### 写什么

- 项目名
- 系统名 / 页面名
- 文档版本
- 日期
- 负责人
- 来源文档

#### 怎么写

只写客观信息，不写长段说明。来源文档建议写到具体文档名，而不是只写"策划文档"。

#### 例

- 项目：画线救狗
- 系统：核心玩法系统
- 文档版本：v1.0
- 更新时间：2026-03-24
- 负责人：XXX
- 来源文档：《画线救狗-界面交互说明》

### 1. ADD 覆盖总表（强制）

#### 写什么

- UI 页面树与弹窗树
- 来源映射表
- 资源层级覆盖矩阵

#### 怎么写

先从 UI 交互说明里把所有页面、弹窗、结果页、列表页、Tips、浮层拆出来；再把来源文档里的 UI 美术对象逐项映射到 ADD 章节；最后检查资源层是否完整覆盖。

#### 例

**UI 页面树与弹窗树**

| 来源文档   | 页面名称     | 页面层级 | 页面类型 | 是否独立成章 | 是否已进入 ADD |
| ---------- | ------------ | -------- | -------- | ------------ | -------------- |
| UI交互说明 | 主界面       | 一级页面 | 主页面   | 是           | 是/否          |
| UI交互说明 | 章节界面     | 一级页面 | 列表页面 | 是           | 是/否          |
| UI交互说明 | 章节关卡列表 | 二级页面 | 列表页面 | 是           | 是/否          |
| UI交互说明 | 关卡界面     | 一级页面 | 玩法页面 | 是           | 是/否          |
| UI交互说明 | 成功结算界面 | 二级页面 | 结果页   | 是           | 是/否          |
| UI交互说明 | 失败重来界面 | 二级页面 | 结果页   | 是           | 是/否          |
| UI交互说明 | 暂停弹窗     | 二级页面 | 弹窗     | 是           | 是/否          |
| UI交互说明 | 退出确认弹窗 | 二级页面 | 弹窗     | 是           | 是/否          |

### 2. 需求概述

#### 写什么

- 本次需求目标
- 需求范围
- 不在本次范围内的内容
- 风格基准
- 复用说明

#### 怎么写

先写"本次为什么做这份 ADD"，再写"这次做到哪里，不做到哪里"，最后写统一的风格方向和复用原则。不要把资源细项堆在这一章。

#### 例

本次需求目标：整理核心玩法首发版 UI 需求，供 AI / UI 美术 / 动效直接拆任务。

需求范围：包含主界面、章节界面、关卡界面、结算界面及所有弹窗的 UI 资源。

不包含：皮肤商店完整界面、活动页、商业化长线包装。

风格基准：轻卡通、轮廓清晰、远看易读。

复用说明：如入口复用已有功能，但当前系统有独立展示要求，仍需写入 ADD。

### 3. 资源分类总览

#### 写什么

概括本次 UI-ADD 涉及的页面数量和覆盖范围。

#### 怎么写

建议用表格，至少列出：页面/弹窗名称、类型、说明。不要在这一章展开细节，只做目录式总览。

#### 例

| 页面 / 弹窗名称 | 类型   | 说明                     |
| --------------- | ------ | ------------------------ |
| 主界面          | 主页面 | 品牌展示、开始入口       |
| 章节界面        | 列表页 | 章节选择                 |
| 关卡界面        | 玩法页 | 局内 UI 层               |
| 成功结算界面    | 结果页 | 成功后展示               |
| 失败重来界面    | 结果页 | 失败后展示               |
| 暂停弹窗        | 弹窗   | 局内暂停操作             |
| 退出确认弹窗    | 弹窗   | 二次确认                 |

### 4. UI 需求

> #### **UI 需求描述写法要求**
>
> UI 的状态差异不再单独拆为"状态/变体"字段。状态必须直接写进"需求描述"。
>
> - **一条合格的 UI 需求描述，至少应同时包含：**
>   - 位置与体量
>   - 外形与底板
>   - 风格与材质感
>   - 文字 / 数值 / 图标承载方式
>   - 默认态和关键状态差异
>   - 是否有灰态 / 锁态 / 高亮态 / 满态 / 空态
> - **不合格写法**
>   - "主按钮，点击进入下一页"
>   - "星级展示，显示玩家星级"
>   - "锁定图标，用于未解锁状态"
> - **合格写法**
>   - "做成底部最醒目的大号主按钮，宽、厚、圆角，像软胶牌；默认态明亮，按下态有明显压感，灰态保留轮廓但降亮度和饱和度。"
>   - "锁定图标放在卡片蒙层中央，形状简洁、轮廓清楚，默认态为完整锁头，灰态卡片上能一眼认出当前不可点击。"
>   - "星级表现图标位于卡片下方信息区，已获得星为亮色、未获得星为浅灰描边，三颗星之间间距固定，不因数字变化跳位。"
>
> - **写什么**
>
> 把 UI 交互说明中的每个独立页面、结果页、弹窗、Tips、浮层翻译成可直接发 UI 美术的需求。
>
> - **每个页面 / 弹窗至少包含：**
>   - 页面信息
>   - 整页原型图占位
>   - 页面外观总述
>   - UI 清单
>   - 状态示意图占位
> - **怎么写**
>
> 按页面逐章展开，不允许把新增子页面、列表页、路线板页直接并进上级页面。UI 清单中，若存在页面背景、遮罩、底板、整体承托层，必须优先写这些对象。若页面存在背景，但 UI 清单中未出现"页面背景 / 遮罩 / 底板"条目，则视为未覆盖完整。
>
> - **UI 清单推荐首行顺序：**
>   - 页面背景 / 弹窗遮罩
>   - 页面主底板 / 主容器
>   - 核心信息区
>   - 核心按钮区
>   - 其他模块

##### 4.x.3 页面外观总述

###### 写什么

### 5. 资源命名与交付规范

#### 5.1 命名格式

适用：Unity + PSD/PSB直读工具 | 核心：全小写 + 下划线 + 无中文无空格

**通用规则（PNG + PSD 通用）**

| 规则           | 示例                      |

#### 4.2 输出要求

**PSD源文件输出要求**

| #  | 要求               | 说明                                  |
| -- | ------------------ | ------------------------------------- |
| 1  | 保存为 .psb 格式   | 支持大画布，性能更好                  |
| 2  | 画布尺寸为2的幂    | 如1024x1024，2048x2048                |
| 3  | 图层已全部栅格化   | 见分层规范                            |
| 4  | 文本图层保留可编辑 | 需要动态改字的加 @_Dynamic            |
| 5  | 按钮状态图尺寸一致 | normal/hover/press 必须同尺寸         |
| 6  | 删除无用图层       | 隐藏的参考线、备注图层删掉或加 @_Hide |

**PNG输出要求（不使用PSD直读时）**

| #  | 规则                     | 说明                           |
| -- | ------------------------ | ------------------------------ |
| 1  | 尺寸为2的幂              | 32/64/128/256/512/1024/2048    |
| 2  | 导出PNG-32（带透明通道） | 禁止JPG                        |
| 3  | 裁剪透明边缘             | 减少包体，九宫格除外           |
| 4  | 无脏边                   | 透明像素边缘干净，无半透明杂点 |

**图层栅格化要求**

| 要求       | 说明                                     |
| ---------- | ---------------------------------------- |
| 必须栅格化 | 图层样式（描边、投影、内发光、渐变叠加） |
| 必须栅格化 | 智能对象（Smart Object）                 |
| 必须栅格化 | 形状图层（Shape Layer）                  |
| 禁止保留   | 实时滤镜、混合选项（除非确认工具支持）   |

> ⚠️ 未栅格化的图层导入Unity后会丢失效果或完全不显示。

### 6. 验收标准

适用：主美验收 + 策划/程序联合验收 | 目的：减少返工，明确"合格"底线

#### 6.1 基础规范验收

| 检查项   | 标准                         | 验收方式        |
| -------- | ---------------------------- | --------------- |
| 命名规范 | 全小写+下划线，无中文无空格  | 目检 + 脚本扫描 |
| 文件格式 | PNG-32（带透明）             | 目检            |
| 尺寸规范 | 2的幂（32/64/128/256/512）   | 脚本扫描        |
| 透明边缘 | 已裁剪多余透明（九宫格除外） | 目检            |

#### 6.2 UI 界面验收

| 检查项       | 标准                                  | 严重程度 |
| ------------ | ------------------------------------- | -------- |
| 九宫格切片   | 拉伸区域无变形，边框不变形            | 🔴 致命   |
| 按钮状态     | normal/hover/press 三态齐全，尺寸一致 | 🔴 致命   |
| 对齐精度     | 元素按设计稿像素级对齐                | 🟡 主要   |
| 字体匹配     | 字体、字号、颜色与设计稿一致          | 🟡 主要   |
| 交互热区     | 按钮点击区域不小于44x44（移动端）     | 🟡 主要   |
| 多分辨率适配 | 不同分辨率下无裁切、无错位            | 🟡 主要   |
| 图集打包     | UI已正确打包到Sprite Atlas            | 🟢 次要   |

#### 6.3 Icon 验收

| 检查项   | 标准                                          | 严重程度 |
| -------- | --------------------------------------------- | -------- |
| 尺寸统一 | 同类Icon尺寸完全一致（如技能Icon全部128x128） | 🟡 主要   |
| 主体突出 | Icon主体占画布80%以上                         | 🟢 次要   |
| 背景透明 | 无残留背景色块                                | 🔴 致命   |
| 风格统一 | 同类Icon透视、光影、描边风格一致              | 🟡 主要   |
| 边缘干净 | 无锯齿、无半透脏边                            | 🟡 主要   |

#### 6.4 验收通过标准

- 🔴 致命项 = 0
- 🟡 主要项 ≤ 2
- 🟢 次要项 可后续优化

### 8. 自检

> AI自检

#### 生成后强制自检（Fail Gate）

以下任一项不满足，则该 UI-ADD 判定为"不合格，不可直接发美术"。

**通用项（所有ADD类型均适用）**

1. 复用入口被直接省略，未判断当前系统的展示要求
2. 新版本新增内容未同步进 ADD
3. 有参考图，但需求描述仍不足以让美术独立开画

**UI 专属项**

4. UI 交互说明中的新增独立界面 / 弹窗，未在 ADD 中逐页覆盖
5. 页面依附型图标未写进对应 UI 页面清单
6. UI 页面树 / 弹窗树未建立即直接生成 ADD
7. 存在页面背景 / 弹窗遮罩 / 结果页包装层，但未进入 UI 清单
8. 存在章节内关卡列表 / 路线板 / 子页面，但未作为独立页面覆盖
9. 页面外观总述提到了背景、场景、包装层，但正文资源清单中没有对应交付项

#### 自检问题单（生成后逐项回答）

- 是否已和 UI 界面清单逐页对齐？
- 是否已和弹窗清单逐个对齐？
- 是否已先做 UI 页面树与弹窗树？
- 是否已先做 ADD 覆盖总表？
- 是否已做资源层级覆盖矩阵？
- 页面依附型图标是否全部放在对应 UI 页面清单？
- 是否已补页面外观总述？
- 是否已把页面背景写进 UI 清单？
- 是否存在"写了资源名，但没写长什么样"的条目？
- 是否存在"复用，所以没写"的条目？
- 是否存在"功能描述很多，但外观描述很少"的条目？
- 是否存在"背景在总述里提到，但清单里没交付项"的条目？
- 是否存在"子页面 / 路线页 / 结果页被并进上级页面"的条目？
