# 原画-ADD 美术需求模版规范 v1.5

## 写作原则

## 0. 文档定位

ADD（Art Design Document，美术需求文档）用于把策划、交互、数值、关卡包装等需求，整理成可直接交付给 AI、美术、动效、UI、场景包装协作方的标准化需求文档。

本文档聚焦 **原画模块**，覆盖关卡场景、角色立绘、地形对象、危险对象、发射器、装饰对象、系统资源型图标、缩略图 / 预览图等所有原画层视觉资源的需求书写规范。

ADD 的目标不是"描述系统功能"，而是把需求翻译成**可直接拆任务、可直接开画、可直接验收**的美术语言。

ADD 需要解决四件事：

1. 让 AI 或美术明确知道"要画什么"
2. 让需求方明确知道"哪些资源必须交付"
3. 让协作方明确知道"哪些内容属于 UI、哪些属于原画、哪些属于特效"
4. 防止来源文档中的页面、弹窗、背景、场景、图标、资源层被遗漏

## 1. 核心原则

### 1.1 ADD 是"来源文档的美术覆盖映射文档"

ADD 不是自由整理文档，而是来源 MDD 文档中所有需要美术承接内容的覆盖映射文档。

在生成 ADD 前，必须先从以下来源中提取美术对象：

- UI 交互说明
- 美术元素资产清单
- GDD
- MDD
- 其他经确认的需求文档

未进入覆盖清单的对象，不允许在 ADD 中被默认省略。

### 1.2 ADD 的重点是"长什么样"，不是"能做什么"

ADD 中的需求描述应优先回答：

- 这是什么东西
- 放在哪里
- 长什么样
- 用什么包装语义
- 有哪些关键状态差异
- 美术交付时至少要做几套

禁止把 ADD 写成偏功能说明的文档。

### 1.3 一条需求只描述一个美术对象

不要把"角色 + 配件 + 特效 + 状态变体"混在一条里写。应按可交付对象拆开写。

### 1.4 原画需求禁止拆得过散（原画专属原则）

原画不要把"主体描述 / 材质形状 / 配色要求"拆成过多字段。统一合并进"需求描述"主字段，避免信息割裂。

所有原画需求统一使用"需求描述"主字段，直接写清：

- 这是什么东西
- 用在什么场景
- 长什么样
- 主材质和主配色
- 世界观包装语义
- 识别点
- 至少需要几种状态或变体

**不合格写法：**
- "火海图标"
- "危险对象"
- "宝石图标"
- "一个木箱"

**合格写法：**
- "做成可爱、厚实、偏卡通的奖励货币图标，轮廓完整、中心体积感明确，主色奶白偏黄，可加轻描边。"
- "地形平台，整体材质偏舞台地板或木制道具，需要和危险对象有明显层级区分，不能比危险对象抢眼。"

### 1.5 复用不等于不用写

若某资源在当前系统中有独立展示位置、独立状态或独立视觉要求，即使是复用已有功能，也必须写进 ADD。只有"完全复用旧资源、当前系统无新增展示要求"时，才允许写"完全复用，不展开"。

### 1.6 页面、弹窗、背景、场景都属于正式覆盖对象

ADD 不只覆盖单个角色、图标等单资源，也必须覆盖：

- 关卡场景整体
- 关卡场景背景
- 缩略图 / 预览图
- 结果页头图包装层（如属于原画层）

凡是来源文档中已经独立存在、且美术需要承接的视觉对象，都必须进入 ADD。

## 2. 适用范围

原画-ADD 覆盖以下资源类型：

- 关卡场景整体（前中后景分层）
- 关卡场景背景
- 角色立绘（目标角色、敌人等）
- 地形对象（平台、坡、墙、柱）
- 区域表现（禁画区、死亡区）
- 危险对象（蜜蜂、滚桶、吊灯等）
- 发射器（蜂巢、吊点、出怪点）
- 场景装饰对象（背景板、器材箱、观众席）
- 系统资源型图标（货币、道具、奖励、材料等）
- 缩略图 / 预览图（章节缩略图、关卡预览图）

**不在原画-ADD 覆盖范围内：**

- 页面背景 / 弹窗遮罩 → 写进 UI-ADD
- 页面依附型图标（设置、返回、星级等）→ 写进 UI-ADD
- 特效资源 → 写进特效-ADD
- 角色动作 → 写进动作-ADD

## 3. 生成 ADD 前的强制步骤

### 3.1 先建立《UI 页面树与弹窗树》（强制）

在正式建立《ADD 覆盖总表》前，必须先把 UI 交互说明中的所有界面按"页面树"方式拆清楚，以确定哪些背景和图标属于 UI 层，哪些属于原画层。

#### 表结构建议

| 来源文档   | 页面名称     | 页面层级 | 页面类型 | 是否独立成章 | 是否已进入 ADD |
| ---------- | ------------ | -------- | -------- | ------------ | -------------- |
| UI交互说明 | 主界面       | 一级页面 | 主页面   | 是           | 是/否          |
| UI交互说明 | 章节界面     | 一级页面 | 列表页面 | 是           | 是/否          |
| UI交互说明 | 章节关卡列表 | 二级页面 | 列表页面 | 是           | 是/否          |
| UI交互说明 | 关卡界面     | 一级页面 | 玩法页面 | 是           | 是/否          |
| UI交互说明 | 成功结算界面 | 二级页面 | 结果页   | 是           | 是/否          |
| UI交互说明 | 失败重来界面 | 二级页面 | 结果页   | 是           | 是/否          |
| UI交互说明 | 暂停弹窗     | 二级页面 | 弹窗     | 是           | 是/否          |
| UI交互说明 | 退出确认弹窗 | 二级页面 | 弹窗     | 是           | 是/否          |

#### 强制规则

- UI 交互说明中出现的每个独立页面、独立弹窗、独立结果页，都必须先进入页面树，再进入 ADD
- 未进入页面树的页面，不允许在 ADD 中被省略
- 子页面、列表页面、路线板页面不能默认并入上级页面，必须先判断是否独立成章

### 3.2 然后建立《ADD 覆盖总表》

在正式写 ADD 正文前，必须先整理覆盖总表。

#### 表结构建议

| 来源文档   | 来源章节/页面 | 对象名称     | 对象类型 | 是否需要独立资源 | 应落入 ADD 哪一章 | 是否已覆盖 |
| ---------- | ------------- | ------------ | -------- | ---------------- | ----------------- | ---------- |
| UI交互说明 | 主界面        | 幸运骨头图标 | 道具图标 | 是               | 原画-图标需求     | 是/否      |
| UI交互说明 | 关卡界面      | 关卡场景     | 场景     | 是               | 原画-关卡场景需求 | 是/否      |
| 资产清单   | 目标角色      | 主目标角色   | 原画     | 是               | 原画-目标角色     | 是/否      |
| 资产清单   | 发射器        | 蜂巢         | 原画     | 是               | 原画-发射器       | 是/否      |

#### 目的

用于防止：

- 漏关卡场景
- 漏原画资源层
- 漏系统资源型图标
- 漏缩略图 / 预览图
- 新版本新增内容未同步进 ADD

### 3.3 再建立《资源层级覆盖矩阵》

#### 表结构建议

| 资源层          | 是否必须             | 当前项目是否有 | 对应对象举例                     | ADD 是否有对应章节 |
| --------------- | -------------------- | -------------- | -------------------------------- | ------------------ |
| 关卡场景整体    | 有玩法局内场景则必须 | 是/否          | 动物表演棚关卡场景               | 是/否              |
| 关卡场景背景    | 有则必须             | 是/否          | 浅网格背景、片场背景层           | 是/否              |
| 目标角色        | 有则必须             | 是/否          | 主目标角色                       | 是/否              |
| 地形对象        | 有则必须             | 是/否          | 平台、坡、墙、柱                 | 是/否              |
| 区域表现        | 有则必须             | 是/否          | 禁画区、死亡区                   | 是/否              |
| 危险对象        | 有则必须             | 是/否          | 蜜蜂、滚桶、吊灯                 | 是/否              |
| 发射器          | 有则必须             | 是/否          | 蜂巢、吊点、出怪点               | 是/否              |
| 场景装饰对象    | 建议覆盖             | 是/否          | 背景板、器材箱、观众席           | 是/否              |
| 缩略图 / 预览图 | 有则必须             | 是/否          | 章节缩略图、关卡预览图           | 是/否              |
| 系统资源型图标  | 有则必须             | 是/否          | 货币、奖励、道具图标             | 是/否              |

## 4. 通用字段规范

### 4.1 通用字段

| 字段            | 是否必填 | 说明                              |
| --------------- | -------- | --------------------------------- |
| 编号 / 资源ID   | 必填     | 便于追踪                          |
| 分类            | 必填     | 原画                              |
| 所属页面 / 系统 | 建议必填 | 用于归属定位                      |
| 模块            | 必填     | 明确资源属于哪个模块              |
| 资源名称        | 必填     | 可交付对象名称                    |
| 需求描述        | 必填     | 直接写清要画什么（含材质、配色、语义、识别点、套数） |
| 状态拆分/最少套数 | 必填   | 至少需要几套，各套差异是什么      |
| 参考图          | 建议必填 | 参考图只能辅助，不能替代描述      |
| 输出要求        | 必填     | PNG透明底 / PSD分层 / PSB 等      |
| 备注            | 可选     | 优先级、复用说明、风险            |

## 5. 图标归属规则（强制）

### 5.1 页面依附型图标：写进 UI-ADD 页面清单

凡是依附于某个 UI 页面存在，并主要服务于该页面操作、状态表达或页面内信息提示的图形资源，统一写入 UI-ADD 中对应页面的清单，**不写进原画-ADD**。

包括但不限于：

- 设置图标
- 返回图标
- 暂停图标
- 锁定图标
- 星级表现图标
- 引导手势小图标
- 按钮上的小图形装饰

### 5.2 系统资源型图标：单独写进原画-ADD 的"图标需求"小节

凡是不依附于某个单一页面，而是作为系统资源在多个页面、多个系统中复用的图标，统一放在本文档（原画-ADD）的"图标需求"小节。

包括但不限于：

- 货币图标
- 道具图标
- 奖励图标
- 材料图标
- 消耗品图标
- 宝箱图标
- 票券图标
- 钥匙图标
- 结算奖励图标
- 掉落物图标

### 5.3 判定规则

#### 归入原画"图标需求"小节的条件

满足以下任一条件，归入原画-ADD 图标需求小节：

- 属于货币、奖励、道具、材料等系统资源
- 会在多个页面中复用
- 独立于具体页面存在，是系统资产
- 未来可能进入背包、奖励、商店、掉落、结算等多个场景

### 5.4 双重属性资源的处理方式

若某图标既是系统资源，又在某个页面中有具体展示要求，则：

- 在本文档"图标需求"小节中建立母资源说明
- 在 UI-ADD 对应页面清单中只写它在页面中的展示方式和表现要求

### 5.5 Fail Gate

- 系统资源型图标未写进原画-ADD"图标需求"小节：不合格
- 把页面依附型图标误写进原画-ADD：不合格

## 6. 页面背景与场景背景归属规则（强制）

### 6.1 页面背景：写进 UI-ADD 对应页面清单

凡是服务于某个具体页面，用于承托该页面布局、氛围的背景资源，统一写进 UI-ADD 中，**不写进原画-ADD**。

包括但不限于：

- 主界面背景
- 章节界面背景
- 成功结算背景
- 失败重来背景
- 弹窗遮罩与背景

### 6.2 关卡场景背景：写进原画-ADD 的"关卡场景需求"

凡是服务于玩法局内场景、且不属于单一 UI 页面的背景资源，统一写进本文档（原画-ADD）的"关卡场景需求"中。

包括但不限于：

- 局内浅网格背景
- 片场背景板
- 后景装饰
- 中景承托层
- 远景观众席
- 场景灯架背景层

### 6.3 Fail Gate

- 存在玩法局内场景，但未建立"关卡场景需求"：不合格
- 把页面背景误写进原画-ADD：不合格

## 7. 文档标准结构

推荐原画-ADD 按以下结构写：

### 0. 文档基本信息

#### 写什么

- 项目名
- 系统名 / 页面名
- 文档版本
- 日期
- 负责人
- 来源文档

#### 怎么写

只写客观信息，不写长段说明。来源文档建议写到具体文档名，而不是只写"策划文档"。

#### 例

- 项目：画线救狗
- 系统：核心玩法系统
- 文档版本：v1.0
- 更新时间：2026-03-24
- 负责人：XXX
- 来源文档：《给美术的关卡元素资产需求清单 v2（整合版）》

### 1. ADD 覆盖总表（强制）

#### 写什么

- 来源映射表
- 资源层级覆盖矩阵

#### 怎么写

先把来源文档里的原画美术对象逐项映射到 ADD 章节；再检查资源层是否完整覆盖。

### 2. 需求概述

#### 写什么

- 本次需求目标
- 需求范围
- 不在本次范围内的内容
- 风格基准
- 复用说明

#### 例

本次需求目标：整理核心玩法首发版原画需求，供 AI / 原画美术直接拆任务。

需求范围：包含关卡场景、目标角色、危险对象、地形、图标。

不包含：皮肤换装、活动特供原画。

风格基准：轻卡通、轮廓清晰、远看易读。

复用说明：如入口复用已有功能，但当前系统有独立展示要求，仍需写入 ADD。

### 3. 资源分类总览

#### 写什么

概括本次原画-ADD 涉及的资源大类和数量级。

#### 例

| 分类     | 首发范围 | 说明                             |
| -------- | -------- | -------------------------------- |
| 关卡场景 | 1个场景  | 动物表演棚，含前中后景           |
| 角色立绘 | 1套      | 主目标角色                       |
| 危险对象 | 3类      | 蜜蜂、滚桶、吊灯                 |
| 地形对象 | 4类      | 平台、坡、墙、柱                 |
| 图标     | 2个      | 幸运骨头图标、结算奖励图标       |

### 4. 原画需求（核心章节）

> - **模块目标**
>
> 把非 UI 的视觉资源拆成可直接发原画 / 场景 / 图标美术的需求。
>
> - **原画至少建议按以下顺序组织：**
>   - 场景需求（如有）
>   - 角色立绘（如有）
>   - 图标需求（仅限货币 / 道具 / 奖励 / 材料等系统资源型图标）
> - 所有原画需求统一使用"需求描述"主字段，直接写清是什么、长什么样、什么材质、什么颜色、什么语义、需要几套。不要把一个资源拆成三四列导致信息割裂。
> - **原画需求必须在同一列“需求描述”中直接写清：**
>   - 这是什么东西
>   - 用在什么场景
>   - 长什么样
>   - 主材质和主配色
>   - 世界观包装语义
>   - 识别点
>   - 至少需要几种状态或变体
> - **不合格写法**
>   - “火海图标”
>   - “危险对象”
>   - “宝石图标”
>   - “一个木箱”

#### 4.1 场景需求

##### 写什么

项目内整体场景主题、前中后景分层、可玩区与装饰区区分、主题变化范围。

##### 怎么写

写"整个场景长什么样"，不是写单个资源。先写整体，再拆资源层。

##### 例

| 资源ID  | 分类 | 模块     | 资源名称 | 需求描述                                                     | 状态拆分 / 最少套数            | 参考图       | 输出要求  |
| ------- | ---- | -------- | -------- | ------------------------------------------------------------ | ------------------------------ | ------------ | --------- |
| ART-060 | 原画 | 场景包装 | 主舞台   | 做动物表演棚最核心的视觉锚点。外观像一个可以演出的主舞台，首发要能看出从"破旧"到"修复"的阶段变化。 | 破旧版 / 基础修复版 / 完整版。 | 关卡资产清单 | PNG / PSD |
| ART-061 | 原画 | 场景背景 | 局内背景 | 浅色网格底，用于视觉打底，不能影响角色和危险对象的识别，网格线偏浅，整体偏平。 | 基础一套                       | 参考图       | PNG / PSD |

#### 4.2 **角色立绘需求**

##### 写什么

资源ID、分类、模块、资源名称、需求描述、状态拆分 / 最少套数、参考图、输出要求。

##### 怎么写

重点放在需求描述，不写抽象词，直接写主体、配色、材质和识别点。

##### 例

| 资源ID  | 分类 | 模块     | 资源名称   | 需求描述                                                     | 状态拆分 / 最少套数                          | 参考图       | 输出要求              |
| ------- | ---- | -------- | ---------- | ------------------------------------------------------------ | -------------------------------------------- | ------------ | --------------------- |

### 5. 资源命名与交付规范

#### 5.1 命名格式

适用：Unity + PSD/PSB直读工具 | 核心：全小写 + 下划线 + 无中文无空格

**通用规则（PNG + PSD 通用）**

| 规则           | 示例                      |
| -------------- | ------------------------- |
| 全小写         | char_dog_idle ✅           |
| 下划线分隔     | art_scene_bg ✅            |

| 数字不开头     | 1_icon ❌ / icon_01 ✅      |
| 无特殊符号     | art#bg ❌                  |

**输出PNG命名规范**

| 资源类型   | 公式             | 示例                        |
| ---------- | ---------------- | --------------------------- |
| 背景       | bg_场景_层级     | bg_forest_00_back.png       |

| 图标       | icon_类型_描述   | icon_item_lucky_bone.png    |
| 场景道具   | prop_类型_名称   | prop_platform_wood.png      |

**常用缩写**

| 缩写  | 含义   | 缩写  | 含义     |
| ----- | ------ | ----- | -------- |
| bg    | 背景   | char  | 角色     |
| icon  | 图标   | prop  | 场景物件 |
| fx    | 特效   |       |          |

#### 5.2 输出要求

**PSD/PSB源文件输出要求**

| #  | 要求               | 说明                                  |
| -- | ------------------ | ------------------------------------- |
| 1  | 保存为 .psb 格式   | 支持大画布，性能更好                  |
| 2  | 画布尺寸为2的幂    | 如1024x1024，2048x2048                |
| 3  | 图层已全部栅格化   | 见分层规范                            |
| 4  | 角色部件同画布尺寸 | 所有部件使用相同画布尺寸              |
| 5  | 删除无用图层       | 隐藏的参考线、备注图层删掉或加 @_Hide |

**PNG输出要求**

| #  | 规则                     | 说明                           |
| -- | ------------------------ | ------------------------------ |
| 1  | 尺寸为2的幂              | 32/64/128/256/512/1024/2048    |
| 2  | 导出PNG-32（带透明通道） | 禁止JPG（角色必须透明底）      |
| 3  | 裁剪透明边缘             | 减少包体                       |
| 4  | 无脏边                   | 透明像素边缘干净，无半透明杂点 |

**图层栅格化要求**

| 要求       | 说明                                     |
| ---------- | ---------------------------------------- |
| 必须栅格化 | 图层样式（描边、投影、内发光、渐变叠加） |
| 必须栅格化 | 智能对象（Smart Object）                 |
| 必须栅格化 | 形状图层（Shape Layer）                  |
| 禁止保留   | 实时滤镜、混合选项（除非确认工具支持）   |

#### 5.3 分层要求（角色 / 骨骼动画 / 换装）

| 规则             | 说明                                                   |
| ---------------- | ------------------------------------------------------ |
| 身体部件独立     | 头、躯干、上臂、前臂、手、大腿、小腿、脚，各为独立图层 |
| 同画布尺寸       | 所有部件使用相同画布尺寸，保证锚点坐标系一致           |
| 图层顺序正确     | 底层在下（后腰），上层在上（前胸、武器）               |
| 换装占位图层     | 可换装部位保留空白图层，命名带 _slot                   |
| 对称部件标注左右 | 左臂 _L，右臂 _R，如 char_knight_arm_L                 |

**分层检查清单**

- 角色身体部件全部独立？
- 部件画布尺寸统一？
- 换装部位有空白占位图层？
- 图层顺序从后到前正确？

| PNG（手动） | —      | —             | 100             | 角色开   |

- 图层样式已栅格化？
- 角色部件画布尺寸统一？
- 保存为 `.psb`？

PNG文件：

### 8. 自检

> AI自检

#### 生成后强制自检（Fail Gate）

以下任一项不满足，则该原画-ADD 判定为"不合格，不可直接发美术"。

**通用项（所有ADD类型均适用）**

1. 复用入口被直接省略，未判断当前系统的展示要求
2. 新版本新增内容未同步进 ADD
3. 有参考图，但需求描述仍不足以让美术独立开画

**原画专属项**

4. 系统资源型图标未写进"图标需求"小节
5. 原画需求描述仍然主要是抽象功能词，而非具体外观
6. 判定资源、危险来源点、装饰资源未分层
7. 死亡区、禁画区、挂点等规则型资源未单列
8. 存在玩法局内场景，但未建立"关卡场景需求"小节
9. 存在货币 / 奖励 / 掉落物，但未建立系统资源型图标需求
10. 存在缩略图 / 预览图 / 章节预览图需求，但未单独覆盖

#### 自检问题单（生成后逐项回答）

- 是否已和资产清单逐类对齐？
- 是否已先做 ADD 覆盖总表？
- 是否已做资源层级覆盖矩阵？
- 系统资源型图标是否全部放在图标需求小节？
- 是否已把玩法局内整体场景写进"关卡场景需求"？
- 是否存在"写了资源名，但没写长什么样"的条目？
- 是否存在"复用，所以没写"的条目？
- 是否存在"功能描述很多，但外观描述很少"的条目？
- 是否存在判定资源 / 危险来源点 / 装饰资源未分层的情况？
- 是否存在死亡区 / 禁画区 / 挂点等规则型资源未单列的情况？
