# 特效-ADD 美术需求模版规范 v1.5

## 写作原则

## 0. 文档定位

ADD（Art Design Document，美术需求文档）用于把策划、交互、数值、关卡包装等需求，整理成可直接交付给 AI、美术、动效、UI、场景包装协作方的标准化需求文档。

本文档聚焦 **特效模块**，覆盖划线反馈、危险循环、结果反馈、UI 特效等所有特效层视觉资源的需求书写规范。

ADD 的目标不是"描述系统功能"，而是把需求翻译成**可直接拆任务、可直接开制作、可直接验收**的美术语言。

ADD 需要解决四件事：

1. 让 AI 或美术明确知道"要做什么"
2. 让需求方明确知道"哪些资源必须交付"
3. 让协作方明确知道"哪些内容属于 UI、哪些属于原画、哪些属于特效"
4. 防止来源文档中的特效触发点、挂点、资源层被遗漏

## 1. 核心原则

### 1.1 ADD 是"来源文档的美术覆盖映射文档"

ADD 不是自由整理文档，而是来源 MDD 文档中所有需要美术承接内容的覆盖映射文档。

在生成 ADD 前，必须先从以下来源中提取美术对象：

- UI 交互说明
- 美术元素资产清单
- GDD
- MDD
- 其他经确认的需求文档

未进入覆盖清单的对象，不允许在 ADD 中被默认省略。

### 1.2 ADD 的重点是"长什么样"，不是"能做什么"

ADD 中的需求描述应优先回答：

- 这是什么特效
- 挂在哪里
- 什么时候触发
- 看起来像什么
- 颜色或变体
- 时长或循环方式

禁止把 ADD 写成偏功能说明的文档。

### 1.3 一条需求只描述一个美术对象

不要把多个特效点混在一条里写。应按可交付特效资源拆开写。

### 1.4 特效需求必须写清触发、挂点和视觉表现（特效专属原则）

特效不能只写"做个高级特效"。必须写清：

- 挂在哪（挂点 / 作用对象）
- 什么时候触发（触发时机）
- 看起来像什么（视觉表现描述）
- 颜色或变体
- 时长或循环方式
- 是否会遮挡 UI 或判定

**不合格写法：**
- "做个炫酷特效"
- "有效线特效，高级一点"
- "结算特效，要好看"

**合格写法：**
- "有效线落地时，在线周围给一个很短的落地感反馈，帮助玩家知道这根线已生效，时间短、范围小，不影响判定观察。"
- "火海危险面上做持续火焰起伏和轻热浪，强度服务于识别，不做表演型大火，常驻循环。"

### 1.5 复用不等于不用写

若某特效在当前系统中有独立触发时机、独立挂点或独立视觉要求，即使是复用已有功能，也必须写进 ADD。只有"完全复用旧资源、当前系统无新增展示要求"时，才允许写"完全复用，不展开"。

### 1.6 特效资源的覆盖边界

特效-ADD 不收录：

- UI 页面的过渡动画（由 UI 动效承接）
- 角色骨骼动作（由动作-ADD 承接）
- 纯静态贴图（由原画-ADD 承接）

特效-ADD 收录：

- 所有需要序列帧 / 粒子系统 / Shader 制作的动态视觉资源
- 局内玩法反馈特效
- 结算表现特效（如属于特效层）
- 危险对象循环特效
- 角色身上的叠加特效

## 2. 适用范围

特效-ADD 覆盖以下资源类型：

- 玩法反馈特效（划线落地、有效线、无效线等）
- 危险对象循环特效（火海、电场等）
- 角色表现特效（受击、死亡、成功等）
- 结算反馈特效（成功爆发、失败消散等）
- 场景氛围特效（尘埃、光晕、环境粒子等）

**不在特效-ADD 覆盖范围内：**

- 图标资源 → 写进原画-ADD
- 页面背景 → 写进 UI-ADD
- 角色动作 → 写进动作-ADD
- UI 页面切换动画 → 由 UI 动效承接

## 3. 生成 ADD 前的强制步骤

### 3.1 先建立《UI 页面树与弹窗树》（强制）

在正式建立《ADD 覆盖总表》前，需参照 UI-ADD 中建立的页面树，了解哪些特效需要挂在 UI 层，哪些挂在局内场景层。

#### 表结构建议

| 来源文档   | 页面名称     | 页面层级 | 页面类型 | 特效挂载层 | 是否已进入特效 ADD |
| ---------- | ------------ | -------- | -------- | ---------- | ------------------ |
| UI交互说明 | 关卡界面     | 一级页面 | 玩法页面 | 局内场景层 | 是/否              |
| UI交互说明 | 成功结算界面 | 二级页面 | 结果页   | UI层       | 是/否              |
| UI交互说明 | 失败重来界面 | 二级页面 | 结果页   | UI层       | 是/否              |

#### 强制规则

- 有玩法局内触发点的特效，必须明确挂载层级（UI层 vs 场景层）
- 未确认挂载层的特效，不允许在 ADD 中被默认省略

### 3.2 然后建立《ADD 覆盖总表》

在正式写 ADD 正文前，必须先整理覆盖总表。

#### 表结构建议

| 来源文档   | 来源章节/页面 | 对象名称     | 特效类型 | 触发方式 | 应落入 ADD 哪一章 | 是否已覆盖 |
| ---------- | ------------- | ------------ | -------- | -------- | ----------------- | ---------- |
| GDD        | 划线系统      | 有效线落地   | 反馈特效 | 事件触发 | 玩法反馈特效      | 是/否      |
| GDD        | 危险系统      | 火海循环     | 循环特效 | 常驻     | 危险循环特效      | 是/否      |
| UI交互说明 | 成功结算      | 成功爆发特效 | 表现特效 | 页面触发 | 结算反馈特效      | 是/否      |

#### 目的

用于防止：

- 漏玩法触发点特效
- 漏危险循环特效
- 漏结算反馈特效
- 新版本新增触发点未同步进 ADD

### 3.3 再建立《资源层级覆盖矩阵》

#### 表结构建议

| 特效资源层         | 是否必须         | 当前项目是否有 | 对应对象举例             | ADD 是否有对应章节 |
| ------------------ | ---------------- | -------------- | ------------------------ | ------------------ |
| 玩法反馈特效       | 有玩法机制则必须 | 是/否          | 有效线落地、无效线反馈   | 是/否              |
| 危险对象循环特效   | 有危险对象则必须 | 是/否          | 火海循环、蜜蜂飞行粒子   | 是/否              |
| 角色表现特效       | 有则必须         | 是/否          | 受击、死亡、成功庆祝特效 | 是/否              |
| 结算反馈特效       | 有结果页则必须   | 是/否          | 成功爆发、失败消散       | 是/否              |
| 场景氛围特效       | 建议覆盖         | 是/否          | 尘埃、光晕、环境粒子     | 是/否              |

## 4. 通用字段规范

### 4.1 特效需求字段

| 字段            | 是否必填 | 说明                                             |
| --------------- | -------- | ------------------------------------------------ |
| 编号 / 资源ID   | 必填     | 便于追踪                                         |
| 分类            | 必填     | 特效                                             |
| 模块            | 必填     | 明确特效属于哪个触发模块                         |
| 特效名称        | 必填     | 可交付特效资源名称                               |
| 需求描述        | 必填     | 写清挂点/作用对象、视觉表现、时长、是否遮挡      |
| 触发时机        | 必填     | 什么条件下触发                                   |
| 颜色 / 变体     | 必填     | 主色调或多种变体说明                             |
| 参考            | 建议必填 | 参考图或参考视频，只能辅助，不能替代描述         |
| 输出要求        | 必填     | 序列帧 / 粒子系统参数 / Shader / 程序参数等      |
| 备注            | 可选     | 优先级、性能限制、与程序的配合要求               |

## 5. 图标与背景资源归属说明

本章为协作边界说明，特效-ADD **不承接**图标和页面背景资源。

- 货币、道具、奖励等系统资源型图标 → 写进原画-ADD
- 页面依附型图标（设置、返回、星级等）→ 写进 UI-ADD
- 页面背景 / 弹窗遮罩 → 写进 UI-ADD
- 关卡场景背景（静态） → 写进原画-ADD

特效-ADD 只收录**动态视觉资源**，包括序列帧、粒子系统、Shader 制作的内容。

如果某个资源需要"静态底图 + 上层动态特效"，则：

- 静态底图写进原画-ADD
- 动态特效部分写进特效-ADD

## 6. 文档标准结构

推荐特效-ADD 按以下结构写：

### 0. 文档基本信息

#### 写什么

- 项目名
- 系统名 / 模块名
- 文档版本
- 日期
- 负责人
- 来源文档

#### 怎么写

只写客观信息，不写长段说明。来源文档建议写到具体文档名，而不是只写"策划文档"。

#### 例

- 项目：画线救狗
- 系统：核心玩法系统
- 文档版本：v1.0
- 更新时间：2026-03-24
- 负责人：XXX
- 来源文档：《画线救狗-界面交互说明》、《给美术的关卡元素资产需求清单 v2（整合版）》

### 1. ADD 覆盖总表

#### 写什么

- 特效触发点清单
- 来源映射表
- 资源层级覆盖矩阵

#### 怎么写

先从 GDD / MDD 里把所有特效触发点拆出来；再把来源文档里的特效对象逐项映射到 ADD 章节；最后检查特效资源层是否完整覆盖。

### 2. 需求概述

#### 写什么

- 本次需求目标
- 需求范围
- 不在本次范围内的内容
- 风格基准
- 复用说明

#### 例

本次需求目标：整理核心玩法首发版特效需求，供特效美术 / 程序直接拆任务。

需求范围：包含划线反馈、危险循环、结算反馈特效。

不包含：皮肤特有特效、活动特效。

风格基准：轻卡通、轮廓清晰、不遮挡判定。

复用说明：如某特效复用已有资源，但当前系统有独立触发要求，仍需写入 ADD。

### 3. 资源分类总览

#### 写什么

概括本次特效-ADD 涉及的特效大类和数量。

#### 例

| 分类         | 首发范围 | 说明                             |
| ------------ | -------- | -------------------------------- |
| 玩法反馈特效 | 2个      | 有效线落地、无效线反馈           |
| 危险循环特效 | 3个      | 火海、电场、蜜蜂粒子             |
| 结算反馈特效 | 2个      | 成功爆发、失败消散               |

### 4. 特效需求

> - **模块目标**
>
> 把所有需要特效美术制作的动态视觉资源拆成可直接发特效制作的需求。
>
> - **特效需求必须在同一行里写清：**
>   - 挂在哪（挂点 / 作用对象）
>   - 什么时候触发
>   - 看起来像什么
>   - 时长或循环方式
>   - 是否遮挡 UI 或判定
>   - 颜色或变体
>
> - **不合格写法**
>   - "做个高级特效"
>   - "有效线特效，要酷"
>   - "结算特效，炸一下"
>
> - **合格写法**
>   - "有效线落地时，在线周围给一个很短的落地感反馈，时间短（0.3s 以内）、范围小，不影响判定观察，颜色偏黑灰中性。"
>   - "火海危险面上做持续火焰起伏和轻热浪，常驻循环，强度服务于识别，不做表演型大火，颜色红橙系。"
>   - "成功结算时在页面主视觉区做一次爆发型粒子，从中心向外散开，时长约 1s，不循环，颜色暖金 / 白光系。"
>
> - **特效章节建议按以下顺序组织：**
>   - 玩法反馈特效（如有）
>   - 危险对象循环特效（如有）
>   - 角色表现特效（如有）
>   - 结算反馈特效（如有）
>   - 场景氛围特效（如有）

#### 4.1 玩法反馈特效

##### 写什么

玩法机制触发的即时反馈特效，包括有效线、无效线、消除、连击等。

##### 怎么写

重点写时机、时长、范围和是否影响判定观察。

##### 例

| 编号  | 分类 | 模块     | 特效名称       | 需求描述                                                     | 触发时机     | 颜色/变体 | 参考 | 输出要求          |
| ----- | ---- | -------- | -------------- | ------------------------------------------------------------ | ------------ | --------- | ---- | ----------------- |
| FX-01 | 特效 | 划线反馈 | 有效线落地反馈 | 有效线落地时，在线周围给一个很短的落地感反馈，帮助玩家知道这根线已生效，时间短（≤0.3s）、范围小，不影响判定观察，不遮挡 UI。 | 有效线生成时 | 黑灰      | 参考 | 序列帧 / 程序参数 |
| FX-02 | 特效 | 划线反馈 | 无效线消除反馈 | 无效线消失时，给一个轻微的消散效果，提示玩家这条线无效，视觉上要比有效线落地反馈更弱，避免误导。 | 无效线消失时 | 浅灰/透明 | 参考 | 序列帧 / 程序参数 |

#### 4.2 危险对象循环特效

##### 写什么

危险对象的常驻循环视觉特效，用于强化危险感和识别度。

##### 怎么写

重点写循环方式和是否遮挡判定区域。

##### 例

| 编号  | 分类 | 模块     | 特效名称 | 需求描述                                                     | 触发时机 | 颜色/变体 | 参考 | 输出要求        |
| ----- | ---- | -------- | -------- | ------------------------------------------------------------ | -------- | --------- | ---- | --------------- |
| FX-03 | 特效 | 危险循环 | 火海循环 | 火海危险面上做持续火焰起伏和轻热浪，强度服务于识别，不做表演型大火；循环无缝衔接，不能遮挡玩家判断路线。 | 常驻     | 红橙      | 参考 | Shader / 序列帧 |
| FX-04 | 特效 | 危险循环 | 蜜蜂飞行粒子 | 蜜蜂周围做轻微飞翔感粒子（翅膀气流或小光点），帮助强化蜜蜂是活体危险的感知，粒子范围不能超出蜜蜂碰撞体太多，循环。 | 常驻     | 浅黄透明  | 参考 | 粒子系统        |

#### 4.3 角色表现特效

##### 写什么

角色在受击、死亡、成功等关键时刻的视觉特效。

##### 怎么写

写清楚特效挂在角色身上还是场景层，以及是否和动作配合。

##### 例

| 编号  | 分类 | 模块     | 特效名称   | 需求描述                                                     | 触发时机     | 颜色/变体 | 参考 | 输出要求 |
| ----- | ---- | -------- | ---------- | ------------------------------------------------------------ | ------------ | --------- | ---- | -------- |
| FX-05 | 特效 | 角色表现 | 受击闪烁   | 角色被危险对象接触时，角色本体做一次轻微闪白（0.2s 以内），帮助玩家感知被攻击事件，不做爆炸型大特效。 | 角色被攻击时 | 白        | 参考 | Shader   |
| FX-06 | 特效 | 角色表现 | 成功庆祝光 | 结算成功时，在角色周围做一次轻量光晕或星星粒子，配合角色庆祝动作，持续约 1.5s，自然消散，不循环。 | 成功结算触发 | 暖金 / 白 | 参考 | 序列帧   |

#### 4.4 结算反馈特效

##### 写什么

成功/失败结算页面的视觉反馈特效。

##### 怎么写

写清楚特效在 UI 层还是场景层，时长，是否遮挡结算信息。

##### 例

| 编号  | 分类 | 模块     | 特效名称   | 需求描述                                                     | 触发时机     | 颜色/变体 | 参考 | 输出要求 |
| ----- | ---- | -------- | ---------- | ------------------------------------------------------------ | ------------ | --------- | ---- | -------- |
| FX-07 | 特效 | 结算反馈 | 成功爆发   | 成功结算页面出现时，做一次从页面中心向外扩散的爆发粒子，持续约 1s，然后自然消散，不遮挡奖励信息和按钮区。 | 成功结算页触发 | 暖金 / 白光 | 参考 | 序列帧   |
| FX-08 | 特效 | 结算反馈 | 失败消散   | 失败结算页面出现时，做一个轻微的灰暗消散效果，衬托失败氛围，强度要弱，不要太压抑影响继续体验的欲望。 | 失败结算页触发 | 灰/黑      | 参考 | 序列帧   |

#### 4.5 场景氛围特效

##### 写什么

场景内常驻的氛围增强特效。

##### 怎么写

写清楚氛围特效是前景还是后景，是否影响可玩区识别。

##### 例

| 编号  | 分类 | 模块     | 特效名称   | 需求描述                                                     | 触发时机 | 颜色/变体 | 参考 | 输出要求    |
| ----- | ---- | -------- | ---------- | ------------------------------------------------------------ | -------- | --------- | ---- | ----------- |
| FX-09 | 特效 | 场景氛围 | 场景尘埃粒子 | 关卡场景内做轻微飘浮尘埃粒子，常驻循环，放在场景后景层，密度低，不影响前景角色和危险对象识别，用于增强场景氛围感。 | 常驻     | 米白透明  | 参考 | 粒子系统    |

### 5. 资源命名与交付规范

#### 5.1 命名格式

适用：Unity | 核心：全小写 + 下划线 + 无中文无空格

**通用规则**

| 规则           | 示例                      |
| -------------- | ------------------------- |
| 全小写         | fx_line_hit ✅             |
| 下划线分隔     | fx_fire_loop ✅            |
| 无空格、无中文 | 火海特效 ❌                |
| 数字不开头     | 1_fx ❌ / fx_01 ✅          |

### 6. 验收标准

适用：主美验收 + 程序联合验收 | 目的：减少返工，明确"合格"底线

#### 6.1 特效验收（序列帧/粒子系统）

| 检查项     | 标准                                        | 严重程度 |
| ---------- | ------------------------------------------- | -------- |
| 序列帧连续 | 编号连续无缺号，补零3位                     | 🔴 致命   |
| 透明边缘   | 粒子贴图无脏边                              | 🟡 主要   |
| 尺寸规范   | 特效贴图2的幂                               | 🟡 主要   |
| 表现力     | 特效符合设计预期（触发感/视觉反馈）         | 🟡 主要   |
| 性能       | 粒子数量 ≤ 规范上限（如单特效≤30粒子）      | 🟡 主要   |
| 层级正确   | 特效渲染层级正确（不被角色遮挡/错误遮挡）   | 🟡 主要   |
| 不遮挡判定 | 玩法反馈特效不影响玩家判断路线和危险区域    | 🔴 致命   |
| 循环特效   | 循环播放首尾无跳帧                          | 🔴 致命   |
| 颜色空间   | 特效颜色与游戏内颜色空间一致（无过曝/过暗） | 🟢 次要   |
| 叠加效果   | 多个特效叠加无渲染冲突                      | 🟢 次要   |

#### 6.2 验收通过标准

- 🔴 致命项 = 0
- 🟡 主要项 ≤ 3
- 🟢 次要项 可后续优化

### 8. 自检

> AI自检

#### 生成后强制自检（Fail Gate）

以下任一项不满足，则该特效-ADD 判定为"不合格，不可直接发制作"。

**通用项（所有ADD类型均适用）**

1. 复用入口被直接省略，未判断当前系统的展示要求
2. 新版本新增内容未同步进 ADD
3. 有参考图，但需求描述仍不足以让美术独立开制作

**特效专属项**

4. 特效需求描述仅写抽象词（"高级""炸""酷"），未写具体视觉表现
5. 特效挂点 / 作用对象未写清楚
6. 特效触发时机未写明
7. 循环类特效未注明循环方式和时长
8. 未注明特效是否会遮挡 UI 或判定区域
9. 未注明特效颜色或变体

#### 自检问题单（生成后逐项回答）

- 是否已从 GDD / MDD 中提取了所有特效触发点？
- 是否已先做 ADD 覆盖总表？
- 是否已确认每个特效的挂点 / 作用对象？
- 是否已写明每个特效的触发时机？
- 是否已写清视觉表现（而不只是"高级炫酷"等抽象描述）？
- 是否已写明时长或循环方式？
- 是否已标注是否遮挡 UI 或判定？
- 是否已写明颜色或变体？
- 是否存在"复用，所以没写"的条目？
- 是否存在"触发点已知，但特效资源未建条目"的情况？
